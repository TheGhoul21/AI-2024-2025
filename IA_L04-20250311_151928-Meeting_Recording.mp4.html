Introduction

This lecture, the fourth in our Artificial Intelligence course, builds upon the foundational concepts introduced in previous sessions. We now transition from the broader definitions and historical context of AI, as outlined in Chapter 1 of Russell and Norvig’s seminal work, to a more focused examination of agents, the central entities in AI. This lecture primarily delves into Chapter 2, aiming to dissect the notion of an agent, particularly what constitutes an intelligent and rational agent. We will explore Artificial Intelligence as the discipline dedicated to the science and engineering of designing, constructing, and understanding these intelligent agents.

A critical aspect of understanding agents lies in recognizing their operational context. Therefore, we will introduce the concept of a task environment, which defines the specific setting in which an agent operates. We will thoroughly analyze the properties that characterize and differentiate various task environments. These properties include:

  • Observability

  • Number of Agents

  • Determinism

  • Episode Type

  • Environment Dynamics

  • State Space

  • Knowledge of the Environment

By examining these properties, we can better understand the challenges and constraints imposed on agents operating in different scenarios. Finally, the lecture will conclude with a categorization of different types of agents based on their internal architecture and decision-making processes. We will also provide an initial introduction to the concept of search problems within the realm of Artificial Intelligence, setting the stage for future discussions on problem-solving methodologies in AI.

Task Environments

A task environment encapsulates the external conditions and settings in which an agent operates. Understanding the properties of task environments is paramount because these characteristics dictate the design and capabilities required for an agent to perform effectively. The nature of the task environment directly influences the agent’s perception, decision-making process, and action execution.

Properties of Task Environments

Task environments can be systematically classified based on a set of distinct properties. These properties are not mutually exclusive and can be combined to describe a wide range of environments. Analyzing these properties is crucial for understanding the inherent challenges and complexities in designing agents tailored for specific operational domains.

Observability

Observability refers to the degree to which an agent can perceive the current state of its environment through its sensors. This property ranges from complete access to the environment’s state to limited or indirect access.

Completely Observable Environments

A task environment is completely observable if the agent’s sensors provide it with access to the entire state of the environment at any given time. In such environments, the agent has all the necessary information to make optimal decisions based on the current state alone.

  • Example:

    Solving a crossword puzzle. All the clues and the current state of the grid are visible to the solver at all times. There is no hidden information relevant to solving the puzzle.

Partially Observable Environments

In contrast, a partially observable environment is one where the agent’s sensors only provide access to a subset of the environment’s state. Some crucial information might be hidden, inaccessible, or noisy, requiring the agent to infer or estimate the complete state.

  • Example:

    A medical diagnosis system. A doctor or an AI system might not have immediate access to all the physiological parameters or the complete medical history of a patient. Diagnostic decisions must be made based on available symptoms, test results, and patient history, which represent only a partial view of the patient’s actual health state.

The distinction between complete and partial observability significantly impacts the complexity of agent design. Agents in partially observable environments often need to maintain internal states, use memory, and employ belief states to reason about the unobserved parts of the environment.

Number of Agents

The number of agents property classifies environments based on how many agents are operating and interacting within them. This distinction is crucial as it determines whether an agent needs to consider the actions and presence of other entities.

Single Agent Environments

A single agent environment involves only one agent that is acting and operating within the environment. The agent is isolated in terms of decision-making entities, although the environment itself might be complex.

  • Example:

    An agent designed to solve a crossword puzzle. The agent works in isolation, without any other entity simultaneously trying to alter the puzzle or compete for resources.

Multiagent Environments

A multiagent environment involves more than one agent simultaneously operating and interacting within the environment. These agents can be cooperative, competitive, or a combination of both. The presence of multiple agents introduces complexities such as coordination, communication, competition for resources, and strategic interactions.

  • Example:

    A medical diagnosis system can be viewed as a multiagent environment. Consider the patient, the diagnosing physician, and perhaps other specialists or automated diagnostic tools as distinct agents. Each agent interacts and influences the environment (patient’s health state) and each other to achieve their respective goals (patient’s well-being, accurate diagnosis).

In multiagent environments, agents must be designed to reason about the behavior of other agents, which can be unpredictable and can significantly affect the environment’s state and the agent’s own performance.

Determinism

Determinism describes the relationship between an agent’s actions and the resulting state of the environment. It specifies whether the outcome of an action is predictable and unique or if there is inherent uncertainty.

Deterministic Environments

In a deterministic environment, for any given state and agent action, there is only one possible resulting state. The outcome of actions is predictable and certain.

  • Example:

    Solving a crossword puzzle. When an agent writes a specific word in a set of cells, the outcome is always the same: that word is placed in those cells. There is no element of chance or variability in the outcome of this action.

Non-deterministic Environments

A non-deterministic environment, also known as a stochastic environment, is characterized by uncertainty in the outcomes of actions. For a given state and action, there might be multiple possible resulting states, and the actual outcome is not fully predictable.

  • Example:

    Medical diagnosis and treatment. Medical treatments are often non-deterministic. For instance, administering a vaccine might have a high probability of preventing a disease, but it is not guaranteed to work in every case due to individual patient variability and other factors. There’s a probabilistic element to the outcome of medical interventions.

Dealing with non-determinism requires agents to reason under uncertainty, consider probabilities of different outcomes, and potentially employ strategies that are robust to variability.

Episode Type

The episode type property distinguishes between environments based on the structure of the agent’s experience. It defines whether the agent’s interaction with the environment is divided into independent episodes or unfolds as a continuous sequence of interactions.

Episodic Environments

In an episodic environment, the agent’s experience is divided into a series of independent episodes. In each episode, the agent perceives the environment and then performs a single action. The crucial characteristic is that each episode is self-contained; the agent’s action in one episode does not affect the environment or subsequent episodes.

  • Example:

    A classification task, such as identifying types of objects from images. Each image presented to the agent is an independent episode. The agent classifies the image, and this action does not influence the next image it will be presented with. Each classification is a separate, self-contained task.

Sequential Environments

In a sequential environment, the agent engages in a sequence of actions where the current decision can affect not only the immediate outcome but also future states and subsequent decisions. Actions have long-term consequences, and the agent needs to consider the future implications of its current choices.

  • Example:

    Medical treatment planning. Medical treatments are inherently sequential. The initial diagnosis and treatment plan set the stage for future health states and subsequent treatment decisions. For example, an initial treatment might affect the patient’s response to later treatments, making the process sequential and requiring long-term planning.

  • Example:

    Solving a crossword puzzle. Crossword puzzles are also sequential because filling in one word can constrain the possibilities for intersecting words. Decisions made early in solving the puzzle affect the options and constraints available later on.

Sequential environments demand agents that can plan ahead, consider the long-term consequences of their actions, and adapt their strategies over time based on the unfolding sequence of interactions.

Environment Dynamics

Environment dynamics describes whether the environment itself changes over time, particularly in relation to the agent’s thinking and acting processes. This property determines if the agent is operating in a static or changing world.

Static Environments

A static environment is one that remains unchanged while the agent is deliberating and deciding on an action. The only changes in the environment are those directly caused by the agent’s actions. If the agent pauses to think, the world does not evolve on its own.

  • Example:

    Solving a crossword puzzle. The crossword puzzle grid and clues do not change while the solver is thinking about possible answers. The puzzle remains constant until the solver makes a change by filling in a word.

Dynamic Environments

In a dynamic environment, the environment can change independently of the agent’s actions and while the agent is in the process of deciding what to do. This means the environment can evolve over time, presenting new situations and challenges even if the agent takes no action. Agents in dynamic environments must be reactive and capable of making timely decisions in response to these changes.

  • Example:

    Medical diagnosis of a patient in critical condition. A patient’s health status can change rapidly and unpredictably, even as a doctor is assessing the situation and planning interventions. For instance, a patient experiencing severe bleeding might deteriorate quickly, requiring immediate and adaptive responses from the medical team.

Dynamic environments often require agents to operate in real-time or near real-time, continuously monitoring the environment and reacting promptly to changes.

State Space

The state space property refers to the nature of the possible states within the environment. It considers whether the states are discrete or continuous and whether the total number of states is finite or infinite.

Discrete Environments

A discrete environment is characterized by a countable number of distinct states, actions, and percepts. The values are typically drawn from a finite or countably infinite set, often represented as integers or symbols.

  • Example:

    Solving a crossword puzzle. The possible states can be described by the arrangement of letters in the grid, which is discrete. The actions (filling in letters) and percepts (viewing the grid) are also discrete.

Continuous Environments

In a continuous environment, the states, actions, and percepts can take on values from a continuous range, typically represented by real numbers. These environments involve variables that can change smoothly and take on any value within a given range.

  • Example:

    Monitoring a patient’s temperature in a medical diagnosis system. Body temperature is a continuous variable that can take any value within a physiological range. Similarly, other vital signs like blood pressure and heart rate are also continuous.

Continuous environments often require different mathematical and computational tools compared to discrete environments, such as calculus and numerical methods, to model and control agent behavior.

Knowledge of Environment

Knowledge of the environment pertains to what the agent or the agent’s designer knows about the rules and physics governing the environment’s behavior. This property is about the level of prior information available.

Known Environments

In a known environment, the agent (or more accurately, the designer) has complete knowledge of the environment’s rules, including how the environment operates and the precise effects of each action. The agent can rely on this pre-existing knowledge to plan and act effectively.

Unknown Environments

In an unknown environment, the agent (and potentially the designer initially) does not possess prior knowledge of the environment’s rules. The agent must learn how the environment works through exploration and interaction. This often involves trial and error, observation, and learning from experience to build a model of the environment.

  • Example:

    AlphaGo Zero learning to play Go. AlphaGo Zero was designed to learn the game of Go from scratch, without being explicitly programmed with the rules or strategies of Go. It learned by playing against itself, exploring the game’s state space, and discovering effective strategies through self-play and reinforcement learning in an initially unknown environment.

Agents in unknown environments require learning mechanisms and exploration strategies to acquire knowledge and improve their performance over time.

Knowledge of Performance Measure

Knowledge of the performance measure refers to whether the agent and its designer are aware of the criteria that define successful performance in the task environment. This is about understanding what constitutes success or optimality.

Known Performance Measure

In scenarios with a known performance measure, both the agent and the designer have a clear and well-defined metric to evaluate the agent’s success. This measure is typically quantifiable and directly reflects the objectives of the task.

Unknown Performance Measure

In situations with an unknown performance measure, the criteria for success are not initially well-defined or fully understood by the agent or even the designer. The agent might need to interact with an external entity, such as a human user, to understand and refine what constitutes good performance. This is common in complex or subjective tasks where success is hard to quantify directly.

For instance, in creative tasks or in scenarios where user satisfaction is paramount, the performance measure might be implicitly defined and only become clear through interaction and feedback.

Classifying and Characterizing Task Environments

The seven properties discussed—observability, number of agents, determinism, episode type, dynamics, state space, and knowledge of the environment and performance measure—collectively provide a comprehensive framework for classifying and characterizing task environments. By analyzing a task environment along these dimensions, we can gain a deeper understanding of its nature and the challenges it poses for agent design. It is important to note, as highlighted in the lecture, that while these properties offer a structured approach, the categorization can sometimes be subjective and context-dependent. The precise classification might depend on the perspective of the observer or the specific level of abstraction considered.

Difficulty based on Task Environment Properties

The difficulty of designing an effective agent for a given task environment is significantly influenced by these properties. Task environments become progressively more challenging as they exhibit the following characteristics:

  • Partial Observability: Agents must manage uncertainty and maintain internal representations of the unobserved parts of the environment, increasing complexity in state estimation and decision-making.

  • Multiagent Nature: The presence of other agents introduces unpredictability and strategic interactions, requiring agents to model and anticipate the behavior of others, which can be computationally intensive and complex.

  • Non-determinism (Stochasticity): Agents must cope with uncertain outcomes of their actions, necessitating probabilistic reasoning, risk assessment, and planning for contingencies, making decision-making more intricate.

  • Sequential Episodes: The need to consider long-term consequences and plan sequences of actions over extended periods adds a layer of complexity, requiring agents to perform planning and optimization over time horizons.

  • Dynamic Nature: Environments that change autonomously demand timely reactions and continuous monitoring. Agents must be reactive and adaptive, capable of processing information and making decisions quickly in response to environmental changes.

  • Continuous State and Action Spaces: Dealing with continuous variables requires more sophisticated mathematical tools and computational techniques compared to discrete environments. Optimization and control in continuous spaces are generally more complex.

  • Unknown Environment: Agents must learn the environment’s dynamics and rules through exploration, adding a learning component to the agent design. Exploration strategies and learning algorithms become crucial for effective operation.

Environments that combine several of these challenging properties represent the most complex scenarios for AI agent design, demanding sophisticated architectures and algorithms to achieve robust and intelligent behavior.

Task Environment Examples

To solidify the understanding of these properties, let’s revisit the examples of the crossword puzzle and medical diagnosis system and analyze them in detail using our framework.

Crossword Puzzle Environment: Detailed Analysis

  • Observability: Completely Observable. All clues and the current state of the grid are always visible.

  • Agents: Single Agent. Typically, a crossword puzzle is solved by an individual in isolation.

  • Determinism: Deterministic. Filling in a word has a predictable outcome.

  • Episode Type: Sequential. Entries must interlock, making decisions interdependent. Solving a crossword is not a series of independent steps but a connected process.

  • Environment Dynamics: Static. The puzzle itself does not change while being solved.

  • State Space: Discrete. The puzzle grid, letters, and word choices are all discrete.

  • Knowledge of Environment: Depends on the solver. For someone familiar with crossword conventions and vocabulary, the environment is largely known. For a novice, it might be partially unknown, requiring learning of puzzle-solving strategies.

Medical Diagnosis System Environment: Detailed Analysis

  • Observability: Partially Observable. A medical system does not have complete and immediate access to all patient information. Some conditions might be hidden, symptoms might be misleading, and test results take time to process.

  • Agents: Multiagent (Potentially). While the primary diagnostic agent might be considered single, the environment inherently involves multiple agents. The patient’s body is a complex system, and considering other medical personnel or even other AI diagnostic tools makes it multiagent.

  • Determinism: Non-deterministic (Stochastic). Medical treatments and diagnoses are not always certain. The same treatment can have different outcomes for different patients, and diagnoses are based on probabilities and likelihoods, not absolute certainty.

  • Episode Type: Sequential. Medical diagnosis and treatment are inherently sequential. Initial diagnoses and treatments influence subsequent health states and future interventions. Patient care is a continuous and evolving process.

  • Environment Dynamics: Dynamic. A patient’s health condition can change rapidly and unpredictably, especially in critical situations. The environment (patient’s body) is not static and evolves independently of the diagnostic agent’s immediate actions.

  • State Space: Continuous (Likely). Many relevant variables in medical diagnosis, such as temperature, blood pressure, and blood glucose levels, are continuous.

  • Knowledge of Environment: Partially Known. Medical science is constantly evolving, and our understanding of the human body and diseases is incomplete. Diagnostic systems operate with partial and evolving knowledge of the environment.

Impact of Task Environment Characteristics on Agent Design

The characteristics of the task environment have profound implications for how we design intelligent agents. Understanding these impacts is crucial for developing agents that are well-suited to their operational domains. The following points elaborate on how each property influences agent design:

  • Partial Observability: In partially observable environments, agents cannot rely solely on immediate perceptions. They must incorporate memory to store past perceptions and build an internal state or belief state. This internal model allows them to reason about aspects of the environment that are not currently visible. Techniques like state estimation, filtering, and probabilistic reasoning become essential.

  • Stochastic Environments: When environments are stochastic, agents must be designed to handle uncertainty. They need to consider multiple possible outcomes for their actions and evaluate actions based on expected outcomes rather than certain results. Probabilistic planning, decision theory, and risk management are crucial components for agents in such environments.

  • Multiagent Environments: In multiagent settings, agents must account for the presence and actions of other agents. This may require modeling other agents, understanding game theory, and employing strategies that consider potential cooperation, competition, or negotiation. In some cases, introducing an element of randomness in behavior can be beneficial to avoid predictable patterns that could be exploited by other agents.

  • Static Environments: Static environments offer the advantage of time for deliberation. Agents can afford to spend more computational resources on planning and decision-making because the environment will not change while they are thinking. Complex planning algorithms and extensive search strategies become feasible.

  • Dynamic Environments: Dynamic environments demand reactive agents capable of timely responses. Agents must be efficient in their processing and decision-making to keep pace with the environment’s changes. Real-time processing, reactive architectures, and potentially simpler decision-making mechanisms are favored.

  • Continuous Environments: Handling continuous variables requires agents to use mathematical tools suitable for continuous spaces. This often involves calculus, differential equations, and numerical methods. Agent designs may need to incorporate continuous control, function approximation, and optimization techniques adapted for continuous domains.

  • Unknown Environments: Agents operating in unknown environments must be equipped with learning mechanisms. They need to explore the environment, gather data, and learn models of the environment’s dynamics and rules. Reinforcement learning, exploration-exploitation strategies, and model learning become central to agent capabilities.

  • Unknown Performance Measure: When the performance measure is not explicitly given, agents need mechanisms to interact with an external evaluator, often a human. This interaction is crucial for understanding and refining the goals. Techniques like interactive learning, preference learning, and methods for eliciting feedback from users become relevant for aligning agent behavior with desired outcomes.

In summary, the task environment is not merely a backdrop for agent operation but a fundamental determinant of agent design. A thorough analysis of the task environment’s properties is the first critical step in engineering intelligent agents that can effectively achieve their goals in diverse and complex settings.

Types of Agents

Agents can be categorized based on their internal architecture and decision-making processes. This lecture outlines five fundamental types of agents, each representing an incremental increase in complexity and capability. These categories provide a structured way to understand the design space of intelligent agents.

Simple Reflex Agents

Structure and Operational Mechanism

Simple reflex agents are the most basic type of agent. They operate on a direct mapping from the current percept to an action. These agents react instantaneously to the environment based on predefined rules, disregarding any history of perceptions or future consequences. Their decision-making process is purely reactive and memoryless.

Implementation with Condition-Action Rules

Simple reflex agents are typically implemented using a set of condition-action rules, often expressed as "if-then" rules. These rules dictate the action to be taken when a specific condition in the environment is perceived.

  • Example Rules:

    • If current location is dirty, then perform suck action. (Vacuum Cleaner Agent)

    • If car ahead is braking (as perceived by sensors), then engage brake action. (Autonomous Driving Agent)

The program for a simple reflex agent involves:

  1. Perceiving the current state of the environment through sensors.

  2. Matching the current percept against the conditions defined in the rule set.

  3. Selecting and executing the action associated with the first rule that matches the current percept. If no rule matches, no action is taken.

This process is repeated in each time step, making the agent continuously reactive to its immediate surroundings.

Limitations of Simple Reflex Agents

Despite their simplicity and reactivity, simple reflex agents suffer from several limitations.

  • Limited Rationality in Partially Observable Environments: Simple reflex agents are truly effective only in completely observable environments. In partially observable environments, their decisions are based solely on the limited information available in thecurrent percept, which may not be sufficient for optimal action. They cannot infer aspects of the world they cannot currently perceive.

  • Lack of Memory and History Consideration: These agents ignore the history of perceptions. They do not have any internal state or memory to store past information. Consequently, they cannot learn from past experiences, adapt to changes over time, or plan based on previous events.

  • Inability to Handle Complex Goals: Simple reflex agents are best suited for simple tasks where the optimal action can be determined directly from the current percept. They are not capable of handling complex goals that require planning, problem-solving, or consideration of future outcomes.

These limitations restrict the applicability of simple reflex agents to relatively simple environments and tasks. For more complex scenarios, more sophisticated agent architectures are necessary.

Model-Based Reflex Agents

Incorporating a World Model

Model-based reflex agents represent an enhancement over simple reflex agents by incorporating a model of the world. This model allows the agent to reason about the environment’s state, even the aspects that are not directly perceived in the current percept. By maintaining an internal representation of how the world works, these agents can make more informed decisions in partially observable environments.

Internal State and Memory Usage

Unlike simple reflex agents, model-based agents maintain an internal state. This state is a representation of the current world state, derived from the history of perceptions. The internal state acts as a form of memory, allowing the agent to keep track of aspects of the environment that are not immediately visible. This enables the agent to make decisions based not only on the current percept but also on its understanding of the unobserved parts of the world.

Transition Model and Sensor Model Components

To maintain and utilize the world model, model-based agents rely on two key components:

  • Transition Model:

    This model describes how the world evolves. It encapsulates two types of knowledge:

    1. Autonomous Evolution: How the environment changes independently of the agent’s actions over time.

    2. Action Effects: How the agent’s actions affect the environment and cause transitions from one state to another.

    The transition model allows the agent to predict the next state of the world given its current state and the action it takes. This can be deterministic or stochastic, depending on the environment’s nature.

  • Sensor Model:

    This model describes how the agent’s sensors perceive the environment. It specifies the relationship between the actual state of the world and the perceptual input received by the agent. The sensor model helps the agent interpret noisy or incomplete sensory information and update its internal state accordingly. It accounts for the limitations and characteristics of the agent’s sensors.

Advantages Over Simple Reflex Agents

Model-based reflex agents offer significant advantages over simple reflex agents, particularly in more realistic and complex environments.

  • Handling Partially Observable Environments: By maintaining an internal state and using a world model, these agents can operate effectively in partially observable environments. They can infer the hidden aspects of the world and make decisions based on a more complete, albeit inferred, understanding of the situation.

  • Informed Decision Making: Model-based agents make more informed decisions because they consider not only the current percept but also the history of perceptions and the predicted outcomes of their actions. This allows for more strategic and context-aware behavior compared to the purely reactive nature of simple reflex agents.

However, the effectiveness of model-based agents heavily depends on the accuracy and completeness of their world model. Constructing and maintaining an accurate model can be challenging, especially in complex and dynamic environments.

Goal-Based Agents

Defining Agent Goals and Objectives

Goal-based agents represent a further step towards more sophisticated agent architectures. Building upon model-based agents, they incorporate goals into their decision-making process. Instead of merely reacting to the current state or predicting future states, goal-based agents actively seek to achieve specific objectives. Goals are desired states of the environment that the agent aims to reach.

Planning for Goal Achievement

Goal-based agents engage in planning to achieve their goals. This involves:

  1. Reasoning about future states: The agent uses its world model to predict the states that would result from different sequences of actions.

  2. Choosing actions that lead to goal states: The agent selects actions that it believes will eventually lead to a state that satisfies its goal.

To achieve this, goal-based agents often employ search and planning algorithms. These algorithms explore possible sequences of actions, evaluate their potential outcomes, and identify a path that leads to a goal state. The agent needs to answer questions such as:

  • What will be the state of the world if I perform action A in the current state?

  • Will performing action A, or a sequence of actions starting with A, bring me closer to achieving my goal?

The focus shifts from immediate reaction to purposeful action aimed at achieving a predefined objective.

Limitations in Handling Conflicting Objectives

While goal-based agents are more sophisticated than reflex agents, they have limitations, particularly when dealing with multiple or conflicting goals.

  • Binary Goal Satisfaction: Goal-based agents typically treat goals in a binary fashion: a state either satisfies the goal or it does not. This binary view is often insufficient to express preferences among different goal states or to handle situations where achieving one goal might hinder the achievement of another.

  • Lack of Prioritization and Trade-offs: When faced with multiple goals, goal-based agents lack a mechanism to prioritize or make trade-offs between them, especially if the goals are mutually exclusive or have varying levels of importance. All goals are treated as equally important objectives to be achieved, which can lead to suboptimal behavior in complex scenarios where some goals are more critical or easier to achieve than others.

These limitations highlight the need for a more nuanced approach to decision-making, especially in environments with complex objectives and constraints.

Utility-Based Agents

Introducing the Utility Concept

Utility-based agents overcome the limitations of goal-based agents by introducing the concept of utility. Utility provides a more flexible and comprehensive framework for decision-making by quantifying the desirability of different states. Utility is a measure of "happiness" or "satisfaction" that an agent derives from being in a particular state. It allows the agent to express preferences not just between achieving a goal and not achieving it, but also among different states of the world, including goal states.

Utility as a Performance Measure

Utility acts as a refined performance measure that goes beyond simple goal satisfaction. Instead of a binary outcome (goal achieved or not), utility assigns a numerical value to each state. This value represents how preferable or desirable that state is to the agent. Higher utility values correspond to more desirable states, and lower values to less desirable or undesirable states.

Managing Uncertainty and Preferences with Utility

Utility-based agents are particularly well-suited for handling uncertainty and expressing preferences:

  • Handling Probabilistic Outcomes: In stochastic environments, actions may lead to different outcomes with varying probabilities. Utility-based agents can evaluate actions by considering the expected utility of their outcomes. Expected utility is calculated by averaging the utilities of possible resulting states, weighted by their probabilities. This allows agents to make rational decisions even when outcomes are uncertain.

  • Resolving Conflicting Goals and Trade-offs: Utility provides a mechanism to handle conflicting goals and make trade-offs. When faced with multiple goals that cannot all be fully achieved, or when achieving one goal compromises another, utility-based agents can choose actions that maximize their overall utility. They can prioritize goals and make rational compromises based on the relative utilities of different outcomes.

  • Expressing Preferences Among Goal States: Utility allows agents to express preferences between different goal states. Not all goal states are equally desirable. Some might be more beneficial or rewarding than others. Utility enables agents to differentiate between goal states and aim for those that provide higher utility.

Advantages of Utility-Based Agent Architecture

Utility-based agents are considered more rational and flexible than goal-based agents, especially in complex and uncertain environments, because they can:

  • Make Decisions in Uncertain Environments: They can make rational choices even when the outcomes of actions are probabilistic, by maximizing expected utility.

  • Balance Multiple Objectives and Preferences: They can handle situations with multiple, potentially conflicting objectives and express preferences among different outcomes using the utility function.

  • Maximize Overall Well-being or Performance: They aim to choose actions that maximize their overall "well-being" or performance, as quantified by the utility function. This leads to more nuanced and adaptable behavior in complex scenarios.

The design of utility functions is a critical aspect of developing utility-based agents. The utility function must accurately reflect the agent’s preferences and the objectives it is designed to achieve.

Learning Agents (Brief Overview)

Learning agents represent a significant advancement in agent design, enabling agents to improve their performance over time by learning from experience. Learning agents can adapt to new environments, refine their strategies, and become more effective problem solvers through learning.

This section provides a brief overview, as learning agents are a central topic in AI and will be covered in greater detail later in the course.

Performance Element in Learning Agents

The performanceElement is the core component of a learning agent responsible for selecting actions. It embodies the agent’s current strategy or policy for acting in the environment. Importantly, the performance element can be any of the agent types discussed previously: simple reflex, model-based reflex, goal-based, or utility-based. It is the part of the agent that directly interacts with the environment and executes actions.

Learning Element and its Role

The learning element is the component that enables the agent to improve. It is responsible for taking feedback from the critic and using this feedback to modify and enhance the performance element. The learning element’s goal is to make the performance element act more effectively in the future.

The specific modifications made by the learning element depend on the type of performance element and the learning mechanism employed. It can adjust:

  • Rules in a simple reflex agent.

  • Models in a model-based agent (transition and sensor models).

  • Goals in a goal-based agent (although goal modification is less common in basic learning agents).

  • Utility functions in a utility-based agent.

Function of the Critic and Problem Generator

Learning agents typically include two additional components that guide the learning process:

  • Critic:

    The critic evaluates the agent’s performance in the environment. It observes the agent’s behavior and provides feedback to the learning element. This feedback is based on a predefined performance standard or measure. The critic essentially answers the question: "How well is the agent doing?" It informs the learning element about the agent’s successes and failures, indicating areas for improvement. The feedback can be in various forms, such as rewards, penalties, or evaluations of state desirability.

  • Problem Generator:

    The problem generator is responsible for suggesting exploratory actions. Its role is to push the agent to explore new parts of the environment and try out different actions, even those that might not seem optimal based on current knowledge. The problem generator aims to ensure that the agent does not become stuck in suboptimal strategies and instead seeks out new experiences that can lead to learning and improvement. For example, in a game-playing agent, the problem generator might suggest trying a move that is not immediately obvious but could potentially uncover a new winning strategy. It addresses the need for exploration in learning, balancing it with exploitation of current knowledge by the performance element.

In summary, a learning agent operates by having the performance element act in the environment, the critic evaluate its performance, the learning element use this feedback to improve the performance element, and the problem generator suggest explorations. This cycle of action, evaluation, learning, and exploration enables the agent to adapt and enhance its capabilities over time, becoming more intelligent and effective in its task environment.

Representing the World

Agents operate within environments and must possess some form of internal representation or world model to reason and act effectively. The level of detail and abstraction in these world models can vary significantly, impacting the agent’s capabilities and complexity. We can categorize these representations into three primary levels of abstraction: atomic, factored, and structured. These levels form a spectrum, ranging from simple and undifferentiated to complex and richly detailed.

Levels of Abstraction for World Models

The choice of world representation is a critical design decision, influencing the agent’s ability to perceive, reason, and act within its environment. The level of abstraction should be appropriate for the complexity of the task and the environment itself.

Atomic World Representation

In an atomic world representation, each state of the world is treated as a single, indivisible entity. States are considered atomic because they lack internal structure and are represented as unique, opaque symbols or identifiers.

When using an atomic representation:

  • States are Black Boxes: Each state is a fundamental unit, and there is no decomposition into smaller parts or attributes.

  • Indivisible and Unique: States are distinct from one another, and the only operation typically supported is comparing states for equality or inequality. We can determine if two states are the same or different, but we cannot access or reason about their internal components.

  • Simplicity: This is the simplest form of world representation, suitable for environments where the distinctions between states are paramount, and internal details are not relevant for decision-making.

Example:

Consider a self-driving taxi navigating between cities. Using an atomic representation, we might represent the taxi’s location simply as the name of the city it is currently in.

  • States: Arad, Bucharest, Craiova, Dobreta, Eforie, Fagaras, Giurgiu, Hirsova, Iasi, Lugoj, Mehadia, Neamt, Oradea, Pitesti, Rimnicu Vilcea, Sibiu, Timisoara, Urziceni, Vaslui, Zerind.

In this representation, each city name is an atomic state. The agent can distinguish between being in Padova versus Venice, but the representation does not capture any information about locations within each city or relationships between cities. This level of abstraction is useful when the task primarily involves navigating between distinct locations, and the details within each location are not important for the agent’s decisions.

Factored World Representation

A factored world representation offers a more structured approach by describing a state as a collection of variables or attributes. Each variable can take on a specific value from its domain. This decomposition of states into factors allows for a more detailed and flexible representation compared to atomic states.

Key characteristics of factored representations include:

  • Structured States: States are no longer monolithic but are structured as a set of features or properties.

  • Variables and Values: The world is described in terms of variables, each representing a specific aspect of the environment, and each variable is assigned a value that describes the state of that aspect.

  • Relationships between States: Factored representations allow for expressing relationships and similarities between states based on shared variable values.

  • Increased Expressiveness: This representation is more expressive than atomic representations, enabling agents to reason about specific aspects of the environment and how they change.

Example:

Consider again the self-driving taxi. Instead of just the city name, we can use a factored representation to include more relevant information about the taxi’s state:

  • Variables:

    • CurrentCity: Possible values: {Arad, Bucharest, ..., Zerind}

    • FuelLevel: Possible values: Continuous range, e.g., \([0, 100]\) liters, or discrete levels, e.g., {Empty, Low, Medium, Full}

    • PassengerPresent: Possible values: {True, False}

  • State Example: A state could be represented as: \(\{\texttt{CurrentCity}=\texttt{Sibiu}, \texttt{FuelLevel}=35, \texttt{PassengerPresent}=\texttt{False}\}\).

With a factored representation, we can now describe the taxi’s state in terms of its city, fuel level, and whether it has a passenger. This allows for more nuanced decision-making. For instance, the agent can now reason about needing to refuel based on the FuelLevel variable, or prioritize actions based on whether PassengerPresent is true. Factored representations are widely used in AI because they strike a balance between simplicity and expressiveness, suitable for many problem domains.

Structured World Representation

A structured world representation is the most complex and expressive level, going beyond simple variables and values to represent states in terms of objects, their properties, and relationships between these objects. This level of representation is essential for dealing with environments that are inherently relational and object-centric.

Key features of structured representations are:

  • Objects and Relations: The world is seen as composed of distinct objects and the relationships that hold between them.

  • Complex Data Structures: States are described using complex data structures such as lists, trees, graphs, or knowledge bases to capture objects and their interconnections.

  • Rich Semantics: Structured representations can capture rich semantic information about the environment, allowing for more sophisticated reasoning and understanding.

  • Reasoning about Entities: Agents can reason about individual objects, their categories, and how they interact, enabling more flexible and general problem-solving.

Example:

Consider a more detailed model of a traffic scenario for a self-driving car. A structured representation could describe the scene as follows:

  • Objects:

    • Taxi-123: An object representing our taxi.

    • Car-456: Another car object.

    • TrafficLight-Red-Zone-A: A traffic light object.

    • Road-Highway-5: A road segment object.

  • Properties of Objects:

    • Taxi-123.Location: Value: (x, y) coordinates on a map.

    • Taxi-123.Speed: Value: 60 km/h.

    • TrafficLight-Red-Zone-A.Color: Value: Red.

    • Road-Highway-5.Lanes: Value: 3.

  • Relationships between Objects:

    • Taxi-123 is_on Road-Highway-5.

    • Car-456 is_ahead_of Taxi-123.

    • TrafficLight-Red-Zone-A controls Road-Highway-5 at Intersection-X.

This structured representation uses objects (Taxi-123, Car-456, etc.), properties (Location, Speed, Color, etc.), and relations (is_on, is_ahead_of, controls) to describe the traffic scene. This rich representation allows the agent to perform complex reasoning, such as: "If TrafficLight-Red-Zone-A.Color is Red and TrafficLight-Red-Zone-A controls Road-Highway-5 and Taxi-123 is_on Road-Highway-5, then Taxi-123 should stop."

Knowledge Graphs and Semantic Networks are examples of formalisms used to implement structured world representations. They are particularly useful in domains requiring reasoning about complex relationships, such as natural language understanding, scene understanding, and common-sense reasoning. Structured representations offer the highest level of expressiveness and are necessary for agents operating in complex, real-world environments, albeit at the cost of increased computational complexity in processing and reasoning.

Search Problems in AI

Introduction to Search Problem Solving Agents

Search problem-solving agents are a fundamental type of intelligent agent in AI. These agents are designed to achieve their goals by searching through a space of possible action sequences to find a path that leads to a desired goal state. The process of searching involves exploring different sequences of actions, evaluating their outcomes, and selecting a sequence that effectively achieves the agent’s objective.

This section introduces the core concepts of search problems in AI, using illustrative examples to clarify these ideas.

Illustrative Example: The Pac-Man Problem

The classic game of Pac-Man provides an intuitive and engaging example to illustrate various agent approaches and the critical concept of optimal path planning. By considering simplified versions of Pac-Man, we can effectively demonstrate different agent strategies, ranging from simple reactive behaviors to sophisticated planning algorithms.

Simple Reflex Agent Approach for Pac-Man

Implementing "Eat Adjacent Pellet" Rule

A basic intelligent behavior for a Pac-Man agent can be implemented using a simple reflex rule: "If there is a pellet adjacent to Pac-Man, eat it." This rule drives the agent to consume pellets whenever they are immediately available.

Behavior: The agent continuously checks its immediate surroundings. If a pellet is detected in any adjacent location (North, East, South, West), the agent takes the action to eat that pellet.

Intelligence Level: This strategy exhibits a rudimentary form of intelligence by enabling the agent to interact with and modify its environment to achieve a basic objective (eating pellets).

Efficiency: While this rule ensures that Pac-Man eats pellets when close by, it is not efficient for maximizing the total number of pellets eaten or for achieving high scores in more complex scenarios. The agent may get stuck in local areas or miss pellets that are slightly further away.

Demonstrations of such an agent would show Pac-Man effectively eating pellets in its immediate vicinity but potentially wandering aimlessly or missing opportunities to eat more pellets efficiently.

Implementing "Nearest Pellet" Rule

To improve upon the "eat adjacent pellet" strategy, we can introduce a slightly more sophisticated rule: "Find the nearest pellet and move towards it." This rule enables the agent to seek out pellets that are not just immediately adjacent but also those that are within a short range.

Behavior: The agent scans its environment to locate all available pellets. It then calculates the distance to each pellet and identifies the nearest one. The agent then plans and executes a sequence of moves to reduce the distance to the nearest pellet, effectively moving towards it.

Improved Intelligence: This strategy is more intelligent than the adjacent pellet rule because it allows the agent to actively seek out pellets, not just react to those that are immediately present. It demonstrates a basic form of goal-directed behavior.

Score Improvement: Demonstrations of this agent typically show improved performance, achieving scores like 907 in certain simplified Pac-Man scenarios. This is because the agent is more proactive in pellet collection.

Suboptimality: Despite the improvement, this strategy is still not optimal. The agent makes greedy decisions by always going for the nearest pellet, which may lead to suboptimal paths in the long run. For instance, it might enter a tunnel to eat a nearby pellet and then have to backtrack, wasting moves that could have been used to collect more pellets elsewhere.

Optimal Path Planning Strategy for Pac-Man

To achieve the best possible performance in Pac-Man, the agent needs to employ optimal path planning. This involves calculating the most efficient path to eat all pellets while minimizing the total distance traveled. This problem is analogous to the classic Traveling Salesperson Problem (TSP), adapted for the Pac-Man context.

Behavior: The agent first analyzes the entire game layout to identify the locations of all pellets. It then computes an optimal or near-optimal path that visits all pellet locations in a sequence that minimizes the total number of moves (or total distance). This computation often involves sophisticated search algorithms.

Planning Overhead: Optimal path planning typically requires significant computation upfront. The agent needs to spend time "thinking" and planning before making its first move. This is in contrast to reflex agents that react immediately.

Optimal Score: By following an optimal path, the agent achieves the highest possible score for a given starting configuration. Demonstrations show scores like 914, which is better than the nearest pellet strategy.

Efficiency in the Long Run: Although there is an initial planning cost, the optimal path strategy is ultimately more efficient in terms of moves and score maximization. It avoids wasted movements and ensures that all pellets are collected in the most economical way.

Complexity: Implementing optimal path planning requires more complex algorithms compared to simple reflex rules. Techniques like A* search, dynamic programming, or TSP solvers might be employed.

The Pac-Man example effectively illustrates the spectrum of agent intelligence and problem-solving strategies, from simple reactive rules to complex planning algorithms aimed at optimality. It highlights the trade-off between computational cost and solution quality, and sets the stage for a more formal discussion of search problems in AI.

Formal Definition of Search Problems

To systematically approach problem-solving in AI, we need a formal way to define a search problem. A search problem is characterized by specifying: the environment’s states, the agent’s possible actions, and the criteria for a successful solution. Formally, a search problem can be defined using six key components.

While the formal definition is rooted in set theory for abstraction, it can be intuitively understood using graph concepts, which we will explore later.

Defining the State Space

The state space \(S\) is the fundamental component of a search problem. It is defined as the set of all possible states that the environment can be in. A state represents a configuration of the world. The level of detail in defining a state depends on the problem and the desired abstraction.

  • Example (Pac-Man):

    For a simplified Pac-Man game, a state could be defined by:

    • Pac-Man’s position \((x, y)\) on the grid.

    • The set of locations of remaining pellets.

    Thus, a state \(s \in S\) might be represented as \(s = ((x, y), P)\), where \((x, y)\) is Pac-Man’s coordinates and \(P\) is the set of pellet coordinates.

  • Example (Simplified 3x3 Pac-Man):

    In an even more simplified 3x3 grid Pac-Man, states could be enumerated. For instance, if we only consider Pac-Man’s position and whether pellets are eaten, we can visualize different states.

The state space can be finite or infinite, discrete or continuous, depending on the problem. For many AI problems, especially in simplified environments, the state space is often treated as discrete and finite to enable search algorithms.

Specifying the Initial State

The initial state \(s_{0}\) is the state in which the agent starts. It is a specific state within the state space \(S\). The search process begins from this initial state.

  • Example (Pac-Man):

    The initial state for a Pac-Man game is the configuration at the very beginning of the game, including:

    • Pac-Man’s starting position.

    • The initial locations of all pellets.

    • Positions of ghosts (if relevant to the search problem formulation).

    For instance, in our simplified 3x3 Pac-Man example, State 1 from the figure above could be designated as the initial state.

Identifying the initial state is straightforward as it is given by the problem setup. It serves as the entry point for any search algorithm.

Defining Possible Actions

Actions \(A(s)\) represent the set of possible actions that the agent can execute when it is in state \(s\). The available actions depend on the current state and the environment’s rules.

  • Example (Pac-Man):

    In Pac-Man, the actions are typically:

    • Move North

    • Move East

    • Move South

    • Move West

    So, \(A(s) = \{\texttt{North}, \texttt{East}, \texttt{South}, \texttt{West}\}\) for most states \(s\). However, if Pac-Man is next to a wall in a certain direction, the corresponding move might not be possible or might have no effect, effectively reducing the set of available actions in such states. For example, if in state \(s\), moving North leads into a wall, then effectively, the action North might be invalid or result in staying in the same state.

The set of actions defines the agent’s capabilities to interact with and change the environment.

Defining the Transition Model

The transition model \(T(s, a)\) describes the outcome of performing action \(a\) in state \(s\). It specifies the state that the agent will transition to after executing action \(a\) in state \(s\).

  • Definition: The transition model \(T: S \times A \rightarrow S\) is a function that maps a state \(s\) and an action \(a \in A(s)\) to the resulting state \(s' = T(s, a)\).

  • Deterministic Environments: In deterministic environments, the transition model is a function that returns a single, unique next state. For example, in Pac-Man, if the action Move North in state \(s\) is valid, it will always lead to the same next state \(s'\). Thus, \(T(s, \texttt{North}) = s'\).

  • Non-deterministic Environments: In non-deterministic environments, the transition model might return a set of possible next states or a probability distribution over possible next states. For simplicity, in many introductory search problem formulations, environments are assumed to be deterministic.

  • Example (Pac-Man - Deterministic):

    If in state \(s_1\), Pac-Man is at position (1,1) and there is no wall to the North, then \(T(s_1, \texttt{North}) = s_2\), where \(s_2\) is the state with Pac-Man at position (1,2) and pellet status updated if a pellet was eaten at (1,2).

The transition model is crucial for search algorithms as it allows them to explore the consequences of actions and predict future states.

Defining the Goal Test

The goal test \(G(s)\) is a function that determines whether a given state \(s\) is a goal state. A goal state is a desirable state that the agent is trying to reach.

  • Definition: The goal test \(G: S \rightarrow \{\texttt{true}, \texttt{false}\}\) is a Boolean function that returns true if state \(s\) is a goal state, and false otherwise.

  • Example (Pac-Man):

    For Pac-Man, a goal state is typically defined as a state in which all pellets have been eaten. Thus, \(G(s) = \texttt{true}\) if in state \(s\), there are no pellets remaining on the game board, and \(G(s) = \texttt{false}\) otherwise. In our 3x3 example, State 3 could be a goal state if it represents the configuration where all pellets have been eaten.

  • Multiple Goal States: There can be one or more goal states in a search problem. The goal test function simply identifies these states.

The goal test defines the success condition for the search problem. The agent’s objective is to find a path to any state for which the goal test returns true.

Defining the Cost Function

The cost function \(C(s, a, s')\) assigns a numerical cost to taking action \(a\) in state \(s\) and transitioning to state \(s'\). The cost typically represents a measure of resources consumed, time taken, or penalty incurred.

  • Definition: The cost function \(C: S \times A \times S \rightarrow \mathbb{R}_{\ge 0}\) assigns a non-negative cost to each transition. \(C(s, a, s')\) is the cost of moving from state \(s\) to state \(s'\) by action \(a\), where \(s' = T(s, a)\).

  • Path Cost: The cost of a path (sequence of actions) is the sum of the costs of the individual transitions along the path.

  • Example (Pac-Man):

    For Pac-Man, a common cost function is:

    • Cost of 1 for each move: \(C(s, a, s') = 1\) for any move action (North, East, South, West). This represents a uniform cost per move, encouraging the agent to find solutions with fewer moves.

    • Reward for eating a pellet: When Pac-Man eats a pellet by moving to a new state \(s'\), we can assign a negative cost (reward), e.g., \(C(s, a, s') = -10\) if action \(a\) results in eating a pellet in state \(s'\). This incentivizes the agent to eat pellets.

    • Penalty for other undesirable outcomes (if any).

    The cost function guides the search towards optimal solutions, where optimality is defined in terms of minimizing the total path cost.

Solutions and Optimal Solutions in Search Problems

With these six components defined, we can now define what constitutes a solution and an optimal solution to a search problem.

  • Solution:

    A solution to a search problem is a sequence of actions \([a_1, a_2, ..., a_n]\) that, when executed starting from the initial state \(s_0\), leads to a goal state \(s_g\) such that \(G(s_g) = \texttt{true}\). That is, applying the sequence of actions transforms \(s_0\) into a state \(s_g\) that satisfies the goal test.

  • Optimal Solution:

    An optimal solution is a solution that has the lowest path cost among all possible solutions. The path cost is the sum of the costs of all actions in the sequence: \(\sum_{i=1}^{n} C(s_{i-1}, a_i, s_i)\), where \(s_i = T(s_{i-1}, a_i)\) and \(s_0\) is the initial state, \(s_n = s_g\) is a goal state.

  • Objective: The primary objective in solving a search problem is often to find an optimal solution – a sequence of actions that not only reaches a goal state but does so with the minimum possible cost. In some cases, finding any solution (not necessarily optimal) is sufficient.

The formal definition of search problems provides a structured framework for analyzing and solving a wide range of AI problems. By specifying the state space, initial state, actions, transition model, goal test, and cost function, we can use various search algorithms to find solutions and optimal solutions.

Example Application: Route Finding in Romania

A classic example to illustrate search problems is finding a route between cities, such as finding a path from Arad to Bucharest in Romania. This example is both intuitive and practically relevant, demonstrating how search problem formulation can be applied to real-world scenarios.

Mapping States, Actions, Goal, and Costs

To formulate the Romania route finding problem as a search problem, we need to define its components based on the given map and objective.

  • States: The states in this problem are the cities in Romania. Each city represents a distinct location that the agent (e.g., a traveler or a navigation system) can be in.

    • Example States: Arad, Bucharest, Sibiu, Timisoara, etc. (all cities on the map).

  • Initial State: The initial state is the starting city, which is given as Arad.

  • Actions: The actions available to the agent in each city are to drive to an adjacent city. Adjacency is defined by the roads connecting the cities on the map.

    • Example Actions (from Arad):

      • Go to Sibiu

      • Go to Timisoara

      • Go to Zerind

  • Transition Model: The transition model is deterministic. If the agent takes an action "Go to City X" from "City Y," it will reliably end up in "City X." There is no uncertainty in the outcome of driving between cities in this simplified model.

  • Goal Test: The goal is to reach Bucharest. Therefore, the goal test \(G(s)\) is true if \(s\) is the city Bucharest, and false otherwise.

  • Cost Function: The cost of each action (driving from one city to another) is the distance in kilometers between the cities, as indicated on the map.

    • Example Costs:

      • \(C(\texttt{Arad}, \texttt{Go to Sibiu}, \texttt{Sibiu}) = 140\) km.

      • \(C(\texttt{Arad}, \texttt{Go to Timisoara}, \texttt{Timisoara}) = 118\) km.

      • \(C(\texttt{Sibiu}, \texttt{Go to Bucharest}, \texttt{Bucharest}) = 278\) km

The objective is to find a sequence of actions (driving from city to city) that starts in Arad, ends in Bucharest, and minimizes the total cost, which is the total distance traveled. An optimal solution would be the shortest path from Arad to Bucharest.

  • Optimal Path: The lecture notes suggest that the shortest path would likely be one of the routes that go relatively directly towards Bucharest, avoiding unnecessary detours. For example, a path through Sibiu or Pitesti might be considered.

  • Suboptimal Paths: Less intelligent agents or suboptimal strategies might take longer routes, such as going through more distant cities or getting stuck in cycles, thus increasing the total distance and cost. For instance, a route that goes from Arad to Zerind to Oradea and then loops back would be inefficient and suboptimal for reaching Bucharest.

This route-finding example clearly illustrates how real-world problems can be abstracted and formulated as search problems, enabling the use of search algorithms to find efficient solutions.

Example Application: Vacuum Cleaner World

The vacuum cleaner world is a simple but illustrative environment often used in AI to demonstrate agent concepts and search problems. Consider a simplified version with two locations, A and B, where the vacuum cleaner can be, and each location can be either dirty or clean.

Defining States, Actions, and Goal

To formulate the vacuum cleaner problem as a search problem, we need to define its states, actions, goal, and costs.

  • States: In this 2-location vacuum world, a state is defined by:

    • The location of the vacuum cleaner: Location A or Location

    • The dirt status of Location A: Dirty or Clean.

    • The dirt status of Location B: Dirty or Clean.

    Combining these, we get \(2 \times 2 \times 2 = 8\) possible states. We can enumerate them as:

    • State 1: (Location A, A=Dirty, B=Dirty)

    • State 2: (Location A, A=Clean, B=Dirty)

    • State 3: (Location A, A=Dirty, B=Clean)

    • State 4: (Location A, A=Clean, B=Clean) - Goal State

    • State 5: (Location B, A=Dirty, B=Dirty)

    • State 6: (Location B, A=Clean, B=Dirty)

    • State 7: (Location B, A=Dirty, B=Clean)

    • State 8: (Location B, B=Clean, B=Clean) - Goal State

    Note that states are distinct from positions. For example, State 1 and State 5 both have dirt in both locations, but the vacuum cleaner’s position is different.

  • Initial State: We can assume an example initial state, say State 1: (Location A, A=Dirty, B=Dirty).

  • Actions: The actions available to the vacuum cleaner are:

    • Right: Move to location B (if currently at A).

    • Left: Move to location A (if currently at B).

    • Suck: Clean dirt in the current location.

  • Goal Test: The goal is to have both locations clean. Thus, any state where both Location A and Location B are clean is a goal state. In our enumerated states, State 4 and State 8 are goal states.

  • Cost Function: We can assign a cost of 1 for each action (move or suck). This implies that we want to find a solution with the minimum number of actions.

Analyzing Example Solutions and Optimality

Let’s consider example solutions and analyze their optimality based on the defined cost function. Starting from the initial State 1: (Location A, A=Dirty, B=Dirty):

  • Solution 1 (Optimal): Suck, Right, Suck (SRS)

    1. Suck in State 1: Transitions to State 3: (Location A, A=Clean, B=Dirty). Cost = 1.

    2. Right in State 3: Transitions to State 7: (Location B, A=Clean, B=Dirty). Cost = 1.

    3. Suck in State 7: Transitions to State 8: (Location B, A=Clean, B=Clean) - Goal State. Cost = 1.

    Total cost of Solution 1 = \(1 + 1 + 1 = 3\). This is an optimal solution because it reaches a goal state in the minimum number of actions.

  • Solution 2 (Suboptimal): Right, Suck, Left, Suck

    1. Right in State 1: Transitions to State 5: (Location B, A=Dirty, B=Dirty). Cost = 1.

    2. Suck in State 5: Transitions to State 6: (Location B, A=Clean, B=Dirty). Cost = 1.

    3. Left in State 6: Transitions to State 2: (Location A, A=Clean, B=Dirty). Cost = 1.

    4. Suck in State 2: Transitions to State 4: (Location A, A=Clean, B=Clean) - Goal State. Cost = 1.

    Total cost of Solution 2 = \(1 + 1 + 1 + 1 = 4\). This is a suboptimal solution as it reaches a goal state but with a higher cost (more actions) than Solution 1.

We can also consider scenarios where the goal is refined. For instance, if the goal is to have both locations clean and the vacuum cleaner to end up in Location A. In this case, State 4 becomes the only goal state: (Location A, A=Clean, B=Clean).

  • Revised Goal: Reach State 4: (Location A, A=Clean, B=Clean).

  • Optimal Solution to Revised Goal: For the revised goal, Solution 1 (SRS) is no longer optimal because it ends in State 8 (Location B, A=Clean, B=Clean). To reach State 4, we can extend Solution 2: Right, Suck, Left, Suck, Right.

    1. Actions Right, Suck, Left, Suck lead to State 4 (as in Solution 2). Cost = 4.

    2. Right in State 4: Transitions to State 4 (remains in State 4 as it is already in Location A and moving right from A might keep it in A or be defined to wrap around, depending on environment definition, but for simplicity, assume it stays in A). Cost = 1.

    Revised Solution Cost = \(4 + 1 = 5\). Another optimal solution for the revised goal, ending in Location A, could be: Suck, Right, Suck, Left.

    1. Actions Suck, Right, Suck lead to State 8 (as in Solution 1). Cost = 3.

    2. Left in State 8: Transitions to State 4: (Location A, A=Clean, B=Clean) - Goal State. Cost = 1.

    Revised Optimal Solution Cost = \(3 + 1 = 4\). Thus, Suck, Right, Suck, Left is an optimal solution for the revised goal, with a cost of 4.

The vacuum cleaner world example, despite its simplicity, effectively demonstrates the formulation of search problems, the concept of optimality, and how changes in goals can affect optimal solutions.

Examples of Puzzle Games as Search Problems

Puzzle games are a rich source of examples for search problems in AI. They often have clear goals, well-defined states and actions, and varying levels of complexity, making them ideal for studying search algorithms.

The 8-Puzzle and 15-Puzzle Challenges

The 8-puzzle and its more complex variant, the 15-puzzle, are classic examples of rearrangement puzzles that can be formulated as search problems. The puzzle consists of a numbered square grid of tiles with one tile missing (the blank space). The goal is to rearrange the tiles from a given initial configuration to a specific goal configuration by sliding tiles into the blank space.

  • States: A state in the 8-puzzle or 15-puzzle is defined by the configuration of tiles on the grid. This can be represented as a 2D array or a sequence of tile numbers.

  • Initial State: A given starting arrangement of tiles.

  • Goal State: A specific target arrangement, typically with tiles in numerical order and the blank in the last position.

  • Actions: The actions are to slide a tile adjacent to the blank space into the blank space. Possible actions are:

    • Move Blank Up (slide tile below blank up)

    • Move Blank Down (slide tile above blank down)

    • Move Blank Left (slide tile to the right of blank left)

    • Move Blank Right (slide tile to the left of blank right)

    Not all actions are possible in every state (e.g., if the blank is at the top edge, Move Blank Up is not possible).

  • Transition Model: Deterministic. Sliding a tile changes the tile configuration in a predictable way.

  • Goal Test: Check if the current tile configuration matches the goal configuration.

  • Cost Function: Typically, a uniform cost of 1 per move is used, aiming to find the solution with the fewest moves.

State Space Explosion in Puzzle Games

Puzzle games like the 8-puzzle and 15-puzzle vividly illustrate the problem of state space explosion. The number of possible states grows factorially with the size of the puzzle, leading to immense search spaces.

  • 8-puzzle: The 8-puzzle has \(9!/2 = 181,440\) reachable states. The factor of 1/2 comes from the fact that only half of the possible permutations are reachable from any given starting state due to parity constraints.

  • 15-puzzle: The 15-puzzle, with a 4x4 grid, has a staggering \(16!/2 \approx 10^{13}\) (over 10 trillion) reachable states.

This vast state space makes it computationally prohibitive to explore all possible states exhaustively, especially for the 15-puzzle and larger versions. Efficient search algorithms and heuristics are essential to solve these puzzles in a reasonable amount of time.

Example Application: Tic-Tac-Toe (Tris) Game

Tic-Tac-Toe (also known as Tris or Noughts and Crosses) is another classic example of a search problem, but it introduces the element of game playing with two players, typically denoted as X and O.

  • States: A state in Tic-Tac-Toe is defined by the configuration of the 3x3 grid, indicating which cells are empty, contain an ‘X’, or contain an ‘O’. The game state also implicitly includes whose turn it is (X or O).

  • Initial State: An empty 3x3 board.

  • Actions: An action consists of a player (X or O) placing their mark in an empty cell on the board. The available actions depend on the current state (only empty cells can be chosen).

  • Transition Model: Deterministic. Placing a mark in an empty cell results in that cell being filled with the mark, and the turn passes to the other player.

  • Goal Test: The game ends when:

    • One player gets three of their marks in a row (horizontally, vertically, or diagonally) - this is a winning goal state.

    • All cells are filled, and no player has won - this is a draw (a terminal, but not winning, goal state).

  • Cost Function: In Tic-Tac-Toe, often no explicit cost function is used in the same way as path cost minimization problems. Instead, the focus is on game outcome (win, lose, or draw). However, in game theory formulations, utility or reward functions are defined based on game outcomes (e.g., +1 for a win, -1 for a loss, 0 for a draw for player X, and vice versa for player O).

The lecture notes mention visualizing a game tree for Tic-Tac-Toe. While it is often referred to as a tree, it is more accurately a graph because the same board configuration can be reached through different sequences of moves (transposition). However, for search purposes, it is often explored as a tree structure.

Limitations of the State Space Approach for Complex Problems

Addressing State Space Explosion

The state space approach, while conceptually powerful and widely applicable, encounters significant limitations when applied to complex problems characterized by state space explosion. As we have seen with the 15-puzzle and even more dramatically with games like chess or Go, the number of possible states can become astronomically large.

  • Computational Intractability:

    For problems with very large state spaces, it becomes computationally infeasible to:

    • Enumerate all states: Simply listing or representing all possible states becomes impossible due to memory and time constraints.

    • Explore the entire state space: Exhaustive search algorithms that explore every possible path become impractical because the search time grows exponentially with the size of the state space.

  • Examples of State Space Explosion:

    • 15-puzzle: \(\approx 10^{13}\) states.

    • Chess: Estimated \(10^{40}\) states in a typical game, and \(10^{120}\) possible games.

    • Go: Even larger state space than Chess, estimated \(10^{170}\) states.

This state space explosion necessitates the use of more efficient search algorithms and abstraction techniques to manage complexity and make problem-solving tractable.

Techniques to handle state space explosion include:

  • Heuristic Search Algorithms: Algorithms like A* search use heuristic functions to guide the search towards promising paths, significantly reducing the search space explored compared to uninformed search methods.

  • Abstraction and Problem Decomposition: Simplifying the problem by abstracting away irrelevant details or decomposing it into smaller, more manageable subproblems.

  • Local Search and Optimization Algorithms: For some problems, finding a globally optimal solution is not necessary or feasible. Local search algorithms aim to find good, locally optimal solutions in a more efficient manner.

  • Machine Learning Techniques: In very complex domains, machine learning, particularly reinforcement learning, can be used to learn effective strategies and policies without explicitly searching the entire state space.

Abstraction and Modeling in Problem Solving Context

The Role of Models and Abstraction vs. Reality

It is crucial to remember that search problems and state space representations are abstractions of real-world problems. When we formulate a problem as a search problem, we are creating a model of reality, focusing on the aspects that are relevant to problem-solving while ignoring others.

  • Models are Simplifications: By definition, models are simplified representations of reality. They are not the reality itself but rather tools to help us understand and solve problems. As the famous statistician George Box noted, "All models are wrong, but some are useful."

  • Abstraction is Necessary: Abstraction is essential to make complex problems tractable. By choosing an appropriate level of abstraction, we can represent a problem in a way that is amenable to algorithmic solution. However, abstraction always involves trade-offs, and it is important to be aware of what is being simplified or ignored.

  • Danger of Confusing Model with Reality: It is crucial not to confuse the model with reality. The model is a tool, and its usefulness depends on how well it captures the essential aspects of the real problem. As humorously put by Arthur Bloch, "Confusing the model with reality is like going to a restaurant and eating the menu." The menu (model) describes the food (reality), but it is not the food itself.

Therefore, when applying search problem formulations in AI, it is vital to:

  • Choose the Right Level of Abstraction: Select a level of detail in state representation and action modeling that is appropriate for the problem’s complexity and the available computational resources.

  • Understand Model Limitations: Be aware of the assumptions and simplifications inherent in the model and their potential impact on the solutions found.

  • Iterate and Refine Models: Problem formulation is often an iterative process. Initial models may need to be refined or revised as we gain a better understanding of the problem and its complexities.

State Space Graphs and Search Trees

To effectively visualize and solve search problems, two crucial representational tools are employed: State Space Graphs and Search Trees. These representations provide frameworks for understanding the structure of a problem and for systematically exploring potential solutions.

State Space Graphs: A Visual Representation

The state space graph is a graphical construct that provides a visual and intuitive representation of a search problem. It captures the essential elements of the problem in a structured diagram, facilitating understanding of the problem’s state space and transitions.

Nodes Representing States

In a state space graph, each node corresponds to a unique state within the problem’s state space. Nodes are abstract representations of the possible configurations of the world that are relevant to the problem at hand. Each node encapsulates all the necessary information to define a particular situation in the environment.

Arcs Representing Actions and Transitions

Arcs, or directed edges, in the state space graph represent the actions that an agent can take to transition from one state to another. A directed arc from a node representing state A to a node representing state B signifies that it is possible to move from state A to state B by executing a specific action.

These arcs are typically:

  • Directed: Indicating the direction of the transition from a preceding state to a succeeding state.

  • Labeled: Often labeled with the action name that causes the transition, providing clarity on what action leads from one state to the next.

  • Weighted: Can be weighted with the cost of the action, representing the numerical cost associated with performing that action and transitioning between the states.

Encoding Costs and Identifying Goal States

The costs associated with actions, if applicable, are typically encoded as weights on the arcs, allowing for the representation of path costs and optimal solutions. Goal states, which are the desired end configurations, are identified within the state space graph as a specific subset of nodes. These goal nodes are often visually distinguished, for example, by using double circles or color highlighting, to clearly mark the successful termination points of a search.

Solutions as Paths within the State Space Graph

A solution to a search problem, within the context of a state space graph, is represented as a path from the node corresponding to the initial state to a node representing a goal state. This path is a sequence of connected arcs, starting from the initial node and ending at a goal node.

  • Path Cost: The cost of a path is calculated by summing the costs of all the arcs that constitute the path. If costs are uniform (e.g., cost of 1 for each action), the path cost is simply the number of arcs in the path.

  • Optimal Solution: An optimal solution corresponds to a path with the lowest total cost among all possible paths from the initial state to any goal state. Finding an optimal solution is often the objective of search algorithms.

  • Finding a route from one city to another becomes a problem of finding a path in this graph.

The vacuum cleaner world can also be effectively visualized as a state space graph. For the 2-location vacuum world:

  • Arcs represent the actions: Left, Right, and Suck, which cause transitions between states.

  • The goal states (both locations clean) are marked as goal nodes in the graph.

Search Trees: Exploring Solution Paths

The search tree is another representation, derived from the state space graph, used to explore possible solution paths. It is particularly useful for systematically searching for solutions.

Constructing Search Trees from State Space Graphs

A search tree is constructed starting from the initial state node of the state space graph as the root. For each node in the tree, branches are created for each possible action, leading to child nodes representing the resulting states. Unlike state space graphs, search trees can have multiple nodes representing the same state if that state is reached through different paths.

Relating Paths in Search Trees to State Space Graph Paths

Each path from the root to a node in the search tree corresponds to a path in the state space graph from the initial state to the state represented by that node. However, a single state in the state space graph can be represented by multiple nodes in the search tree, especially if there are cycles in the state space graph.

The optimal path in the state space graph is highlighted, and its corresponding path is shown in the search tree. The search tree explicitly shows all explored paths from the initial state.

Introduction to Efficiency Advantages of Search Trees

Search trees, despite potentially being larger than state space graphs (due to repeated states), offer advantages for search algorithms. They allow for systematic exploration of paths and can be pruned to avoid redundant or suboptimal paths. Search trees facilitate algorithms that can efficiently find solutions without needing to explicitly construct the entire state space graph in memory. Algorithms can explore branches of the search tree and backtrack when necessary, potentially saving computational resources.

# Task Environments

A **task environment** encapsulates the external conditions and settings
in which an agent operates. Understanding the properties of task
environments is paramount because these characteristics dictate the
design and capabilities required for an agent to perform effectively.
The nature of the task environment directly influences the agent's
perception, decision-making process, and action execution.

## Properties of Task Environments

Task environments can be systematically classified based on a set of
distinct properties. These properties are not mutually exclusive and can
be combined to describe a wide range of environments. Analyzing these
properties is crucial for understanding the inherent challenges and
complexities in designing agents tailored for specific operational
domains.

### Observability

**Observability** refers to the degree to which an agent can perceive
the current state of its environment through its sensors. This property
ranges from complete access to the environment's state to limited or
indirect access.

#### Completely Observable Environments

::: tcolorbox
A task environment is **completely observable** if the agent's sensors
provide it with access to the entire state of the environment at any
given time. In such environments, the agent has all the necessary
information to make optimal decisions based on the current state alone.
:::

-   **Example:**

    ::: tcolorbox
    Solving a **crossword puzzle**. All the clues and the current state
    of the grid are visible to the solver at all times. There is no
    hidden information relevant to solving the puzzle.
    :::

#### Partially Observable Environments

::: tcolorbox
In contrast, a **partially observable environment** is one where the
agent's sensors only provide access to a subset of the environment's
state. Some crucial information might be hidden, inaccessible, or noisy,
requiring the agent to infer or estimate the complete state.
:::

-   **Example:**

    ::: tcolorbox
    A **medical diagnosis system**. A doctor or an AI system might not
    have immediate access to all the physiological parameters or the
    complete medical history of a patient. Diagnostic decisions must be
    made based on available symptoms, test results, and patient history,
    which represent only a partial view of the patient's actual health
    state.
    :::

The distinction between complete and partial observability significantly
impacts the complexity of agent design. Agents in partially observable
environments often need to maintain internal states, use memory, and
employ belief states to reason about the unobserved parts of the
environment.

### Number of Agents

The **number of agents** property classifies environments based on how
many agents are operating and interacting within them. This distinction
is crucial as it determines whether an agent needs to consider the
actions and presence of other entities.

#### Single Agent Environments

::: tcolorbox
A **single agent environment** involves only one agent that is acting
and operating within the environment. The agent is isolated in terms of
decision-making entities, although the environment itself might be
complex.
:::

-   **Example:**

    ::: tcolorbox
    An agent designed to solve a **crossword puzzle**. The agent works
    in isolation, without any other entity simultaneously trying to
    alter the puzzle or compete for resources.
    :::

#### Multiagent Environments

::: tcolorbox
A **multiagent environment** involves more than one agent simultaneously
operating and interacting within the environment. These agents can be
cooperative, competitive, or a combination of both. The presence of
multiple agents introduces complexities such as coordination,
communication, competition for resources, and strategic interactions.
:::

-   **Example:**

    ::: tcolorbox
    A **medical diagnosis system** can be viewed as a multiagent
    environment. Consider the patient, the diagnosing physician, and
    perhaps other specialists or automated diagnostic tools as distinct
    agents. Each agent interacts and influences the environment
    (patient's health state) and each other to achieve their respective
    goals (patient's well-being, accurate diagnosis).
    :::

In multiagent environments, agents must be designed to reason about the
behavior of other agents, which can be unpredictable and can
significantly affect the environment's state and the agent's own
performance.

### Determinism

**Determinism** describes the relationship between an agent's actions
and the resulting state of the environment. It specifies whether the
outcome of an action is predictable and unique or if there is inherent
uncertainty.

#### Deterministic Environments

::: tcolorbox
In a **deterministic environment**, for any given state and agent
action, there is only one possible resulting state. The outcome of
actions is predictable and certain.
:::

-   **Example:**

    ::: tcolorbox
    Solving a **crossword puzzle**. When an agent writes a specific word
    in a set of cells, the outcome is always the same: that word is
    placed in those cells. There is no element of chance or variability
    in the outcome of this action.
    :::

#### Non-deterministic Environments

::: tcolorbox
A **non-deterministic environment**, also known as a **stochastic
environment**, is characterized by uncertainty in the outcomes of
actions. For a given state and action, there might be multiple possible
resulting states, and the actual outcome is not fully predictable.
:::

-   **Example:**

    ::: tcolorbox
    **Medical diagnosis and treatment**. Medical treatments are often
    non-deterministic. For instance, administering a vaccine might have
    a high probability of preventing a disease, but it is not guaranteed
    to work in every case due to individual patient variability and
    other factors. There's a probabilistic element to the outcome of
    medical interventions.
    :::

Dealing with non-determinism requires agents to reason under
uncertainty, consider probabilities of different outcomes, and
potentially employ strategies that are robust to variability.

### Episode Type

The **episode type** property distinguishes between environments based
on the structure of the agent's experience. It defines whether the
agent's interaction with the environment is divided into independent
episodes or unfolds as a continuous sequence of interactions.

#### Episodic Environments

::: tcolorbox
In an **episodic environment**, the agent's experience is divided into a
series of independent episodes. In each episode, the agent perceives the
environment and then performs a single action. The crucial
characteristic is that each episode is self-contained; the agent's
action in one episode does not affect the environment or subsequent
episodes.
:::

-   **Example:**

    ::: tcolorbox
    A **classification task**, such as identifying types of objects from
    images. Each image presented to the agent is an independent episode.
    The agent classifies the image, and this action does not influence
    the next image it will be presented with. Each classification is a
    separate, self-contained task.
    :::

#### Sequential Environments

::: tcolorbox
In a **sequential environment**, the agent engages in a sequence of
actions where the current decision can affect not only the immediate
outcome but also future states and subsequent decisions. Actions have
long-term consequences, and the agent needs to consider the future
implications of its current choices.
:::

-   **Example:**

    ::: tcolorbox
    **Medical treatment planning**. Medical treatments are inherently
    sequential. The initial diagnosis and treatment plan set the stage
    for future health states and subsequent treatment decisions. For
    example, an initial treatment might affect the patient's response to
    later treatments, making the process sequential and requiring
    long-term planning.
    :::

-   **Example:**

    ::: tcolorbox
    Solving a **crossword puzzle**. Crossword puzzles are also
    sequential because filling in one word can constrain the
    possibilities for intersecting words. Decisions made early in
    solving the puzzle affect the options and constraints available
    later on.
    :::

Sequential environments demand agents that can plan ahead, consider the
long-term consequences of their actions, and adapt their strategies over
time based on the unfolding sequence of interactions.

### Environment Dynamics

**Environment dynamics** describes whether the environment itself
changes over time, particularly in relation to the agent's thinking and
acting processes. This property determines if the agent is operating in
a static or changing world.

#### Static Environments

::: tcolorbox
A **static environment** is one that remains unchanged while the agent
is deliberating and deciding on an action. The only changes in the
environment are those directly caused by the agent's actions. If the
agent pauses to think, the world does not evolve on its own.
:::

-   **Example:**

    ::: tcolorbox
    Solving a **crossword puzzle**. The crossword puzzle grid and clues
    do not change while the solver is thinking about possible answers.
    The puzzle remains constant until the solver makes a change by
    filling in a word.
    :::

#### Dynamic Environments

::: tcolorbox
In a **dynamic environment**, the environment can change independently
of the agent's actions and while the agent is in the process of deciding
what to do. This means the environment can evolve over time, presenting
new situations and challenges even if the agent takes no action. Agents
in dynamic environments must be reactive and capable of making timely
decisions in response to these changes.
:::

-   **Example:**

    ::: tcolorbox
    **Medical diagnosis of a patient in critical condition**. A
    patient's health status can change rapidly and unpredictably, even
    as a doctor is assessing the situation and planning interventions.
    For instance, a patient experiencing severe bleeding might
    deteriorate quickly, requiring immediate and adaptive responses from
    the medical team.
    :::

Dynamic environments often require agents to operate in real-time or
near real-time, continuously monitoring the environment and reacting
promptly to changes.

### State Space

The **state space** property refers to the nature of the possible states
within the environment. It considers whether the states are discrete or
continuous and whether the total number of states is finite or infinite.

#### Discrete Environments

::: tcolorbox
A **discrete environment** is characterized by a countable number of
distinct states, actions, and percepts. The values are typically drawn
from a finite or countably infinite set, often represented as integers
or symbols.
:::

-   **Example:**

    ::: tcolorbox
    Solving a **crossword puzzle**. The possible states can be described
    by the arrangement of letters in the grid, which is discrete. The
    actions (filling in letters) and percepts (viewing the grid) are
    also discrete.
    :::

#### Continuous Environments

::: tcolorbox
In a **continuous environment**, the states, actions, and percepts can
take on values from a continuous range, typically represented by real
numbers. These environments involve variables that can change smoothly
and take on any value within a given range.
:::

-   **Example:**

    ::: tcolorbox
    Monitoring a patient's **temperature** in a medical diagnosis
    system. Body temperature is a continuous variable that can take any
    value within a physiological range. Similarly, other vital signs
    like blood pressure and heart rate are also continuous.
    :::

Continuous environments often require different mathematical and
computational tools compared to discrete environments, such as calculus
and numerical methods, to model and control agent behavior.

### Knowledge of Environment

**Knowledge of the environment** pertains to what the agent or the
agent's designer knows about the rules and physics governing the
environment's behavior. This property is about the level of prior
information available.

#### Known Environments

::: tcolorbox
In a **known environment**, the agent (or more accurately, the designer)
has complete knowledge of the environment's rules, including how the
environment operates and the precise effects of each action. The agent
can rely on this pre-existing knowledge to plan and act effectively.
:::

#### Unknown Environments

::: tcolorbox
In an **unknown environment**, the agent (and potentially the designer
initially) does not possess prior knowledge of the environment's rules.
The agent must learn how the environment works through exploration and
interaction. This often involves trial and error, observation, and
learning from experience to build a model of the environment.
:::

-   **Example:**

    ::: tcolorbox
    **AlphaGo Zero** learning to play Go. AlphaGo Zero was designed to
    learn the game of Go from scratch, without being explicitly
    programmed with the rules or strategies of Go. It learned by playing
    against itself, exploring the game's state space, and discovering
    effective strategies through self-play and reinforcement learning in
    an initially unknown environment.
    :::

Agents in unknown environments require learning mechanisms and
exploration strategies to acquire knowledge and improve their
performance over time.

### Knowledge of Performance Measure

**Knowledge of the performance measure** refers to whether the agent and
its designer are aware of the criteria that define successful
performance in the task environment. This is about understanding what
constitutes success or optimality.

#### Known Performance Measure

::: tcolorbox
In scenarios with a **known performance measure**, both the agent and
the designer have a clear and well-defined metric to evaluate the
agent's success. This measure is typically quantifiable and directly
reflects the objectives of the task.
:::

#### Unknown Performance Measure

::: tcolorbox
In situations with an **unknown performance measure**, the criteria for
success are not initially well-defined or fully understood by the agent
or even the designer. The agent might need to interact with an external
entity, such as a human user, to understand and refine what constitutes
good performance. This is common in complex or subjective tasks where
success is hard to quantify directly.
:::

For instance, in creative tasks or in scenarios where user satisfaction
is paramount, the performance measure might be implicitly defined and
only become clear through interaction and feedback.

## Classifying and Characterizing Task Environments

The seven properties discussed---observability, number of agents,
determinism, episode type, dynamics, state space, and knowledge of the
environment and performance measure---collectively provide a
comprehensive framework for classifying and characterizing task
environments. By analyzing a task environment along these dimensions, we
can gain a deeper understanding of its nature and the challenges it
poses for agent design. It is important to note, as highlighted in the
lecture, that while these properties offer a structured approach, the
categorization can sometimes be subjective and context-dependent. The
precise classification might depend on the perspective of the observer
or the specific level of abstraction considered.

## Difficulty based on Task Environment Properties

The difficulty of designing an effective agent for a given task
environment is significantly influenced by these properties. Task
environments become progressively more challenging as they exhibit the
following characteristics:

-   **Partial Observability**: Agents must manage uncertainty and
    maintain internal representations of the unobserved parts of the
    environment, increasing complexity in state estimation and
    decision-making.

-   **Multiagent Nature**: The presence of other agents introduces
    unpredictability and strategic interactions, requiring agents to
    model and anticipate the behavior of others, which can be
    computationally intensive and complex.

-   **Non-determinism (Stochasticity)**: Agents must cope with uncertain
    outcomes of their actions, necessitating probabilistic reasoning,
    risk assessment, and planning for contingencies, making
    decision-making more intricate.

-   **Sequential Episodes**: The need to consider long-term consequences
    and plan sequences of actions over extended periods adds a layer of
    complexity, requiring agents to perform planning and optimization
    over time horizons.

-   **Dynamic Nature**: Environments that change autonomously demand
    timely reactions and continuous monitoring. Agents must be reactive
    and adaptive, capable of processing information and making decisions
    quickly in response to environmental changes.

-   **Continuous State and Action Spaces**: Dealing with continuous
    variables requires more sophisticated mathematical tools and
    computational techniques compared to discrete environments.
    Optimization and control in continuous spaces are generally more
    complex.

-   **Unknown Environment**: Agents must learn the environment's
    dynamics and rules through exploration, adding a learning component
    to the agent design. Exploration strategies and learning algorithms
    become crucial for effective operation.

Environments that combine several of these challenging properties
represent the most complex scenarios for AI agent design, demanding
sophisticated architectures and algorithms to achieve robust and
intelligent behavior.

    solved by an individual in isolation.

-   **Determinism**: **Deterministic**. Filling in a word has a
    predictable outcome.

-   **Episode Type**: **Sequential**. Entries must interlock, making
    decisions interdependent. Solving a crossword is not a series of
    independent steps but a connected process.

-   **Environment Dynamics**: **Static**. The puzzle itself does not
    change while being solved.

-   **State Space**: **Discrete**. The puzzle grid, letters, and word
    choices are all discrete.

-   **Knowledge of Environment**: **Depends on the solver**. For someone
    familiar with crossword conventions and vocabulary, the environment
    is largely known. For a novice, it might be partially unknown,
    requiring learning of puzzle-solving strategies.

### Medical Diagnosis System Environment: Detailed Analysis

-   **Observability**: **Partially Observable**. A medical system does
    not have complete and immediate access to all patient information.
    Some conditions might be hidden, symptoms might be misleading, and
    test results take time to process.

-   **Agents**: **Multiagent (Potentially)**. While the primary
    diagnostic agent might be considered single, the environment
    inherently involves multiple agents. The patient's body is a complex
    system, and considering other medical personnel or even other AI
    diagnostic tools makes it multiagent.

-   **Determinism**: **Non-deterministic (Stochastic)**. Medical
    treatments and diagnoses are not always certain. The same treatment
    can have different outcomes for different patients, and diagnoses
    are based on probabilities and likelihoods, not absolute certainty.

-   **Episode Type**: **Sequential**. Medical diagnosis and treatment
    are inherently sequential. Initial diagnoses and treatments
    influence subsequent health states and future interventions. Patient
    care is a continuous and evolving process.

-   **Environment Dynamics**: **Dynamic**. A patient's health condition
    can change rapidly and unpredictably, especially in critical
    situations. The environment (patient's body) is not static and
    evolves independently of the diagnostic agent's immediate actions.

-   **State Space**: **Continuous (Likely)**. Many relevant variables in
    medical diagnosis, such as temperature, blood pressure, and blood
    glucose levels, are continuous.

-   **Knowledge of Environment**: **Partially Known**. Medical science
    is constantly evolving, and our understanding of the human body and
    diseases is incomplete. Diagnostic systems operate with partial and
    evolving knowledge of the environment.

## Impact of Task Environment Characteristics on Agent Design

The characteristics of the task environment have profound implications
for how we design intelligent agents. Understanding these impacts is
crucial for developing agents that are well-suited to their operational
domains. The following points elaborate on how each property influences
agent design:

-   **Partial Observability**: In partially observable environments,
    agents cannot rely solely on immediate perceptions. They must
    incorporate **memory** to store past perceptions and build an
    **internal state** or **belief state**. This internal model allows
    them to reason about aspects of the environment that are not
    currently visible. Techniques like state estimation, filtering, and
    probabilistic reasoning become essential.

-   **Stochastic Environments**: When environments are stochastic,
    agents must be designed to handle **uncertainty**. They need to
    consider multiple possible outcomes for their actions and evaluate
    actions based on **expected outcomes** rather than certain results.
    Probabilistic planning, decision theory, and risk management are
    crucial components for agents in such environments.

-   **Multiagent Environments**: In multiagent settings, agents must
    account for the presence and actions of **other agents**. This may
    require modeling other agents, understanding game theory, and
    employing strategies that consider potential cooperation,
    competition, or negotiation. In some cases, introducing an element
    of **randomness** in behavior can be beneficial to avoid predictable
    patterns that could be exploited by other agents.

-   **Static Environments**: Static environments offer the advantage of
    time for **deliberation**. Agents can afford to spend more
    computational resources on planning and decision-making because the
    environment will not change while they are thinking. Complex
    planning algorithms and extensive search strategies become feasible.

-   **Dynamic Environments**: Dynamic environments demand **reactive
    agents** capable of timely responses. Agents must be efficient in
    their processing and decision-making to keep pace with the
    environment's changes. Real-time processing, reactive architectures,
    and potentially simpler decision-making mechanisms are favored.

-   **Continuous Environments**: Handling continuous variables requires
    agents to use mathematical tools suitable for continuous spaces.
    This often involves calculus, differential equations, and numerical
    methods. Agent designs may need to incorporate continuous control,
    function approximation, and optimization techniques adapted for
    continuous domains.

-   **Unknown Environments**: Agents operating in unknown environments
    must be equipped with **learning mechanisms**. They need to explore
    the environment, gather data, and learn models of the environment's
    dynamics and rules. Reinforcement learning, exploration-exploitation
    strategies, and model learning become central to agent capabilities.

-   **Unknown Performance Measure**: When the performance measure is not
    explicitly given, agents need mechanisms to **interact with an
    external evaluator**, often a human. This interaction is crucial for
    understanding and refining the goals. Techniques like interactive
    learning, preference learning, and methods for eliciting feedback
    from users become relevant for aligning agent behavior with desired
    outcomes.

In summary, the task environment is not merely a backdrop for agent
operation but a fundamental determinant of agent design. A thorough
analysis of the task environment's properties is the first critical step
in engineering intelligent agents that can effectively achieve their
goals in diverse and complex settings.

# Types of Agents

Agents can be categorized based on their internal architecture and
decision-making processes. This lecture outlines five fundamental types
of agents, each representing an incremental increase in complexity and
capability. These categories provide a structured way to understand the
design space of intelligent agents.

## Simple Reflex Agents

### Structure and Operational Mechanism

::: tcolorbox
**Simple reflex agents** are the most basic type of agent. They operate
on a direct mapping from the current percept to an action. These agents
react instantaneously to the environment based on predefined rules,
disregarding any history of perceptions or future consequences. Their
decision-making process is purely reactive and memoryless.
:::

### Implementation with Condition-Action Rules

Simple reflex agents are typically implemented using a set of
**condition-action rules**, often expressed as \"if-then\" rules. These
rules dictate the action to be taken when a specific condition in the
environment is perceived.

-   **Example Rules:**

    -   *If* current *location is dirty*, *then* perform *suck* action.
        (Vacuum Cleaner Agent)

    -   *If* *car ahead is braking* (as perceived by sensors), *then*
        engage *brake* action. (Autonomous Driving Agent)

The program for a simple reflex agent involves:

1.  Perceiving the current state of the environment through sensors.

2.  Matching the current percept against the conditions defined in the
    rule set.

3.  Selecting and executing the action associated with the first rule
    that matches the current percept. If no rule matches, no action is
    taken.

This process is repeated in each time step, making the agent
continuously reactive to its immediate surroundings.

### Limitations of Simple Reflex Agents

::: tcolorbox
Despite their simplicity and reactivity, simple reflex agents suffer
from several limitations.
:::

-   **Limited Rationality in Partially Observable Environments:** Simple
    reflex agents are truly effective only in **completely observable
    environments**. In partially observable environments, their
    decisions are based solely on the limited information available in
    thecurrent percept, which may not be sufficient for optimal action.
    They cannot infer aspects of the world they cannot currently
    perceive.

-   **Lack of Memory and History Consideration:** These agents **ignore
    the history of perceptions**. They do not have any internal state or
    memory to store past information. Consequently, they cannot learn
    from past experiences, adapt to changes over time, or plan based on
    previous events.

-   **Inability to Handle Complex Goals:** Simple reflex agents are best
    suited for simple tasks where the optimal action can be determined
    directly from the current percept. They are not capable of handling
    complex goals that require planning, problem-solving, or
    consideration of future outcomes.

These limitations restrict the applicability of simple reflex agents to
relatively simple environments and tasks. For more complex scenarios,
more sophisticated agent architectures are necessary.

## Model-Based Reflex Agents

### Incorporating a World Model

::: tcolorbox
**Model-based reflex agents** represent an enhancement over simple
reflex agents by incorporating a **model of the world**. This model
allows the agent to reason about the environment's state, even the
aspects that are not directly perceived in the current percept. By
maintaining an internal representation of how the world works, these
agents can make more informed decisions in partially observable
environments.
:::

### Internal State and Memory Usage

Unlike simple reflex agents, model-based agents maintain an **internal
state**. This state is a representation of the current world state,
derived from the history of perceptions. The internal state acts as a
form of memory, allowing the agent to keep track of aspects of the
environment that are not immediately visible. This enables the agent to
make decisions based not only on the current percept but also on its
understanding of the unobserved parts of the world.

### Transition Model and Sensor Model Components

To maintain and utilize the world model, model-based agents rely on two
key components:

-   **Transition Model**:

    ::: tcolorbox
    This model describes **how the world evolves**. It encapsulates two
    types of knowledge:

    1.  **Autonomous Evolution**: How the environment changes
        independently of the agent's actions over time.

    2.  **Action Effects**: How the agent's actions affect the
        environment and cause transitions from one state to another.

    The transition model allows the agent to predict the next state of
    the world given its current state and the action it takes. This can
    be deterministic or stochastic, depending on the environment's
    nature.
    :::

-   **Sensor Model**:

    ::: tcolorbox
    This model describes **how the agent's sensors perceive the
    environment**. It specifies the relationship between the actual
    state of the world and the perceptual input received by the agent.
    The sensor model helps the agent interpret noisy or incomplete
    sensory information and update its internal state accordingly. It
    accounts for the limitations and characteristics of the agent's
    sensors.
    :::

### Advantages Over Simple Reflex Agents

::: tcolorbox
Model-based reflex agents offer significant advantages over simple
reflex agents, particularly in more realistic and complex environments.
:::

-   **Handling Partially Observable Environments:** By maintaining an
    internal state and using a world model, these agents can operate
    effectively in **partially observable environments**. They can infer
    the hidden aspects of the world and make decisions based on a more
    complete, albeit inferred, understanding of the situation.

-   **Informed Decision Making:** Model-based agents make more
    **informed decisions** because they consider not only the current
    percept but also the history of perceptions and the predicted
    outcomes of their actions. This allows for more strategic and
    context-aware behavior compared to the purely reactive nature of
    simple reflex agents.

However, the effectiveness of model-based agents heavily depends on the
accuracy and completeness of their world model. Constructing and
maintaining an accurate model can be challenging, especially in complex
and dynamic environments.

## Goal-Based Agents

### Defining Agent Goals and Objectives

::: tcolorbox
**Goal-based agents** represent a further step towards more
sophisticated agent architectures. Building upon model-based agents,
they incorporate **goals** into their decision-making process. Instead
of merely reacting to the current state or predicting future states,
goal-based agents actively seek to achieve specific objectives.
**Goals** are desired states of the environment that the agent aims to
reach.
:::

### Planning for Goal Achievement

Goal-based agents engage in **planning** to achieve their goals. This
involves:

1.  **Reasoning about future states**: The agent uses its world model to
    predict the states that would result from different sequences of
    actions.

2.  **Choosing actions that lead to goal states**: The agent selects
    actions that it believes will eventually lead to a state that
    satisfies its goal.

To achieve this, goal-based agents often employ **search and planning
algorithms**. These algorithms explore possible sequences of actions,
evaluate their potential outcomes, and identify a path that leads to a
goal state. The agent needs to answer questions such as:

-   *What will be the state of the world if I perform action A in the
    current state?*

-   *Will performing action A, or a sequence of actions starting with A,
    bring me closer to achieving my goal?*

The focus shifts from immediate reaction to purposeful action aimed at
achieving a predefined objective.

### Limitations in Handling Conflicting Objectives

::: tcolorbox
While goal-based agents are more sophisticated than reflex agents, they
have limitations, particularly when dealing with **multiple or
conflicting goals**.
:::

-   **Binary Goal Satisfaction**: Goal-based agents typically treat
    goals in a binary fashion: a state either satisfies the goal or it
    does not. This binary view is often insufficient to express
    preferences among different goal states or to handle situations
    where achieving one goal might hinder the achievement of another.

-   **Lack of Prioritization and Trade-offs**: When faced with multiple
    goals, goal-based agents lack a mechanism to **prioritize** or make
    **trade-offs** between them, especially if the goals are mutually
    exclusive or have varying levels of importance. All goals are
    treated as equally important objectives to be achieved, which can
    lead to suboptimal behavior in complex scenarios where some goals
    are more critical or easier to achieve than others.

These limitations highlight the need for a more nuanced approach to
decision-making, especially in environments with complex objectives and
constraints.

## Utility-Based Agents

### Introducing the Utility Concept

::: tcolorbox
**Utility-based agents** overcome the limitations of goal-based agents
by introducing the concept of **utility**. Utility provides a more
flexible and comprehensive framework for decision-making by quantifying
the **desirability** of different states. **Utility** is a measure of
\"happiness\" or \"satisfaction\" that an agent derives from being in a
particular state. It allows the agent to express preferences not just
between achieving a goal and not achieving it, but also among different
states of the world, including goal states.
:::

### Utility as a Performance Measure

Utility acts as a refined **performance measure** that goes beyond
simple goal satisfaction. Instead of a binary outcome (goal achieved or
not), utility assigns a **numerical value** to each state. This value
represents how preferable or desirable that state is to the agent.
Higher utility values correspond to more desirable states, and lower
values to less desirable or undesirable states.

### Managing Uncertainty and Preferences with Utility

Utility-based agents are particularly well-suited for handling
**uncertainty** and expressing **preferences**:

-   **Handling Probabilistic Outcomes**: In stochastic environments,
    actions may lead to different outcomes with varying probabilities.
    Utility-based agents can evaluate actions by considering the
    **expected utility** of their outcomes. Expected utility is
    calculated by averaging the utilities of possible resulting states,
    weighted by their probabilities. This allows agents to make rational
    decisions even when outcomes are uncertain.

-   **Resolving Conflicting Goals and Trade-offs**: Utility provides a
    mechanism to handle **conflicting goals** and make **trade-offs**.
    When faced with multiple goals that cannot all be fully achieved, or
    when achieving one goal compromises another, utility-based agents
    can choose actions that maximize their overall utility. They can
    prioritize goals and make rational compromises based on the relative
    utilities of different outcomes.

-   **Expressing Preferences Among Goal States**: Utility allows agents
    to express **preferences between different goal states**. Not all
    goal states are equally desirable. Some might be more beneficial or
    rewarding than others. Utility enables agents to differentiate
    between goal states and aim for those that provide higher utility.

### Advantages of Utility-Based Agent Architecture

::: tcolorbox
Utility-based agents are considered more rational and flexible than
goal-based agents, especially in complex and uncertain environments,
because they can:
:::

-   **Make Decisions in Uncertain Environments**: They can make rational
    choices even when the outcomes of actions are probabilistic, by
    maximizing expected utility.

-   **Balance Multiple Objectives and Preferences**: They can handle
    situations with multiple, potentially conflicting objectives and
    express preferences among different outcomes using the utility
    function.

-   **Maximize Overall Well-being or Performance**: They aim to choose
    actions that maximize their overall \"well-being\" or performance,
    as quantified by the utility function. This leads to more nuanced
    and adaptable behavior in complex scenarios.

The design of utility functions is a critical aspect of developing
utility-based agents. The utility function must accurately reflect the
agent's preferences and the objectives it is designed to achieve.

## Learning Agents (Brief Overview)

::: tcolorbox
**Learning agents** represent a significant advancement in agent design,
enabling agents to **improve their performance over time** by learning
from experience. Learning agents can adapt to new environments, refine
their strategies, and become more effective problem solvers through
learning.
:::

This section provides a brief overview, as learning agents are a central
topic in AI and will be covered in greater detail later in the course.

### Performance Element in Learning Agents

::: tcolorbox
The **performanceElement** is the core component of a learning agent
responsible for **selecting actions**. It embodies the agent's current
strategy or policy for acting in the environment. Importantly, the
performance element can be any of the agent types discussed previously:
simple reflex, model-based reflex, goal-based, or utility-based. It is
the part of the agent that directly interacts with the environment and
executes actions.
:::

### Learning Element and its Role

::: tcolorbox
The **learning element** is the component that enables the agent to
**improve**. It is responsible for taking feedback from the **critic**
and using this feedback to modify and enhance the **performance
element**. The learning element's goal is to make the performance
element act more effectively in the future.
:::

The specific modifications made by the learning element depend on the
type of performance element and the learning mechanism employed. It can
adjust:

-   **Rules** in a simple reflex agent.

-   **Models** in a model-based agent (transition and sensor models).

-   **Goals** in a goal-based agent (although goal modification is less
    common in basic learning agents).

-   **Utility functions** in a utility-based agent.

### Function of the Critic and Problem Generator

Learning agents typically include two additional components that guide
the learning process:

-   **Critic**:

    ::: tcolorbox
    The **critic** evaluates the agent's performance in the environment.
    It observes the agent's behavior and provides **feedback** to the
    learning element. This feedback is based on a predefined
    **performance standard** or measure. The critic essentially answers
    the question: *\"How well is the agent doing?\"* It informs the
    learning element about the agent's successes and failures,
    indicating areas for improvement. The feedback can be in various
    forms, such as rewards, penalties, or evaluations of state
    desirability.
    :::

-   **Problem Generator**:

    ::: tcolorbox
    The **problem generator** is responsible for suggesting
    **exploratory actions**. Its role is to push the agent to explore
    new parts of the environment and try out different actions, even
    those that might not seem optimal based on current knowledge. The
    problem generator aims to ensure that the agent does not become
    stuck in suboptimal strategies and instead seeks out new experiences
    that can lead to learning and improvement. For example, in a
    game-playing agent, the problem generator might suggest trying a
    move that is not immediately obvious but could potentially uncover a
    new winning strategy. It addresses the need for **exploration** in
    learning, balancing it with **exploitation** of current knowledge by
    the performance element.
    :::

::: tcolorbox
In summary, a learning agent operates by having the performance element
act in the environment, the critic evaluate its performance, the
learning element use this feedback to improve the performance element,
and the problem generator suggest explorations. This cycle of action,
evaluation, learning, and exploration enables the agent to adapt and
enhance its capabilities over time, becoming more intelligent and
effective in its task environment.
:::

# Representing the World

Agents operate within environments and must possess some form of
internal representation or **world model** to reason and act
effectively. The level of detail and abstraction in these world models
can vary significantly, impacting the agent's capabilities and
complexity. We can categorize these representations into three primary
levels of abstraction: atomic, factored, and structured. These levels
form a spectrum, ranging from simple and undifferentiated to complex and
richly detailed.

## Levels of Abstraction for World Models

The choice of world representation is a critical design decision,
influencing the agent's ability to perceive, reason, and act within its
environment. The level of abstraction should be appropriate for the
complexity of the task and the environment itself.

### Atomic World Representation

::: tcolorbox
In an **atomic world representation**, each state of the world is
treated as a single, indivisible entity. States are considered
**atomic** because they lack internal structure and are represented as
unique, opaque symbols or identifiers.
:::

When using an atomic representation:

-   **States are Black Boxes**: Each state is a fundamental unit, and
    there is no decomposition into smaller parts or attributes.

-   **Indivisible and Unique**: States are distinct from one another,
    and the only operation typically supported is comparing states for
    equality or inequality. We can determine if two states are the same
    or different, but we cannot access or reason about their internal
    components.

-   **Simplicity**: This is the simplest form of world representation,
    suitable for environments where the distinctions between states are
    paramount, and internal details are not relevant for
    decision-making.

**Example:**

::: tcolorbox
Consider a self-driving taxi navigating between cities. Using an atomic
representation, we might represent the taxi's location simply as the
name of the city it is currently in.

-   **States:** `Arad`, `Bucharest`, `Craiova`, `Dobreta`, `Eforie`,
    `Fagaras`, `Giurgiu`, `Hirsova`, `Iasi`, `Lugoj`, `Mehadia`,
    `Neamt`, `Oradea`, `Pitesti`, `Rimnicu Vilcea`, `Sibiu`,
    `Timisoara`, `Urziceni`, `Vaslui`, `Zerind`.

In this representation, each city name is an atomic state. The agent can
distinguish between being in `Padova` versus `Venice`, but the
representation does not capture any information about locations within
each city or relationships between cities. This level of abstraction is
useful when the task primarily involves navigating between distinct
locations, and the details within each location are not important for
the agent's decisions.
:::

### Factored World Representation

::: tcolorbox
A **factored world representation** offers a more structured approach by
describing a state as a collection of **variables** or **attributes**.
Each variable can take on a specific **value** from its domain. This
decomposition of states into factors allows for a more detailed and
flexible representation compared to atomic states.
:::

Key characteristics of factored representations include:

-   **Structured States**: States are no longer monolithic but are
    structured as a set of features or properties.

-   **Variables and Values**: The world is described in terms of
    variables, each representing a specific aspect of the environment,
    and each variable is assigned a value that describes the state of
    that aspect.

-   **Relationships between States**: Factored representations allow for
    expressing relationships and similarities between states based on
    shared variable values.

-   **Increased Expressiveness**: This representation is more expressive
    than atomic representations, enabling agents to reason about
    specific aspects of the environment and how they change.

**Example:**

::: tcolorbox
Consider again the self-driving taxi. Instead of just the city name, we
can use a factored representation to include more relevant information
about the taxi's state:

-   **Variables:**

    -   `CurrentCity`: Possible values: {`Arad`, `Bucharest`, \...,
        `Zerind`}

    -   `FuelLevel`: Possible values: Continuous range, e.g., $[0, 100]$
        liters, or discrete levels, e.g., {`Empty`, `Low`, `Medium`,
        `Full`}

    -   `PassengerPresent`: Possible values: {`True`, `False`}

-   **State Example:** A state could be represented as:
    $\{\texttt{CurrentCity}=\texttt{Sibiu}, \texttt{FuelLevel}=35, \texttt{PassengerPresent}=\texttt{False}\}$.

With a factored representation, we can now describe the taxi's state in
terms of its city, fuel level, and whether it has a passenger. This
allows for more nuanced decision-making. For instance, the agent can now
reason about needing to refuel based on the `FuelLevel` variable, or
prioritize actions based on whether `PassengerPresent` is true. Factored
representations are widely used in AI because they strike a balance
between simplicity and expressiveness, suitable for many problem
domains.
:::

### Structured World Representation

::: tcolorbox
A **structured world representation** is the most complex and expressive
level, going beyond simple variables and values to represent states in
terms of **objects**, their **properties**, and **relationships**
between these objects. This level of representation is essential for
dealing with environments that are inherently relational and
object-centric.
:::

Key features of structured representations are:

-   **Objects and Relations**: The world is seen as composed of distinct
    objects and the relationships that hold between them.

-   **Complex Data Structures**: States are described using complex data
    structures such as lists, trees, graphs, or knowledge bases to
    capture objects and their interconnections.

-   **Rich Semantics**: Structured representations can capture rich
    semantic information about the environment, allowing for more
    sophisticated reasoning and understanding.

-   **Reasoning about Entities**: Agents can reason about individual
    objects, their categories, and how they interact, enabling more
    flexible and general problem-solving.

**Example:**

::: tcolorbox
Consider a more detailed model of a traffic scenario for a self-driving
car. A structured representation could describe the scene as follows:

-   **Objects:**

    -   `Taxi-123`: An object representing our taxi.

    -   `Car-456`: Another car object.

    -   `TrafficLight-Red-Zone-A`: A traffic light object.

    -   `Road-Highway-5`: A road segment object.

-   **Properties of Objects:**

    -   `Taxi-123.Location`: Value: (x, y) coordinates on a map.

    -   `Taxi-123.Speed`: Value: 60 km/h.

    -   `TrafficLight-Red-Zone-A.Color`: Value: `Red`.

    -   `Road-Highway-5.Lanes`: Value: 3.

-   **Relationships between Objects:**

    -   `Taxi-123` `is_on` `Road-Highway-5`.

    -   `Car-456` `is_ahead_of` `Taxi-123`.

    -   `TrafficLight-Red-Zone-A` `controls` `Road-Highway-5` `at`
        `Intersection-X`.

This structured representation uses objects (`Taxi-123`, `Car-456`,
etc.), properties (`Location`, `Speed`, `Color`, etc.), and relations
(`is_on`, `is_ahead_of`, `controls`) to describe the traffic scene. This
rich representation allows the agent to perform complex reasoning, such
as: \"If `TrafficLight-Red-Zone-A.Color` is `Red` and
`TrafficLight-Red-Zone-A` `controls` `Road-Highway-5` and `Taxi-123`
`is_on` `Road-Highway-5`, then `Taxi-123` should stop.\"

**Knowledge Graphs** and **Semantic Networks** are examples of
formalisms used to implement structured world representations. They are
particularly useful in domains requiring reasoning about complex
relationships, such as natural language understanding, scene
understanding, and common-sense reasoning. Structured representations
offer the highest level of expressiveness and are necessary for agents
operating in complex, real-world environments, albeit at the cost of
increased computational complexity in processing and reasoning.
:::

# Search Problems in AI

## Introduction to Search Problem Solving Agents

::: tcolorbox
**Search problem-solving agents** are a fundamental type of intelligent
agent in AI. These agents are designed to achieve their goals by
**searching** through a space of possible action sequences to find a
path that leads to a desired **goal state**. The process of searching
involves exploring different sequences of actions, evaluating their
outcomes, and selecting a sequence that effectively achieves the agent's
objective.
:::

This section introduces the core concepts of search problems in AI,
using illustrative examples to clarify these ideas.

## Illustrative Example: The Pac-Man Problem

The classic game of **Pac-Man** provides an intuitive and engaging
example to illustrate various agent approaches and the critical concept
of **optimal path planning**. By considering simplified versions of
Pac-Man, we can effectively demonstrate different agent strategies,
ranging from simple reactive behaviors to sophisticated planning
algorithms.

### Simple Reflex Agent Approach for Pac-Man

#### Implementing \"Eat Adjacent Pellet\" Rule

::: tcolorbox
A basic intelligent behavior for a Pac-Man agent can be implemented
using a **simple reflex rule**: \"If there is a pellet adjacent to
Pac-Man, eat it.\" This rule drives the agent to consume pellets
whenever they are immediately available.

**Behavior:** The agent continuously checks its immediate surroundings.
If a pellet is detected in any adjacent location (North, East, South,
West), the agent takes the action to eat that pellet.

**Intelligence Level:** This strategy exhibits a rudimentary form of
intelligence by enabling the agent to interact with and modify its
environment to achieve a basic objective (eating pellets).

**Efficiency:** While this rule ensures that Pac-Man eats pellets when
close by, it is not efficient for maximizing the total number of pellets
eaten or for achieving high scores in more complex scenarios. The agent
may get stuck in local areas or miss pellets that are slightly further
away.
:::

::: center
:::

Demonstrations of such an agent would show Pac-Man effectively eating
pellets in its immediate vicinity but potentially wandering aimlessly or
missing opportunities to eat more pellets efficiently.

#### Implementing \"Nearest Pellet\" Rule

::: tcolorbox
To improve upon the \"eat adjacent pellet\" strategy, we can introduce a
slightly more sophisticated rule: \"Find the nearest pellet and move
towards it.\" This rule enables the agent to seek out pellets that are
not just immediately adjacent but also those that are within a short
range.

**Behavior:** The agent scans its environment to locate all available
pellets. It then calculates the distance to each pellet and identifies
the nearest one. The agent then plans and executes a sequence of moves
to reduce the distance to the nearest pellet, effectively moving towards
it.

**Improved Intelligence:** This strategy is more intelligent than the
adjacent pellet rule because it allows the agent to actively seek out
pellets, not just react to those that are immediately present. It
demonstrates a basic form of goal-directed behavior.

**Score Improvement:** Demonstrations of this agent typically show
improved performance, achieving scores like **907** in certain
simplified Pac-Man scenarios. This is because the agent is more
proactive in pellet collection.

**Suboptimality:** Despite the improvement, this strategy is still **not
optimal**. The agent makes greedy decisions by always going for the
nearest pellet, which may lead to suboptimal paths in the long run. For
instance, it might enter a tunnel to eat a nearby pellet and then have
to backtrack, wasting moves that could have been used to collect more
pellets elsewhere.
:::

::: center
:::

### Optimal Path Planning Strategy for Pac-Man

::: tcolorbox
To achieve the best possible performance in Pac-Man, the agent needs to
employ **optimal path planning**. This involves calculating the most
efficient path to eat all pellets while minimizing the total distance
traveled. This problem is analogous to the classic **Traveling
Salesperson Problem (TSP)**, adapted for the Pac-Man context.

**Behavior:** The agent first analyzes the entire game layout to
identify the locations of all pellets. It then computes an optimal or
near-optimal path that visits all pellet locations in a sequence that
minimizes the total number of moves (or total distance). This
computation often involves sophisticated search algorithms.

**Planning Overhead:** Optimal path planning typically requires
significant **computation upfront**. The agent needs to spend time
\"thinking\" and planning before making its first move. This is in
contrast to reflex agents that react immediately.

**Optimal Score:** By following an optimal path, the agent achieves the
**highest possible score** for a given starting configuration.
Demonstrations show scores like **914**, which is better than the
nearest pellet strategy.

**Efficiency in the Long Run:** Although there is an initial planning
cost, the optimal path strategy is ultimately more efficient in terms of
moves and score maximization. It avoids wasted movements and ensures
that all pellets are collected in the most economical way.

**Complexity:** Implementing optimal path planning requires more complex
algorithms compared to simple reflex rules. Techniques like A\* search,
dynamic programming, or TSP solvers might be employed.
:::

::: center
:::

The Pac-Man example effectively illustrates the spectrum of agent
intelligence and problem-solving strategies, from simple reactive rules
to complex planning algorithms aimed at optimality. It highlights the
trade-off between computational cost and solution quality, and sets the
stage for a more formal discussion of search problems in AI.

## Formal Definition of Search Problems

::: tcolorbox
To systematically approach problem-solving in AI, we need a formal way
to define a **search problem**. A search problem is characterized by
specifying: the environment's states, the agent's possible actions, and
the criteria for a successful solution. Formally, a search problem can
be defined using six key components.
:::

While the formal definition is rooted in set theory for abstraction, it
can be intuitively understood using graph concepts, which we will
explore later.

### Defining the State Space

::: tcolorbox
The **state space** $S$ is the fundamental component of a search
problem. It is defined as the set of all possible **states** that the
environment can be in. A state represents a configuration of the world.
The level of detail in defining a state depends on the problem and the
desired abstraction.
:::

-   **Example (Pac-Man):**

    ::: tcolorbox
    For a simplified Pac-Man game, a state could be defined by:

    -   Pac-Man's position $(x, y)$ on the grid.

    -   The set of locations of remaining pellets.

    Thus, a state $s \in S$ might be represented as $s = ((x, y), P)$,
    where $(x, y)$ is Pac-Man's coordinates and $P$ is the set of pellet
    coordinates.
    :::

-   **Example (Simplified 3x3 Pac-Man):**

    ::: tcolorbox
    In an even more simplified 3x3 grid Pac-Man, states could be
    enumerated. For instance, if we only consider Pac-Man's position and
    whether pellets are eaten, we can visualize different states.
    :::

::: center
:::

The state space can be finite or infinite, discrete or continuous,
depending on the problem. For many AI problems, especially in simplified
environments, the state space is often treated as discrete and finite to
enable search algorithms.

### Specifying the Initial State

::: tcolorbox
The **initial state** $s_{0}$ is the state in which the agent starts. It
is a specific state within the state space $S$. The search process
begins from this initial state.
:::

-   **Example (Pac-Man):**

    ::: tcolorbox
    The initial state for a Pac-Man game is the configuration at the
    very beginning of the game, including:

    -   Pac-Man's starting position.

    -   The initial locations of all pellets.

    -   Positions of ghosts (if relevant to the search problem
        formulation).

    For instance, in our simplified 3x3 Pac-Man example, **State 1**
    from the figure above could be designated as the initial state.
    :::

Identifying the initial state is straightforward as it is given by the
problem setup. It serves as the entry point for any search algorithm.

### Defining Possible Actions

::: tcolorbox
**Actions** $A(s)$ represent the set of possible actions that the agent
can execute when it is in state $s$. The available actions depend on the
current state and the environment's rules.
:::

-   **Example (Pac-Man):**

    ::: tcolorbox
    In Pac-Man, the actions are typically:

    -   `Move North`

    -   `Move East`

    -   `Move South`

    -   `Move West`

    So,
    $A(s) = \{\texttt{North}, \texttt{East}, \texttt{South}, \texttt{West}\}$
    for most states $s$. However, if Pac-Man is next to a wall in a
    certain direction, the corresponding move might not be possible or
    might have no effect, effectively reducing the set of available
    actions in such states. For example, if in state $s$, moving North
    leads into a wall, then effectively, the action `North` might be
    invalid or result in staying in the same state.
    :::

The set of actions defines the agent's capabilities to interact with and
change the environment.

### Defining the Transition Model

::: tcolorbox
The **transition model** $T(s, a)$ describes the outcome of performing
action $a$ in state $s$. It specifies the state that the agent will
transition to after executing action $a$ in state $s$.
:::

-   **Definition:** The transition model $T: S \times A \rightarrow S$
    is a function that maps a state $s$ and an action $a \in A(s)$ to
    the resulting state $s' = T(s, a)$.

-   **Deterministic Environments:** In deterministic environments, the
    transition model is a function that returns a **single, unique next
    state**. For example, in Pac-Man, if the action `Move North` in
    state $s$ is valid, it will always lead to the same next state $s'$.
    Thus, $T(s, \texttt{North}) = s'$.

-   **Non-deterministic Environments:** In non-deterministic
    environments, the transition model might return a **set of possible
    next states** or a probability distribution over possible next
    states. For simplicity, in many introductory search problem
    formulations, environments are assumed to be deterministic.

-   **Example (Pac-Man - Deterministic):**

    ::: tcolorbox
    If in state $s_1$, Pac-Man is at position (1,1) and there is no wall
    to the North, then $T(s_1, \texttt{North}) = s_2$, where $s_2$ is
    the state with Pac-Man at position (1,2) and pellet status updated
    if a pellet was eaten at (1,2).
    :::

The transition model is crucial for search algorithms as it allows them
to explore the consequences of actions and predict future states.

### Defining the Goal Test

::: tcolorbox
The **goal test** $G(s)$ is a function that determines whether a given
state $s$ is a **goal state**. A goal state is a desirable state that
the agent is trying to reach.
:::

-   **Definition:** The goal test
    $G: S \rightarrow \{\texttt{true}, \texttt{false}\}$ is a Boolean
    function that returns `true` if state $s$ is a goal state, and
    `false` otherwise.

-   **Example (Pac-Man):**

    ::: tcolorbox
    For Pac-Man, a goal state is typically defined as a state in which
    **all pellets have been eaten**. Thus, $G(s) = \texttt{true}$ if in
    state $s$, there are no pellets remaining on the game board, and
    $G(s) = \texttt{false}$ otherwise. In our 3x3 example, **State 3**
    could be a goal state if it represents the configuration where all
    pellets have been eaten.
    :::

-   **Multiple Goal States:** There can be one or more goal states in a
    search problem. The goal test function simply identifies these
    states.

The goal test defines the success condition for the search problem. The
agent's objective is to find a path to any state for which the goal test
returns `true`.

### Defining the Cost Function

::: tcolorbox
The **cost function** $C(s, a, s')$ assigns a numerical cost to taking
action $a$ in state $s$ and transitioning to state $s'$. The cost
typically represents a measure of resources consumed, time taken, or
penalty incurred.
:::

-   **Definition:** The cost function
    $C: S \times A \times S \rightarrow \mathbb{R}_{\ge 0}$ assigns a
    non-negative cost to each transition. $C(s, a, s')$ is the cost of
    moving from state $s$ to state $s'$ by action $a$, where
    $s' = T(s, a)$.

-   **Path Cost:** The cost of a path (sequence of actions) is the sum
    of the costs of the individual transitions along the path.

-   **Example (Pac-Man):**

    ::: tcolorbox
    For Pac-Man, a common cost function is:

    -   Cost of 1 for each move: $C(s, a, s') = 1$ for any move action
        (North, East, South, West). This represents a uniform cost per
        move, encouraging the agent to find solutions with fewer moves.

    -   Reward for eating a pellet: When Pac-Man eats a pellet by moving
        to a new state $s'$, we can assign a negative cost (reward),
        e.g., $C(s, a, s') = -10$ if action $a$ results in eating a
        pellet in state $s'$. This incentivizes the agent to eat
        pellets.

    -   Penalty for other undesirable outcomes (if any).
    :::

    The cost function guides the search towards optimal solutions, where
    optimality is defined in terms of minimizing the total path cost.

### Solutions and Optimal Solutions in Search Problems

::: tcolorbox
With these six components defined, we can now define what constitutes a
solution and an optimal solution to a search problem.
:::

-   **Solution:**

    ::: tcolorbox
    A **solution** to a search problem is a **sequence of actions**
    $[a_1, a_2, ..., a_n]$ that, when executed starting from the initial
    state $s_0$, leads to a goal state $s_g$ such that
    $G(s_g) = \texttt{true}$. That is, applying the sequence of actions
    transforms $s_0$ into a state $s_g$ that satisfies the goal test.
    :::

-   **Optimal Solution:**

    ::: tcolorbox
    An **optimal solution** is a solution that has the **lowest path
    cost** among all possible solutions. The path cost is the sum of the
    costs of all actions in the sequence:
    $\sum_{i=1}^{n} C(s_{i-1}, a_i, s_i)$, where $s_i = T(s_{i-1}, a_i)$
    and $s_0$ is the initial state, $s_n = s_g$ is a goal state.
    :::

-   **Objective:** The primary objective in solving a search problem is
    often to find an **optimal solution** -- a sequence of actions that
    not only reaches a goal state but does so with the minimum possible
    cost. In some cases, finding any solution (not necessarily optimal)
    is sufficient.

The formal definition of search problems provides a structured framework
for analyzing and solving a wide range of AI problems. By specifying the
state space, initial state, actions, transition model, goal test, and
cost function, we can use various search algorithms to find solutions
and optimal solutions.

## Example Application: Route Finding in Romania

A classic example to illustrate search problems is finding a route
between cities, such as finding a path from Arad to Bucharest in
Romania. This example is both intuitive and practically relevant,
demonstrating how search problem formulation can be applied to
real-world scenarios.

### Mapping States, Actions, Goal, and Costs

To formulate the Romania route finding problem as a search problem, we
need to define its components based on the given map and objective.

-   **States:** The states in this problem are the **cities in
    Romania**. Each city represents a distinct location that the agent
    (e.g., a traveler or a navigation system) can be in.

    -   **Example States:** Arad, Bucharest, Sibiu, Timisoara, etc. (all
        cities on the map).

-   **Initial State:** The initial state is the starting city, which is
    given as **Arad**.

-   **Actions:** The actions available to the agent in each city are to
    **drive to an adjacent city**. Adjacency is defined by the roads
    connecting the cities on the map.

    -   **Example Actions (from Arad):**

        -   `Go to Sibiu`

        -   `Go to Timisoara`

        -   `Go to Zerind`

-   **Transition Model:** The transition model is **deterministic**. If
    the agent takes an action \"Go to City X\" from \"City Y,\" it will
    reliably end up in \"City X.\" There is no uncertainty in the
    outcome of driving between cities in this simplified model.

-   **Goal Test:** The goal is to reach **Bucharest**. Therefore, the
    goal test $G(s)$ is true if $s$ is the city Bucharest, and false
    otherwise.

-   **Cost Function:** The cost of each action (driving from one city to
    another) is the **distance in kilometers** between the cities, as
    indicated on the map.

    -   **Example Costs:**

        -   $C(\texttt{Arad}, \texttt{Go to Sibiu}, \texttt{Sibiu}) = 140$
            km.

        -   $C(\texttt{Arad}, \texttt{Go to Timisoara}, \texttt{Timisoara}) = 118$
            km.

        -   $C(\texttt{Sibiu}, \texttt{Go to Bucharest}, \texttt{Bucharest}) = 278$
            km

The objective is to find a sequence of actions (driving from city to
city) that starts in Arad, ends in Bucharest, and minimizes the total
cost, which is the total distance traveled. An optimal solution would be
the shortest path from Arad to Bucharest.

-   **Optimal Path:** The lecture notes suggest that the shortest path
    would likely be one of the routes that go relatively directly
    towards Bucharest, avoiding unnecessary detours. For example, a path
    through Sibiu or Pitesti might be considered.

-   **Suboptimal Paths:** Less intelligent agents or suboptimal
    strategies might take longer routes, such as going through more
    distant cities or getting stuck in cycles, thus increasing the total
    distance and cost. For instance, a route that goes from Arad to
    Zerind to Oradea and then loops back would be inefficient and
    suboptimal for reaching Bucharest.

This route-finding example clearly illustrates how real-world problems
can be abstracted and formulated as search problems, enabling the use of
search algorithms to find efficient solutions.

## Example Application: Vacuum Cleaner World

The **vacuum cleaner world** is a simple but illustrative environment
often used in AI to demonstrate agent concepts and search problems.
Consider a simplified version with two locations, A and B, where the
vacuum cleaner can be, and each location can be either dirty or clean.

### Defining States, Actions, and Goal

To formulate the vacuum cleaner problem as a search problem, we need to
define its states, actions, goal, and costs.

-   **States:** In this 2-location vacuum world, a state is defined by:

    -   The **location** of the vacuum cleaner: Location A or Location
        B.

    -   The **dirt status** of Location A: Dirty or Clean.

    -   The **dirt status** of Location B: Dirty or Clean.

    Combining these, we get $2 \times 2 \times 2 = 8$ possible states.
    We can enumerate them as:

    -   State 1: (Location A, A=Dirty, B=Dirty)

    -   State 2: (Location A, A=Clean, B=Dirty)

    -   State 3: (Location A, A=Dirty, B=Clean)

    -   State 4: (Location A, A=Clean, B=Clean) - Goal State

    -   State 5: (Location B, A=Dirty, B=Dirty)

    -   State 6: (Location B, A=Clean, B=Dirty)

    -   State 7: (Location B, A=Dirty, B=Clean)

    -   State 8: (Location B, B=Clean, B=Clean) - Goal State

    Note that **states are distinct from positions**. For example, State
    1 and State 5 both have dirt in both locations, but the vacuum
    cleaner's position is different.

-   **Initial State:** We can assume an example initial state, say
    **State 1: (Location A, A=Dirty, B=Dirty)**.

-   **Actions:** The actions available to the vacuum cleaner are:

    -   `Right`: Move to location B (if currently at A).

    -   `Left`: Move to location A (if currently at B).

    -   `Suck`: Clean dirt in the current location.

-   **Goal Test:** The goal is to have both locations clean. Thus, any
    state where both Location A and Location B are clean is a goal
    state. In our enumerated states, **State 4** and **State 8** are
    goal states.

-   **Cost Function:** We can assign a cost of **1 for each action**
    (move or suck). This implies that we want to find a solution with
    the minimum number of actions.

### Analyzing Example Solutions and Optimality

::: tcolorbox
Let's consider example solutions and analyze their optimality based on
the defined cost function. Starting from the initial **State 1:
(Location A, A=Dirty, B=Dirty)**:

-   **Solution 1 (Optimal): Suck, Right, Suck (SRS)**

    1.  **Suck** in State 1: Transitions to State 3: (Location A,
        A=Clean, B=Dirty). Cost = 1.

    2.  **Right** in State 3: Transitions to State 7: (Location B,
        A=Clean, B=Dirty). Cost = 1.

    3.  **Suck** in State 7: Transitions to State 8: (Location B,
        A=Clean, B=Clean) - Goal State. Cost = 1.

    Total cost of Solution 1 = $1 + 1 + 1 = 3$. This is an **optimal
    solution** because it reaches a goal state in the minimum number of
    actions.

-   **Solution 2 (Suboptimal): Right, Suck, Left, Suck**

    1.  **Right** in State 1: Transitions to State 5: (Location B,
        A=Dirty, B=Dirty). Cost = 1.

    2.  **Suck** in State 5: Transitions to State 6: (Location B,
        A=Clean, B=Dirty). Cost = 1.

    3.  **Left** in State 6: Transitions to State 2: (Location A,
        A=Clean, B=Dirty). Cost = 1.

    4.  **Suck** in State 2: Transitions to State 4: (Location A,
        A=Clean, B=Clean) - Goal State. Cost = 1.

    Total cost of Solution 2 = $1 + 1 + 1 + 1 = 4$. This is a
    **suboptimal solution** as it reaches a goal state but with a higher
    cost (more actions) than Solution 1.
:::

We can also consider scenarios where the goal is refined. For instance,
if the goal is to have both locations clean **and** the vacuum cleaner
to end up in Location A. In this case, **State 4** becomes the only goal
state: **(Location A, A=Clean, B=Clean)**.

-   **Revised Goal:** Reach State 4: (Location A, A=Clean, B=Clean).

-   **Optimal Solution to Revised Goal:** For the revised goal, Solution
    1 (SRS) is no longer optimal because it ends in State 8 (Location B,
    A=Clean, B=Clean). To reach State 4, we can extend Solution 2:
    **Right, Suck, Left, Suck, Right**.

    1.  Actions Right, Suck, Left, Suck lead to State 4 (as in Solution
        2). Cost = 4.

    2.  **Right** in State 4: Transitions to State 4 (remains in State 4
        as it is already in Location A and moving right from A might
        keep it in A or be defined to wrap around, depending on
        environment definition, but for simplicity, assume it stays in
        A). Cost = 1.

    Revised Solution Cost = $4 + 1 = 5$. Another optimal solution for
    the revised goal, ending in Location A, could be: **Suck, Right,
    Suck, Left**.

    1.  Actions Suck, Right, Suck lead to State 8 (as in Solution 1).
        Cost = 3.

    2.  **Left** in State 8: Transitions to State 4: (Location A,
        A=Clean, B=Clean) - Goal State. Cost = 1.

    Revised Optimal Solution Cost = $3 + 1 = 4$. Thus, **Suck, Right,
    Suck, Left** is an optimal solution for the revised goal, with a
    cost of 4.

::: tcolorbox
The vacuum cleaner world example, despite its simplicity, effectively
demonstrates the formulation of search problems, the concept of
optimality, and how changes in goals can affect optimal solutions.
:::

## Examples of Puzzle Games as Search Problems

Puzzle games are a rich source of examples for search problems in AI.
They often have clear goals, well-defined states and actions, and
varying levels of complexity, making them ideal for studying search
algorithms.

### The 8-Puzzle and 15-Puzzle Challenges

::: tcolorbox
The **8-puzzle** and its more complex variant, the **15-puzzle**, are
classic examples of rearrangement puzzles that can be formulated as
search problems. The puzzle consists of a numbered square grid of tiles
with one tile missing (the blank space). The goal is to rearrange the
tiles from a given **initial configuration** to a specific **goal
configuration** by sliding tiles into the blank space.
:::

-   **States:** A state in the 8-puzzle or 15-puzzle is defined by the
    **configuration of tiles** on the grid. This can be represented as a
    2D array or a sequence of tile numbers.

-   **Initial State:** A given starting arrangement of tiles.

-   **Goal State:** A specific target arrangement, typically with tiles
    in numerical order and the blank in the last position.

-   **Actions:** The actions are to slide a tile adjacent to the blank
    space into the blank space. Possible actions are:

    -   `Move Blank Up` (slide tile below blank up)

    -   `Move Blank Down` (slide tile above blank down)

    -   `Move Blank Left` (slide tile to the right of blank left)

    -   `Move Blank Right` (slide tile to the left of blank right)

    Not all actions are possible in every state (e.g., if the blank is
    at the top edge, `Move Blank Up` is not possible).

-   **Transition Model:** Deterministic. Sliding a tile changes the tile
    configuration in a predictable way.

-   **Goal Test:** Check if the current tile configuration matches the
    goal configuration.

-   **Cost Function:** Typically, a uniform cost of 1 per move is used,
    aiming to find the solution with the fewest moves.

::: center
:::

### State Space Explosion in Puzzle Games

::: tcolorbox
Puzzle games like the 8-puzzle and 15-puzzle vividly illustrate the
problem of **state space explosion**. The number of possible states
grows factorially with the size of the puzzle, leading to immense search
spaces.
:::

-   **8-puzzle:** The 8-puzzle has $9!/2 = 181,440$ reachable states.
    The factor of 1/2 comes from the fact that only half of the possible
    permutations are reachable from any given starting state due to
    parity constraints.

-   **15-puzzle:** The 15-puzzle, with a 4x4 grid, has a staggering
    $16!/2 \approx 10^{13}$ (over 10 trillion) reachable states.

::: tcolorbox
This vast state space makes it computationally prohibitive to explore
all possible states exhaustively, especially for the 15-puzzle and
larger versions. Efficient search algorithms and heuristics are
essential to solve these puzzles in a reasonable amount of time.
:::

## Example Application: Tic-Tac-Toe (Tris) Game

::: tcolorbox
**Tic-Tac-Toe** (also known as Tris or Noughts and Crosses) is another
classic example of a search problem, but it introduces the element of
**game playing** with two players, typically denoted as X and O.
:::

-   **States:** A state in Tic-Tac-Toe is defined by the configuration
    of the 3x3 grid, indicating which cells are empty, contain an 'X',
    or contain an 'O'. The game state also implicitly includes whose
    turn it is (X or O).

-   **Initial State:** An empty 3x3 board.

-   **Actions:** An action consists of a player (X or O) placing their
    mark in an empty cell on the board. The available actions depend on
    the current state (only empty cells can be chosen).

-   **Transition Model:** Deterministic. Placing a mark in an empty cell
    results in that cell being filled with the mark, and the turn passes
    to the other player.

-   **Goal Test:** The game ends when:

    -   One player gets three of their marks in a row (horizontally,
        vertically, or diagonally) - this is a winning goal state.

    -   All cells are filled, and no player has won - this is a draw (a
        terminal, but not winning, goal state).

-   **Cost Function:** In Tic-Tac-Toe, often no explicit cost function
    is used in the same way as path cost minimization problems. Instead,
    the focus is on game outcome (win, lose, or draw). However, in game
    theory formulations, utility or reward functions are defined based
    on game outcomes (e.g., +1 for a win, -1 for a loss, 0 for a draw
    for player X, and vice versa for player O).

::: tcolorbox
The lecture notes mention visualizing a **game tree** for Tic-Tac-Toe.
While it is often referred to as a tree, it is more accurately a graph
because the same board configuration can be reached through different
sequences of moves (transposition). However, for search purposes, it is
often explored as a tree structure.
:::

## Limitations of the State Space Approach for Complex Problems

### Addressing State Space Explosion

::: tcolorbox
The state space approach, while conceptually powerful and widely
applicable, encounters significant limitations when applied to **complex
problems** characterized by **state space explosion**. As we have seen
with the 15-puzzle and even more dramatically with games like chess or
Go, the number of possible states can become astronomically large.
:::

-   **Computational Intractability:**

    ::: tcolorbox
    For problems with very large state spaces, it becomes
    computationally infeasible to:

    -   **Enumerate all states:** Simply listing or representing all
        possible states becomes impossible due to memory and time
        constraints.

    -   **Explore the entire state space:** Exhaustive search algorithms
        that explore every possible path become impractical because the
        search time grows exponentially with the size of the state
        space.
    :::

-   **Examples of State Space Explosion:**

    -   **15-puzzle:** $\approx 10^{13}$ states.

    -   **Chess:** Estimated $10^{40}$ states in a typical game, and
        $10^{120}$ possible games.

    -   **Go:** Even larger state space than Chess, estimated $10^{170}$
        states.

::: tcolorbox
This state space explosion necessitates the use of more **efficient
search algorithms** and **abstraction techniques** to manage complexity
and make problem-solving tractable.
:::

Techniques to handle state space explosion include:

-   **Heuristic Search Algorithms:** Algorithms like A\* search use
    heuristic functions to guide the search towards promising paths,
    significantly reducing the search space explored compared to
    uninformed search methods.

-   **Abstraction and Problem Decomposition:** Simplifying the problem
    by abstracting away irrelevant details or decomposing it into
    smaller, more manageable subproblems.

-   **Local Search and Optimization Algorithms:** For some problems,
    finding a globally optimal solution is not necessary or feasible.
    Local search algorithms aim to find good, locally optimal solutions
    in a more efficient manner.

-   **Machine Learning Techniques:** In very complex domains, machine
    learning, particularly reinforcement learning, can be used to learn
    effective strategies and policies without explicitly searching the
    entire state space.

## Abstraction and Modeling in Problem Solving Context

### The Role of Models and Abstraction vs. Reality

::: tcolorbox
It is crucial to remember that search problems and state space
representations are **abstractions** of real-world problems. When we
formulate a problem as a search problem, we are creating a **model** of
reality, focusing on the aspects that are relevant to problem-solving
while ignoring others.
:::

-   **Models are Simplifications:** By definition, models are simplified
    representations of reality. They are not the reality itself but
    rather tools to help us understand and solve problems. As the famous
    statistician George Box noted, *\"All models are wrong, but some are
    useful.\"*

-   **Abstraction is Necessary:** Abstraction is essential to make
    complex problems tractable. By choosing an appropriate level of
    abstraction, we can represent a problem in a way that is amenable to
    algorithmic solution. However, abstraction always involves
    trade-offs, and it is important to be aware of what is being
    simplified or ignored.

-   **Danger of Confusing Model with Reality:** It is crucial not to
    confuse the model with reality. The model is a tool, and its
    usefulness depends on how well it captures the essential aspects of
    the real problem. As humorously put by Arthur Bloch, *\"Confusing
    the model with reality is like going to a restaurant and eating the
    menu.\"* The menu (model) describes the food (reality), but it is
    not the food itself.

::: tcolorbox
Therefore, when applying search problem formulations in AI, it is vital
to:

-   **Choose the Right Level of Abstraction:** Select a level of detail
    in state representation and action modeling that is appropriate for
    the problem's complexity and the available computational resources.

-   **Understand Model Limitations:** Be aware of the assumptions and
    simplifications inherent in the model and their potential impact on
    the solutions found.

-   **Iterate and Refine Models:** Problem formulation is often an
    iterative process. Initial models may need to be refined or revised
    as we gain a better understanding of the problem and its
    complexities.
:::

# State Space Graphs and Search Trees

To effectively visualize and solve search problems, two crucial
representational tools are employed: **State Space Graphs** and **Search
Trees**. These representations provide frameworks for understanding the
structure of a problem and for systematically exploring potential
solutions.

## State Space Graphs: A Visual Representation

::: tcolorbox
The **state space graph** is a graphical construct that provides a
visual and intuitive representation of a search problem. It captures the
essential elements of the problem in a structured diagram, facilitating
understanding of the problem's state space and transitions.
:::

### Nodes Representing States

::: tcolorbox
In a state space graph, each **node** corresponds to a unique **state**
within the problem's state space. Nodes are abstract representations of
the possible configurations of the world that are relevant to the
problem at hand. Each node encapsulates all the necessary information to
define a particular situation in the environment.
:::

### Arcs Representing Actions and Transitions

::: tcolorbox
**Arcs**, or directed edges, in the state space graph represent the
**actions** that an agent can take to transition from one state to
another. A directed arc from a node representing state A to a node
representing state B signifies that it is possible to move from state A
to state B by executing a specific action.
:::

These arcs are typically:

-   **Directed**: Indicating the direction of the transition from a
    preceding state to a succeeding state.

-   **Labeled**: Often labeled with the **action name** that causes the
    transition, providing clarity on what action leads from one state to
    the next.

-   **Weighted**: Can be weighted with the **cost of the action**,
    representing the numerical cost associated with performing that
    action and transitioning between the states.

### Encoding Costs and Identifying Goal States

::: tcolorbox
The **costs** associated with actions, if applicable, are typically
encoded as weights on the arcs, allowing for the representation of path
costs and optimal solutions. **Goal states**, which are the desired end
configurations, are identified within the state space graph as a
specific subset of **nodes**. These goal nodes are often visually
distinguished, for example, by using double circles or color
highlighting, to clearly mark the successful termination points of a
search.
:::

### Solutions as Paths within the State Space Graph

::: tcolorbox
A **solution** to a search problem, within the context of a state space
graph, is represented as a **path** from the node corresponding to the
**initial state** to a node representing a **goal state**. This path is
a sequence of connected arcs, starting from the initial node and ending
at a goal node.
:::

-   **Path Cost**: The **cost of a path** is calculated by summing the
    costs of all the arcs that constitute the path. If costs are uniform
    (e.g., cost of 1 for each action), the path cost is simply the
    number of arcs in the path.

-   **Optimal Solution**: An **optimal solution** corresponds to a path
    with the **lowest total cost** among all possible paths from the
    initial state to any goal state. Finding an optimal solution is
    often the objective of search algorithms.

## Search Trees: Exploring Solution Paths

::: tcolorbox
The **search tree** is another representation, derived from the state
space graph, used to explore possible solution paths. It is particularly
useful for systematically searching for solutions.
:::

### Constructing Search Trees from State Space Graphs

::: tcolorbox
A search tree is constructed starting from the initial state node of the
state space graph as the root. For each node in the tree, branches are
created for each possible action, leading to child nodes representing
the resulting states. Unlike state space graphs, search trees can have
multiple nodes representing the same state if that state is reached
through different paths.
:::

### Relating Paths in Search Trees to State Space Graph Paths

::: tcolorbox
Each path from the root to a node in the search tree corresponds to a
path in the state space graph from the initial state to the state
represented by that node. However, a single state in the state space
graph can be represented by multiple nodes in the search tree,
especially if there are cycles in the state space graph.
:::

### Search Tree Example and Optimal Path Identification

::: tcolorbox
Example comparing a state space graph and its corresponding search tree.
The search tree expands paths from the start node, showing different
possible sequences of actions. The optimal path in the state space graph
is highlighted, and its corresponding path is shown in the search tree.
The search tree explicitly shows all explored paths from the initial
state.
:::

### Introduction to Efficiency Advantages of Search Trees

::: tcolorbox
Search trees, despite potentially being larger than state space graphs
(due to repeated states), offer advantages for search algorithms. They
allow for systematic exploration of paths and can be pruned to avoid
redundant or suboptimal paths. Search trees facilitate algorithms that
can efficiently find solutions without needing to explicitly construct
the entire state space graph in memory. Algorithms can explore branches
of the search tree and backtrack when necessary, potentially saving
computational resources.
:::
