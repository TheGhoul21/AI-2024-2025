Introduction

Building upon the foundational search concepts discussed in previous lectures, we will now delve into advanced techniques that enhance the efficiency and applicability of search in more realistic and challenging scenarios.

  • Informed Search: We will explore how to leverage domain-specific knowledge to guide the search process more effectively. This involves the use of heuristic functions to estimate the proximity to a goal, allowing for more directed and efficient search strategies, such as Greedy Best-First Search and the A* algorithm.

  • Search in Non-Deterministic Environments: We will move beyond the assumption of deterministic action outcomes and consider environments where actions can have multiple possible results. Recap of Search Fundamentals

Before delving into advanced search techniques, it is crucial to revisit the foundational concepts of search algorithms. These fundamentals provide the necessary context for understanding the more sophisticated methods we will explore.

Problem Solving Agents and Search

At the heart of intelligent behavior lies the ability to solve problems. In artificial intelligence, we often model problem-solving through the concept of agents that navigate through different states to achieve a goal. These problem-solving agents operate by searching for a sequence of actions that lead from an initial state to a desired goal state. The process of finding this sequence is known as search. Search algorithms provide systematic methods to explore the space of possible states and actions to find a solution.

Formulating Search Problems

To apply search algorithms, we must first formulate the problem in a structured manner. A search problem is defined by the following components, which collectively describe the environment and the objective:

  • State Space: This is the set of all possible configurations or situations in which the agent can be. Each state represents a distinct situation in the problem domain. For example, in route-finding, states are cities; in a puzzle, states are configurations of the puzzle pieces.

  • Initial State: The starting point of the problem. It is the state from which the agent begins its search for a solution. In a navigation problem, this could be the agent’s current location.

  • Actions: These are the operations that the agent can perform in each state to transition to another state. Actions are context-dependent; the available actions vary from state to state. For instance, from a city, the actions might be to travel to adjacent cities.

  • Result Function (Transition Model): This function defines the outcome of performing an action in a given state. It specifies the state that the agent will transition to after executing an action. In deterministic environments, the result is a single, predictable state.

  • Goal Test: A condition that determines whether a given state is a goal state. This test checks if the current state satisfies the problem’s objective. There might be one or more goal states. For example, in route-finding, the goal is to be in the destination city.

  • Cost Function (Path Cost): Assigns a numerical cost to each action. This cost can represent various factors, such as time, distance, resources, or penalties. The path cost is the sum of the costs of the actions in a path. In many problems, the goal is to find a path with the minimum total cost.

Representing Search Problems: State Space Graph and Search Tree

To visualize and solve search problems, we use two key representations:

  • State Space Graph: This is a graphical representation of the problem’s state space.

    • Nodes in the graph represent states.

    • Edges represent transitions between states, resulting from actions. Edges can be directed and may be labeled with the action and its associated cost.

    The state space graph provides a complete map of all possible states and transitions, but for complex problems, it can be very large or even infinite.

  • Search Tree: A search tree is constructed by exploring paths from the initial state. It is an explicit tree structure that is generated during the search process.

    • The root node of the search tree corresponds to the initial state.

    • Each node in the search tree represents a path from the initial state to the corresponding state in the state space graph. Thus, a state can appear multiple times in a search tree if it is reachable through different paths.

    • Branches represent actions, leading to child nodes that represent the resulting states.

    The search tree is essentially an "unfolding" of the state space graph, focused on exploring paths from the initial state to find goal states.

The Frontier: Managing Search Exploration

The concept of the frontier (also known as the open set) is central to many search algorithms. The frontier is the collection of states that the algorithm has reached but not yet explored. It marks the boundary between the explored and unexplored parts of the state space.

Search algorithms operate by iteratively:

  1. Selecting a state from the frontier to expand. The selection strategy differentiates various search algorithms (e.g., BFS, DFS, UCS, A*).

  2. Expanding the selected state, which means generating its successor states by considering all possible actions applicable in that state.

  3. Adding the newly generated successor states to the frontier, if they have not been explored yet and meet certain criteria.

By managing the frontier, search algorithms systematically explore the state space, ensuring that they consider relevant paths and avoid redundant exploration.

Goals and Properties of Search Algorithms

The primary objectives when designing and evaluating search algorithms are:

  • Finding a Solution: The fundamental goal is to locate a path from the initial state to a goal state. A solution is a sequence of actions that achieves the goal.

  • Finding an Optimal Solution: Often, we are not just interested in any solution, but in the best solution, typically defined as the one with the minimum path cost. Optimality is a crucial property for many applications.

  • Efficiency: Search algorithms should achieve these goals efficiently, using minimal computational resources, both in terms of time and memory. Efficiency is critical for solving complex problems within practical constraints.

To assess and compare search algorithms, we evaluate them based on the following key properties:

  • Completeness: A search algorithm is complete if it guarantees finding a solution if one exists. Completeness is a desirable property, especially in critical applications where failing to find a solution can have significant consequences.

  • Optimality: An algorithm is optimal if it guarantees finding the least-cost solution among all possible solutions. Optimality is important when the quality of the solution is paramount.

  • Time Complexity: Measures how long the algorithm takes to find a solution, typically expressed in terms of the problem size. Time complexity is usually described using Big O notation, indicating how the runtime grows with the input size (e.g., branching factor, depth of solution).

  • Space Complexity: Measures the amount of memory the algorithm requires during its execution. Similar to time complexity, space complexity is also usually expressed using Big O notation, indicating how memory usage scales with the problem size.

Classic Uninformed Search Algorithms

We have previously discussed three fundamental uninformed search algorithms, also known as blind search algorithms. These algorithms do not use any domain-specific knowledge beyond the problem definition. They explore the search space based on a fixed strategy, without any heuristic guidance.

Breadth-First Search (BFS)

  • Strategy: BFS explores the search tree level by level. It expands all nodes at the current depth before proceeding to the next depth level. This is achieved by using a FIFO (First-In, First-Out) queue for the frontier.

  • Completeness: BFS is complete. If a solution exists at a finite depth, BFS is guaranteed to find it.

  • Optimality: BFS is optimal if all action costs are uniform (e.g., unit costs). In this case, it finds the shortest path in terms of the number of actions.

  • Time Complexity: \(O(b^{d+1})\), where \(b\) is the branching factor (maximum number of successors for any node) and \(d\) is the depth of the shallowest goal node. In the worst case, it explores all nodes up to depth \(d\).

  • Space Complexity: \(O(b^{d+1})\). BFS needs to store all nodes at the current level in the frontier, which can be exponential in depth. This makes BFS space-inefficient for problems with large depths.

  • Pros: Completeness and optimality for unit costs.

  • Cons: High space complexity, can be impractical for large state spaces.

Depth-First Search (DFS)

  • Strategy: DFS explores deeply along each branch of the search tree as far as possible before backtracking. It uses a LIFO (Last-In, First-Out) stack for the frontier.

  • Completeness: DFS is not complete in infinite state spaces or state spaces with cycles. It can get stuck in infinite loops if it explores along an infinitely long path that does not lead to a goal. In finite state spaces, it is complete if cycles are avoided.

  • Optimality: DFS is not optimal. It may find a solution in a deeper part of the search tree even if shallower, less costly solutions exist.

  • Time Complexity: \(O(b^{m})\), where \(m\) is the maximum depth of the search tree. In the worst case, DFS might explore the entire depth of the search space. For infinite depth spaces, \(m\) can be infinity.

  • Space Complexity: \(O(bm)\). DFS only needs to store the nodes along the current path from the root to the current node, plus siblings at each level for backtracking. This makes DFS much more space-efficient than BFS.

  • Pros: Low space complexity, can find solutions quickly if they exist in deep parts of the search space.

  • Cons: Incomplete in infinite spaces, not optimal, can explore very deep paths even if solutions are shallow.

Uniform Cost Search (UCS) (Dijkstra’s Algorithm)

  • Strategy: UCS expands nodes in order of increasing path cost \(g(n)\). It uses a priority queue for the frontier, prioritizing nodes with the lowest \(g(n)\) values. UCS is essentially Dijkstra’s algorithm applied to state space search.

  • Completeness: UCS is complete if action costs are positive. It will find a solution if one exists and the costs are not negative, preventing infinite loops with zero or negative cost cycles (though negative costs are typically not well-defined in basic search problems).

  • Optimality: UCS is optimal. It always finds the least-cost solution because it explores paths in order of their cost. When it expands a goal node, it is guaranteed to have found the optimal path to that goal.

  • Time Complexity: \(O(b^{C^*/\epsilon})\), where \(C^*\) is the cost of the optimal solution and \(\epsilon\) is the minimum action cost. In the worst case, it can explore all nodes with path cost less than or equal to \(C^*\).

  • Space Complexity: \(O(b^{C^*/\epsilon})\). Similar to BFS, UCS can store a large number of nodes in the frontier, especially if costs are uniform or nearly uniform, and the optimal path is long.

  • Pros: Completeness and optimality for general path costs.

  • Cons: Can be computationally expensive in terms of both time and space, especially if there are many paths with similar costs or if the optimal path cost is high.

Search in the Broader Context of Computer Science

The concept of search is not confined to the realm of Artificial Intelligence; it is a cornerstone of computer science, permeating various fields and applications. Many fundamental ideas and algorithms that are now considered core computer science principles have their roots in AI research, particularly in the domain of search.

Search as a Foundational Concept in Computer Science

Search algorithms and concepts are foundational to numerous areas within computer science. The influence of AI on the broader field is evident in several key developments:

  • LISP Programming Language: Developed by John McCarthy, LISP (LISt Processor) was one of the earliest high-level programming languages and became the language of choice for AI research for decades. LISP’s design, emphasizing symbolic computation and recursion, was deeply influenced by the problem-solving approaches in AI, including search. Its flexibility and expressiveness facilitated the implementation and experimentation with various search algorithms and AI techniques.

  • Object-Oriented Programming (OOP): While the origins of OOP are debated, the AI community, particularly at Xerox PARC, played a significant role in its development and popularization. Concepts like message passing and object interaction, crucial in OOP, were inspired by attempts to model complex systems and agent interactions in AI. Search problems often involve complex state representations and actions, and OOP provided a structured way to manage this complexity.

  • Database Systems and Information Retrieval: Search algorithms are at the heart of database query processing and information retrieval systems. Efficiently searching through large datasets to find relevant information relies heavily on search techniques. AI research in knowledge representation and reasoning has contributed to more sophisticated search methods in databases, moving beyond simple keyword matching to semantic search and knowledge-based retrieval.

  • Algorithms and Complexity Theory: The study of search algorithms in AI has significantly contributed to the development of algorithms and complexity theory in computer science. Analyzing the efficiency (time and space complexity) of search algorithms has led to a deeper understanding of computational limits and the design of more efficient algorithms in general. Concepts like heuristics, pruning, and optimization techniques developed in AI search are now widely used across computer science.

As John McCarthy, a pivotal figure in AI, famously remarked, the success of AI ideas often leads to their assimilation into mainstream computer science. Once an AI technique proves effective and practical, it tends to become a standard tool in the broader computer science toolkit, often losing its exclusive association with "artificial intelligence." Search algorithms are a prime example of this phenomenon.

AI’s Ongoing Contribution to Search Algorithms

While classical search algorithms like Breadth-First Search (BFS), Depth-First Search (DFS), and Uniform Cost Search (UCS) are now fundamental components of computer science curricula and practice, AI research continues to be a driving force in advancing the field of search algorithms. AI’s contribution is not limited to the initial development but extends to ongoing refinement, adaptation, and innovation:

  • Heuristic Search and Optimization: AI has significantly advanced heuristic search methods. Algorithms like A*, developed within AI, are now widely used in various optimization problems across computer science, from route planning in GPS systems to resource allocation in operations research. AI research continues to explore new types of heuristics, automated heuristic generation, and adaptive heuristic methods.

  • Constraint Satisfaction and Optimization Problems: Many real-world problems can be formulated as constraint satisfaction problems (CSPs) or optimization problems. AI has developed sophisticated search techniques, such as backtracking search, local search, and genetic algorithms, to solve these problems efficiently. These techniques are now applied in diverse fields like scheduling, logistics, and circuit design.

  • Search in Complex and Dynamic Environments: AI research addresses the challenges of search in environments that are not static, fully observable, or deterministic. Techniques for online search, reinforcement learning, and planning under uncertainty, developed in AI, extend the applicability of search to more realistic and complex scenarios.

  • Metaheuristics and Evolutionary Algorithms: Inspired by natural processes, AI has developed metaheuristic search algorithms like simulated annealing, tabu search, and evolutionary algorithms (genetic algorithms, particle swarm optimization). These methods provide robust approaches to tackle very large and complex search spaces where traditional algorithms may struggle. They are used in optimization, machine learning, and various engineering applications.

Search at the Frontier of Research and Unsolved Problems

Despite the maturity and widespread application of classical search algorithms, search remains a vibrant and crucial area of research, particularly at the cutting edge of computer science and artificial intelligence. Many contemporary challenges require search techniques that go far beyond the capabilities of basic algorithms. These challenges arise from:

  • Scale and Complexity of Data: Modern datasets and problem spaces are often enormous and highly complex. Searching for patterns, solutions, or optimal configurations in these vast spaces demands algorithms that are not only efficient but also scalable. Examples include searching the internet, analyzing massive biological datasets, or optimizing complex logistical networks.

  • Uncertainty and Dynamism: Real-world environments are rarely static and predictable. Dealing with uncertainty, incomplete information, and dynamically changing conditions requires search algorithms that are adaptive, robust, and capable of online planning and replanning. Applications in robotics, autonomous systems, and real-time decision-making highlight these needs.

  • Adversarial and Competitive Environments: In multi-agent systems and competitive scenarios like games, search algorithms must account for the actions and strategies of other agents. Adversarial search, game theory, and multi-agent planning are active research areas addressing these challenges.

  • Learning and Adaptation: The ability to learn from experience and adapt search strategies over time is crucial for intelligent systems. Integrating search with machine learning techniques, such as reinforcement learning and imitation learning, is a major direction in current research, aiming to create systems that can improve their search performance through experience.

Current Research Directions in Search Algorithms

Research in search algorithms is not only ongoing but is also expanding into new and exciting directions. Current research addresses the limitations of existing methods and seeks to develop more powerful, versatile, and intelligent search techniques. Key areas of active research include:

  • Automated Algorithm Configuration and Selection (AutoML for Search): Developing methods to automatically configure and select the best search algorithm and its parameters for a given problem. This aims to reduce the need for manual algorithm tuning and make search techniques more accessible and effective for non-expert users.

  • Anytime and Real-Time Search: Designing algorithms that can provide useful solutions even when time is limited and can improve the quality of solutions as more time becomes available. This is crucial for applications with strict time constraints, such as robotics and real-time decision systems.

  • Search in Hybrid and Continuous Spaces: Extending search techniques to handle problems with both discrete and continuous variables, and to operate in continuous state and action spaces. This is relevant to many engineering and scientific applications, such as control systems and physical simulations.

  • Integration of Search with Learning (Neuro-Symbolic AI): Combining search algorithms with machine learning techniques, particularly deep learning, to create hybrid AI systems that can leverage both symbolic reasoning and data-driven learning. This includes using neural networks to guide search, learn heuristics, or represent complex state spaces.

  • Explainable and Interpretable Search: Developing search algorithms that are not only effective but also transparent and explainable. In applications where trust and understanding are important (e.g., decision support systems, critical infrastructure control), it is crucial to understand why a search algorithm makes certain decisions and how it arrives at a solution.

  • Multi-Agent Search and Coordination: Researching search algorithms for scenarios involving multiple agents that need to coordinate their actions to achieve common or individual goals. This includes distributed search, cooperative search, and negotiation strategies in multi-agent systems.

These research directions highlight the continued importance and dynamism of search algorithms in computer science and artificial intelligence. As we tackle increasingly complex and real-world problems, the evolution and advancement of search techniques will remain central to progress in AI and related fields.

Advanced Search Techniques

Building upon the foundation of uninformed search methods, we now explore advanced search techniques that incorporate additional knowledge to guide the search process more effectively. These informed search methods, along with approaches for handling non-deterministic environments and adversarial scenarios in games, represent significant advancements in AI problem-solving.

Informed Search: Guiding Search with Heuristics

Informed search algorithms leverage domain-specific knowledge to make more intelligent choices during search. Unlike uninformed search, which explores the search space blindly, informed search uses heuristic functions to estimate the desirability of different states, guiding the search towards promising paths and potentially finding solutions more efficiently.

Heuristic Functions - \(h(n)\): Estimating the Path to the Goal

Definition 1 (Heuristic Function).

A heuristic function \(h(n)\) is a function that estimates the cost of the cheapest path from a state \(n\) to a goal state.

The heuristic function, denoted as \(h(n)\), is a crucial component of informed search. It provides an educated guess or estimate of the remaining cost to reach a goal from the current state \(n\). A good heuristic function should be computationally inexpensive to calculate and provide a meaningful estimate that helps to differentiate between more and less promising paths.

It is essential to distinguish the heuristic function \(h(n)\) from the path cost function \(g(n)\).

  • \(g(n)\): The path cost function, \(g(n)\), calculates the actual cost incurred to reach the state \(n\) from the initial state. It is a precise, backward-looking measure, representing the accumulated cost along the path traversed so far.

  • \(h(n)\): The heuristic function, \(h(n)\), estimates the cost to reach a goal state from the current state \(n\). It is an estimated, forward-looking measure, guiding the search towards the goal.

The effectiveness of informed search algorithms heavily depends on the design of a good heuristic function. Developing an effective heuristic typically requires domain knowledge and a deep understanding of the problem’s characteristics. The heuristic function is not derived from the problem definition itself but is brought in as additional information to improve search efficiency.

Greedy Best-First Search: Prioritizing the Most Promising Path

Input: Problem, heuristic function \(h\) Initialize \(\mathcal{F}\) with the initial state while \(\mathcal{F}\) is not empty do Select the node \(n\) from \(\mathcal{F}\) with the lowest \(h(n)\) if \(n\) is a goal state then return solution path to \(n\) end if Expand \(n\) and add its successors to \(\mathcal{F}\) end while return failure

Complexity Analysis:

  • Time Complexity: \(O(b^m)\) in the worst case, where \(m\) is the maximum depth of the search space. However, with a good heuristic, it can perform much better in practice.

  • Space Complexity: \(O(b^m)\) in the worst case, as it stores all nodes in the frontier.

Greedy Best-First Search (GBFS), outlined in Algorithm [alg:greedy_bfs], is an informed search algorithm that expands nodes based solely on the heuristic function \(h(n)\). It operates by prioritizing the nodes that are estimated to be closest to the goal, in a greedy manner. At each step, GBFS selects the node from the frontier that has the lowest \(h(n)\) value, hoping that this will quickly lead to a goal state.

While Greedy Best-First Search can be significantly faster than uninformed search methods, especially when guided by a good heuristic, it suffers from limitations:

  • Not Optimal: GBFS is not guaranteed to find the optimal solution. Because it only considers the heuristic cost \(h(n)\) and ignores the path cost \(g(n)\), it may take suboptimal paths that appear to be promising based on the heuristic but are actually more costly in the long run.

  • Incomplete: GBFS is not complete in general. It can get stuck in loops or infinite paths, even in finite state spaces, if it makes a series of locally optimal choices that do not lead to a goal.

Example 1 (Suboptimality of Greedy Best-First Search).

Consider a route-finding problem where we want to travel from city A to city C. Suppose there are two paths:

  • Path 1: A \(\rightarrow\) B \(\rightarrow\) C, with actual costs \(g(A,B) = 10\) and \(g(B,C) = 10\), total cost = 20.

  • Path 2: A \(\rightarrow\) D \(\rightarrow\) C, with actual costs \(g(A,D) = 20\) and \(g(D,C) = 5\), total cost = 25.

Let’s assume the heuristic estimates are: \(h(B) = 5\), \(h(D) = 1\), \(h(A) = 10\). Greedy Best-First Search would evaluate:

  • From A, consider moving to B with \(h(B) = 5\) or D with \(h(D) = 1\).

  • GBFS would choose to go to D first because \(h(D) < h(B)\), as it greedily selects the node that appears closest to the goal based on \(h(n)\).

  • However, the path through D (Path 2) is actually more costly (25) than the path through B (Path 1, cost 20).

This example illustrates how Greedy Best-First Search can be misled by the heuristic and choose a suboptimal path.

A* Search Algorithm: Combining Path Cost and Heuristic Estimate

Input: Problem, heuristic function \(h\) Initialize \(\mathcal{F}\) with the initial state while \(\mathcal{F}\) is not empty do Select the node \(n\) from \(\mathcal{F}\) with the lowest \(f(n) = g(n) + h(n)\) if \(n\) is a goal state then return solution path to \(n\) end if Expand \(n\) and add its successors to \(\mathcal{F}\) end while return failure

Complexity Analysis:

  • Time Complexity: In the worst case, A* can have exponential time complexity, similar to UCS. However, with an admissible and consistent heuristic, the number of nodes expanded can be significantly reduced.

  • Space Complexity: Also similar to UCS, A* can store a large number of nodes in the frontier, leading to exponential space complexity in the worst case.

The A* Search algorithm, detailed in Algorithm [alg:astar], is a more sophisticated informed search algorithm that addresses the limitations of Greedy Best-First Search by combining both the path cost \(g(n)\) and the heuristic estimate \(h(n)\). A* uses an evaluation function \(f(n)\) to prioritize nodes for expansion: \[f(n) = g(n) + h(n)\] where:

  • \(g(n)\) is the cost of the path from the start node to node \(n\).

  • \(h(n)\) is the estimated cost of the cheapest path from node \(n\) to a goal node.

  • \(f(n)\) is the estimated total cost of the cheapest path from the start node through \(n\) to a goal node.

A* expands nodes with the lowest \(f(n)\) value. By considering both the cost already spent (\(\\g(n)\)) and the estimated cost to the goal (\(h(n)\)), A* aims to find the optimal path efficiently. It balances exploration (considering nodes with low \(g(n)\)) and exploitation (favoring nodes with low \(h(n)\)).

Step-by-Step Example: A* Search on the Romanian Map

Example 2 (A* Search for Route Finding in Romania).

Let’s illustrate the execution of A* search using the example of finding a path from Arad to Bucharest on a map of Romania. We will use the straight-line distance to Bucharest as our heuristic function \(h(n)\).

  1. Initialization: Start by initializing the frontier with the initial state, Arad. Calculate the evaluation function \(f(\text{Arad})\): \[f(\text{Arad}) = g(\text{Arad}) + h(\text{Arad}) = 0 + 366 = 366\] Initially, \(g(\text{Arad}) = 0\) because we are at the starting city, and \(h(\text{Arad}) = 366\) is the straight-line distance from Arad to Bucharest.

  2. Expanding Arad: Expand Arad to its neighbors: Sibiu, Timisoara, and Zerind. Calculate \(f(n)\) for each neighbor:

    • Sibiu: \(g(\text{Sibiu}) = 140\) (distance from Arad to Sibiu), \(h(\text{Sibiu}) = 253\). \[f(\text{Sibiu}) = g(\text{Sibiu}) + h(\text{Sibiu}) = 140 + 253 = 393\]

    • Timisoara: \(g(\text{Timisoara}) = 118\), \(h(\text{Timisoara}) = 329\). \[f(\text{Timisoara}) = g(\text{Timisoara}) + h(\text{Timisoara}) = 118 + 329 = 447\]

    • Zerind: \(g(\text{Zerind}) = 75\), \(h(\text{Zerind}) = 374\). \[f(\text{Zerind}) = g(\text{Zerind}) + h(\text{Zerind}) = 75 + 374 = 449\]

    The frontier now contains Sibiu, Timisoara, Zerind with f-costs 393, 447, 449.

  3. Selecting Sibiu: Sibiu has the lowest \(f(n)\) value (393). Select Sibiu for expansion. Expand Sibiu to its neighbors: Arad (already visited), Fagaras, Oradea, and Rimnicu Vilcea.

    • Fagaras: \(g(\text{Fagaras}) = g(\text{Sibiu}) + \text{Cost}(\text{Sibiu, Fagaras}) = 140 + 99 = 239\), \(h(\text{Fagaras}) = 176\). \[f(\text{Fagaras}) = g(\text{Fagaras}) + h(\text{Fagaras}) = 239 + 176 = 415\]

    • Rimnicu Vilcea: \(g(\text{Rimnicu Vilcea}) = g(\text{Sibiu}) + \text{Cost}(\text{Sibiu, Rimnicu Vilcea}) = 140 + 80 = 220\), \(h(\text{Rimnicu Vilcea}) = 193\). \[f(\text{Rimnicu Vilcea}) = g(\text{Rimnicu Vilcea}) + h(\text{Rimnicu Vilcea}) = 220 + 193 = 413\]

    • Oradea: \(g(\text{Oradea}) = g(\text{Sibiu}) + \text{Cost}(\text{Sibiu, Oradea}) = 140 + 151 = 291\), \(h(\text{Oradea}) = 380\). \[f(\text{Oradea}) = g(\text{Oradea}) + h(\text{Oradea}) = 291 + 380 = 671\]

    The frontier now contains Timisoara, Zerind, Fagaras, Rimnicu Vilcea, Oradea with f-costs 447, 449, 415, 413, 671.

  4. Selecting Rimnicu Vilcea: Rimnicu Vilcea has the lowest \(f(n)\) value (413). Select Rimnicu Vilcea for expansion. Expand Rimnicu Vilcea to its neighbors: Craiova, Pitesti, and Sibiu (already visited).

    • Craiova: \(g(\text{Craiova}) = g(\text{Rimnicu Vilcea}) + \text{Cost}(\text{Rimnicu Vilcea, Craiova}) = 220 + 146 = 366\), \(h(\text{Craiova}) = 160\). \[f(\text{Craiova}) = g(\text{Craiova}) + h(\text{Craiova}) = 366 + 160 = 526\]

Admissible Heuristics and the Optimality of A*

To guarantee that A* search finds the optimal solution, we need to impose a condition on the heuristic function: admissibility.

Definition 2 (Admissible Heuristic).

An admissible heuristic \(h(n)\) is a heuristic function that never overestimates the true cost to reach a goal state from state \(n\). Formally, for all states \(n\), \(h(n) \leq h^*(n)\), where \(h^*(n)\) is the true cost of the optimal path from \(n\) to a goal state.

In simpler terms, an admissible heuristic is optimistic; it underestimates or at worst, accurately estimates the cost to the goal, but never overestimates it. Straight-line distance, as used in the Romanian map example, is an admissible heuristic for route-finding problems on a map because the straight-line distance between two points is always less than or equal to the actual path distance by road.

The admissibility of the heuristic is crucial for ensuring the optimality of A* search. This leads to a fundamental theorem:

Theorem 1 (Optimality of A*).

If the heuristic function \(h(n)\) is admissible, then A* search is optimal.

Proof. Sketch of Proof. Assume, for the sake of contradiction, that A* finds a suboptimal goal state \(G_2\) with cost \(f(G_2)\), but there exists an optimal goal state \(G_1\) with a lower cost \(f(G_1) < f(G_2)\). Since A* selected \(G_2\) for expansion before \(G_1\), it implies that at some point during the search, \(G_2\) was chosen from the frontier while \(G_1\) was either not yet found or still in the frontier.

Consider a node \(n\) that is on an optimal path to \(G_1\) and is currently in the frontier. Because \(h\) is admissible, we know that \(h(n) \leq h^*(n)\), where \(h^*(n)\) is the true optimal cost from \(n\) to \(G_1\). Therefore, the f-cost of node \(n\) is: \[f(n) = g(n) + h(n) \leq g(n) + h^*(n) = \text{Cost of optimal path through } n \text{ to } G_1 = f(G_1)\] Since \(G_1\) is a goal state, \(h^*(G_1) = 0\), and \(f(G_1) = g(G_1)\), which is the optimal path cost to \(G_1\). Thus, we have \(f(n) \leq f(G_1)\).

By our initial assumption, \(f(G_1) < f(G_2)\). Combining these inequalities, we get \(f(n) \leq f(G_1) < f(G_2)\). This shows that there exists a node \(n\) on the optimal path to \(G_1\) in the frontier whose f-cost \(f(n)\) is less than the f-cost of the suboptimal goal \(G_2\) that A* expanded.

According to the A* algorithm, if there is a node \(n\) in the frontier with \(f(n) < f(G_2)\), A* should have expanded \(n\) (or some other node with an f-cost no greater than \(f(n)\)) before expanding \(G_2\). This contradicts our assumption that A* expanded \(G_2\) before finding the optimal goal \(G_1\).

Therefore, our initial assumption must be false, and A* cannot find a suboptimal goal before finding an optimal goal if the heuristic is admissible. Hence, A* search is optimal when using an admissible heuristic. ◻

The admissibility of the heuristic guarantees the optimality of A*. However, a purely admissible heuristic might not always lead to the most efficient search. The challenge in using A* effectively is to design heuristics that are not only admissible but also informative enough to significantly prune the search space and speed up the search process. An ideal heuristic is both admissible and as close as possible to the true remaining cost without overestimation.

Illustrative Example: Heuristic Properties in Pac-Man

Example 3 (Heuristics for Pac-Man Pathfinding).

Consider the problem of Pac-Man navigating a grid to reach a food pellet. Let’s examine two common heuristic functions for this problem:

  • Manhattan Distance: The Manhattan distance between Pac-Man’s current position \((x_1, y_1)\) and the pellet’s position \((x_2, y_2)\) is calculated as \(|x_1 - x_2| + |y_1 - y_2|\). This represents the sum of horizontal and vertical steps needed to reach the pellet, assuming no obstacles.

  • Euclidean Distance: The Euclidean distance is the straight-line distance between the two points, calculated as \(\sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2}\).

In a grid-based Pac-Man environment where Pac-Man can only move horizontally and vertically and cannot pass through walls, both Manhattan distance and Euclidean distance are admissible heuristics.

  • Admissibility: Both heuristics are admissible because they never overestimate the actual path length. The shortest path in the grid will always be greater than or equal to the straight-line distance (Euclidean) or the Manhattan distance (in a grid without diagonal moves).

  • Informativeness: Manhattan distance is generally considered a more informative heuristic in grid environments than Euclidean distance. This is because Pac-Man’s movements are constrained to horizontal and vertical directions, which aligns more closely with the Manhattan distance calculation. Euclidean distance, while admissible, can sometimes be a less accurate estimate of the actual path cost in grid worlds, especially when movements are axis-aligned.

For instance, if the pellet is directly to the right of Pac-Man, the Manhattan distance accurately reflects the number of steps needed, while Euclidean distance might be a fractional value, still admissible but less precise in this context.

While Manhattan distance is often a tighter and more relevant estimate for grid-based movements, both heuristics are admissible and would ensure the optimality of A* search. The choice of heuristic can significantly impact the efficiency of the search, even if both guarantee optimality. In practice, a more informative admissible heuristic (closer to \(h^*(n)\)) typically leads to faster search by guiding A* to explore fewer nodes.

It is crucial to remember that for A* optimality, the primary requirement is the admissibility of the heuristic, not necessarily its "tightness" or closeness to the true cost, although a tighter admissible heuristic generally improves performance.

Search in Non-Deterministic Environments: Handling Uncertainty

In our discussion so far, we have assumed deterministic environments, where the outcome of an action is uniquely determined. However, many real-world environments are non-deterministic, meaning that an action taken in a state can lead to multiple possible outcomes. This uncertainty necessitates different approaches to planning and search.

Non-Deterministic Actions and Multiple Outcomes

In deterministic environments, the result function \(\text{Result}(s, a)\) maps a state \(s\) and an action \(a\) to a single, predictable next state. In non-deterministic environments, the result function \(\text{Result}(s, a)\) maps a state \(s\) and an action \(a\) to a set of possible states \(\{s'_1, s'_2, ..., s'_k\}\). This set represents all potential states that could result from performing action \(a\) in state \(s\).

Example 4 (Non-Deterministic Vacuum Cleaner Revisited).

Consider again the vacuum cleaner world with two locations, A and B. Let’s introduce non-determinism into the Suck* action. In a non-deterministic version, the action Suck in a location might have the following outcomes:*

  • Success: Clean the current location and possibly the adjacent location (as intended).

  • Partial Failure: Only clean the current location, leaving the adjacent location unchanged.

  • Adverse Effect: If the current location is already clean, the Suck* action might accidentally deposit dirt in the current location due to a malfunction.*

For instance, if the vacuum cleaner is in state 1 (location A dirty, location B dirty, vacuum at A) and performs Suck, the possible resulting states might be:

  • State 5: Location A clean, location B dirty, vacuum at A (successful cleaning of current location).

  • State 7: Location A clean, location B clean, vacuum at A (successful cleaning of both locations).

  • State 3: Location A dirty, location B dirty, vacuum at A (action fails to clean, or deposits more dirt).

This non-deterministic behavior means that a simple sequence of actions, which would suffice in a deterministic environment, is no longer adequate to guarantee reaching a goal state. The agent must plan for contingencies and handle multiple possible outcomes.

Conditional Plans: Planning for Contingencies

In non-deterministic environments, a solution is typically not a fixed sequence of actions but a conditional plan or a contingency plan. A conditional plan specifies a course of action that depends on the observed outcomes of actions. It is a more flexible and robust approach to problem-solving under uncertainty.

Example 5 (Conditional Plan for Non-Deterministic Vacuum Cleaner).

For the non-deterministic vacuum cleaner, a conditional plan to achieve the goal of having both locations A and B clean might look like this:

1. Action: Suck (in location A)
2. Observe the outcome state after Suck.
3. If the outcome is State 7 (both locations clean):
    Plan is complete, goal achieved.
4. If the outcome is State 5 (location A clean, location B dirty):
    Action: Right (move to location B)
    Action: Suck (in location B)
    Observe the outcome state after Suck in location B.
    If location B is now clean, plan is complete.
    Else, replan or take further actions (e.g., Suck again in B).
5. If the outcome is State 3 (location A remains dirty):
    Action: Suck again (in location A)
    Observe the outcome state.
    ... (continue planning based on outcomes)

This conditional plan explicitly considers different possible outcomes after each action and specifies subsequent actions based on these outcomes. It is more complex than a simple sequence of actions but is necessary to handle the uncertainty inherent in non-deterministic environments.

AND-OR Trees: Representing Contingent Solutions

AND-OR trees provide a graphical representation for solutions in non-deterministic environments. They extend the concept of search trees to incorporate both choices made by the agent (OR nodes) and contingencies arising from the environment’s non-deterministic actions (AND nodes).

In an AND-OR tree:

  • OR Nodes: Represent states where the agent needs to choose an action. From an OR node, the agent can select any one of the available actions, leading to different possible next states. OR nodes correspond to decision points for the agent, similar to nodes in standard search trees. In diagrams, OR nodes are typically represented as circles.

  • AND Nodes: Represent points where, after taking an action, the environment can produce multiple possible outcomes. For each possible outcome, there is a branch leading to a subsequent state. To achieve success from an AND node, the plan must work for all possible outcomes. AND nodes represent contingencies that the agent must handle. In diagrams, AND nodes are often represented as squares or circles with an arc connecting the branches. In the transcript example, they are represented as green circles.

Solutions in AND-OR Trees

A solution in an AND-OR tree is not a single path, as in deterministic search, but a subtree that satisfies certain conditions. A solution subtree in an AND-OR tree is defined as follows:

  • It must include the root node, representing the initial state.

  • For each OR node in the subtree, it must include exactly one outgoing branch, corresponding to a chosen action. This represents the agent’s choice of action in that state.

  • For each AND node in the subtree, it must include all outgoing branches, corresponding to all possible outcomes of an action. This ensures that the plan accounts for all contingencies.

  • All leaf nodes in the solution subtree must be goal states. This guarantees that every path in the conditional plan leads to a successful outcome, regardless of the environment’s responses at AND nodes.

Finding a solution in an AND-OR tree means identifying a subtree that meets these criteria, effectively representing a conditional plan that is guaranteed to reach a goal state despite the non-deterministic nature of the environment.

Game Playing and Adversarial Search

Game playing introduces a fundamentally different type of search problem: adversarial search. In game scenarios, we have multiple agents (players) with conflicting goals, where each agent tries to maximize their own outcome while simultaneously hindering others. This competitive aspect requires search algorithms to consider not only the possible actions and states but also the potential moves and counter-moves of opponents.

Games as a Challenge for Artificial Intelligence

Games have long been recognized as a compelling and challenging domain for Artificial Intelligence research. They offer well-defined, yet often highly complex, environments that require sophisticated AI techniques. The challenges in game playing include:

  • Strategic Thinking: Games demand strategic decision-making, planning multiple steps ahead, and anticipating future consequences of actions.

  • Adversarial Reasoning: In competitive games, agents must reason about the intentions and potential moves of opponents, whose goals are in direct conflict. This requires modeling opponent behavior and developing counter-strategies.

  • Complexity and Search Space: Many games, like chess and Go, have enormous state spaces and branching factors, making exhaustive search computationally infeasible. Efficient search algorithms and heuristics are essential to manage this complexity.

  • Imperfect Information and Uncertainty: Some games involve imperfect information (e.g., poker, bridge), where players do not have complete knowledge of the game state (like opponent’s cards). This introduces uncertainty and requires probabilistic reasoning and decision-making under incomplete information.

Despite these challenges, games provide a valuable testbed for AI algorithms. The clear objectives, rules, and performance metrics in games allow for rigorous evaluation and comparison of different AI approaches. Success in game playing has often been seen as a milestone in AI, demonstrating progress in areas like search, planning, and strategic reasoning.

A Brief History of Game AI

The pursuit of creating game-playing AI has been a significant thread in the history of artificial intelligence, marked by notable milestones across different games:

  • Checkers (Dama): Checkers was one of the earliest games tackled by AI researchers. Arthur Samuel’s checkers-playing program in the 1950s was a landmark achievement, demonstrating machine learning and search techniques. In 1994, the Chinook program achieved a historic victory by defeating the human world champion, and in 2007, checkers was effectively "solved" by the development of a program that could provably play optimally.

  • Chess (Scacchi): Chess has long been considered a grand challenge for AI. Early pioneers like Claude Shannon and Alan Turing explored chess programming in the early days of AI. Significant progress was made over decades, culminating in IBM’s Deep Blue defeating world chess champion Garry Kasparov in 1997. This event was a watershed moment, demonstrating that AI could achieve superhuman performance in a complex strategic game. Modern chess engines now far surpass even the best human players, used extensively for analysis and training.

  • Go (囲碁): Go, an ancient board game with vastly higher complexity than chess, posed an even greater challenge to AI. For a long time, Go resisted traditional AI approaches due to its enormous branching factor and the difficulty of evaluating board positions. However, a breakthrough came with the development of Monte Carlo Tree Search (MCTS) combined with deep learning. Google DeepMind’s AlphaGo program achieved a historic feat in 2016 by defeating a world Go champion, and its successor AlphaGo Zero further advanced the field by learning to play Go from scratch without human data.

  • Pac-Man: While perhaps less strategically complex than chess or Go, Pac-Man and other arcade games have also been used as testbeds for AI research, particularly in areas like real-time decision-making, planning under uncertainty, and learning from game play. The lecturer’s mention of Pac-Man may reflect research interests in applying search and AI techniques to such dynamic game environments.

These milestones in game AI highlight the continuous evolution of AI techniques and their increasing capability to master games of ever-increasing complexity. They also underscore the role of games as a driving force and a benchmark for progress in artificial intelligence.

Classifying Games: A Spectrum of Game Types

The world of games is incredibly diverse. Games can be classified along several dimensions, each influencing the AI approaches needed to play them effectively:

  • Deterministic vs. Stochastic Games:

    • Deterministic Games: These games have no element of chance or randomness. The game state evolves predictably based on player actions. Examples include chess, checkers, Go, and tic-tac-toe.

    • Stochastic Games: These games incorporate randomness, typically through dice rolls, card shuffling, or other chance events. Examples include backgammon, Monopoly, poker, and bridge. Stochastic games require AI agents to reason about probabilities and expected outcomes.

  • Perfect vs. Imperfect Information Games:

    • Perfect Information Games: In these games, all players have complete knowledge of the current game state. There is no hidden information. Examples include chess, checkers, and Go.

    • Imperfect Information Games: Players have incomplete information about the game state, often due to hidden elements like opponent’s cards or concealed units. Examples include poker, bridge, and Starcraft (fog of war). Imperfect information games require dealing with uncertainty and bluffing/deception strategies.

  • Number of Players:

    • Two-Player Games: Games with exactly two players, like chess, checkers, and Go.

    • Multi-Player Games: Games with more than two players, such as poker, bridge, Monopoly, and many board games and video games. Multi-player games introduce complexities of coalitions, negotiation, and more intricate strategic interactions.

  • Zero-Sum vs. Non-Zero-Sum Games:

    • Zero-Sum Games: In a zero-sum game, the total utility or payoff is constant. One player’s gain is directly equivalent to another player’s loss. Classic examples are chess and tic-tac-toe.

    • Non-Zero-Sum Games: It is possible for multiple players to gain or lose simultaneously. Cooperation and mutual benefit are possible. Examples include many economic games, resource management games, and real-world scenarios where agents can collaborate or compete to varying degrees.

  • Turn-Based vs. Real-Time Games:

    • Turn-Based Games: Players take turns making moves sequentially. Examples include chess, Go, and turn-based strategy games.

    • Real-Time Games: Players act simultaneously and continuously in real-time. Examples include real-time strategy games like Starcraft, action games, and sports games. Real-time games often require fast reflexes, continuous planning, and handling time pressure.

Focus on Deterministic, Turn-Based, Two-Player, Zero-Sum Games

For the purpose of introducing fundamental concepts in adversarial search, we will initially focus on a simplified class of games: deterministic, turn-based, two-player, zero-sum games with perfect information. These games, while simpler than many real-world scenarios, provide a clear framework for understanding core AI game-playing techniques. Key characteristics of this class are:

  • Deterministic: No element of chance. Game outcomes are solely determined by player decisions.

  • Turn-Based: Players move in turns, providing a structured sequence of actions.

  • Two-Player: Exactly two players, often referred to as MAX and MIN, who have opposing goals.

  • Zero-Sum: The game is purely competitive; one player’s gain is the other’s loss. The total payoff is constant (often zero, hence "zero-sum").

  • Perfect Information: Both players have complete knowledge of the game state at all times.

Examples of games fitting this category include chess, checkers, tic-tac-toe, and Go (in its deterministic, two-player form). These games are adversarial because the players are opponents, and they are zero-sum because a win for one player is a loss for the other.

Game Formulation as a Search Problem: Game Trees

Similar to other problem-solving scenarios, games can be formally defined as search problems. Specifically, deterministic, turn-based, two-player, zero-sum games can be represented using game trees. A game tree is a specialized type of search tree tailored for game playing. The key components of game formulation are:

  • Initial State: The starting configuration of the game, e.g., the initial board setup in chess.

  • Player Function: Determines which player’s turn it is to move in a given state. Typically alternates between players (MAX, MIN, MAX, MIN, ...).

  • Actions (Moves): Defines the set of legal moves available to the current player in a given state. These are the actions that transition the game from one state to another.

  • Result Function (Transition Model): Specifies the state that results from making a move in the current state. In deterministic games, this is a single, uniquely determined state.

  • Terminal Test: A condition that determines when the game ends. Terminal states are reached when the game concludes, such as checkmate in chess, reaching a certain score, or filling the board.

  • Utility Function(Objective Function or Payoff Function): Assigns a numerical value to each terminal state. This value represents the outcome of the game from the perspective of one player (conventionally MAX). In zero-sum games, a positive utility for MAX implies a negative utility of equal magnitude for MIN, and vice versa. Common utility values are:

    • +1: Win for MAX (and loss for MIN).

    • -1: Loss for MAX (and win for MIN).

    • 0: Draw or tie.

The game tree starts at the initial state and branches out to represent all possible sequences of moves by both players until terminal states are reached. Each level of the tree typically represents a turn for one of the players.

Utility Values in Game States: Evaluating Game Outcomes

The utility function is crucial for evaluating the desirability of game states, particularly terminal states. In terminal states, the utility value is directly determined by the game rules (win, loss, or draw). However, for non-terminal states, we need a way to estimate their utility, reflecting how favorable they are for a player in leading to a win.

In deterministic, turn-based, two-player, zero-sum games, the utility values are often defined from the perspective of one player, conventionally called MAX. MAX aims to maximize the utility value, while the opponent, called MIN, aims to minimize it (which is equivalent to maximizing their own utility in a zero-sum game).

Introduction to the Minimax Algorithm: Optimal Play in Adversarial Games

Utility(state) return MaxValue(state) return MinValue(state)

Initialize \(v = -\infty\) \(v = \max(v, \Call{Minimax}{Result(state, a)})\) return \(v\)

Initialize \(v = +\infty\) \(v = \min(v, \Call{Minimax}{Result(state, a)})\) return \(v\)

Description: The Minimax algorithm computes the optimal decision for a game by recursively computing the minimax value of each successor state. MaxValue computes the highest utility value achievable by MAX, while MinValue computes the lowest utility value achievable by MIN.

The Minimax algorithm is a foundational algorithm for decision-making in deterministic, turn-based, two-player, zero-sum games with perfect information. It provides a way to determine the optimal move for the MAX player, assuming that the MIN player will also play optimally to minimize MAX’s utility. Minimax is based on the principle of perfect rationality: both players are assumed to play perfectly to achieve their conflicting goals.

The core idea of the Minimax algorithm, as shown in Algorithm [alg:minimax], is recursive and involves the following steps:

  1. Game Tree Construction: Build a game tree starting from the current game state, expanding all possible moves for both players to a certain depth or until terminal states are reached. The depth of the tree explored depends on computational resources and game complexity. For simple games like tic-tac-toe, the entire game tree can be explored. For complex games like chess or Go, a limited-depth tree is explored, combined with evaluation functions for non-terminal states (discussed in the next lecture).

  2. Utility Evaluation of Terminal States: Evaluate the utility of all terminal states in the game tree using the utility function defined for the game (e.g., +1 for MAX win, -1 for MIN win, 0 for draw). These utility values are the base case for the recursion.

  3. Utility Propagation Upwards (Backpropagation): Propagate the utility values from the terminal states upwards through the game tree, level by level, using the Minimax principle:

    • MAX Nodes (Maximizing Player’s Turn): At nodes where it is MAX’s turn to move (MAX nodes), MAX will choose the move that leads to the state with the maximum utility value among its children. The utility value of a MAX node is the maximum of the utility values of its successors. This reflects MAX’s goal to maximize their outcome.

    • MIN Nodes (Minimizing Player’s Turn): At nodes where it is MIN’s turn to move (MIN nodes), MIN will choose the move that leads to the state with the minimum utility value among its children. The utility value of a MIN node is the minimum of the utility values of its successors. This reflects MIN’s goal to minimize MAX’s outcome (and thus maximize their own in a zero-sum game).

  4. Optimal Move Selection: After propagating utility values up to the root node (representing the current game state), the root node’s utility value represents the best achievable outcome for MAX, assuming optimal play by both sides. MAX should choose the move from the initial state that leads to the child node with this minimax value. This is the optimal move according to the Minimax algorithm.

By recursively applying the maximization and minimization steps at alternating levels of the game tree, the Minimax algorithm effectively simulates optimal adversarial play. It determines the best move for MAX in the current state, considering all possible responses from MIN and assuming MIN will also choose their best moves to counter MAX.

# Recap of Search Fundamentals

Before delving into advanced search techniques, it is crucial to revisit
the foundational concepts of search algorithms. These fundamentals
provide the necessary context for understanding the more sophisticated
methods we will explore.

## Problem Solving Agents and Search

At the heart of intelligent behavior lies the ability to solve problems.
In artificial intelligence, we often model problem-solving through the
concept of *agents* that navigate through different states to achieve a
goal. These *problem-solving agents* operate by searching for a sequence
of actions that lead from an initial state to a desired goal state. The
process of finding this sequence is known as *search*. Search algorithms
provide systematic methods to explore the space of possible states and
actions to find a solution.

## Formulating Search Problems

To apply search algorithms, we must first formulate the problem in a
structured manner. A search problem is defined by the following
components, which collectively describe the environment and the
objective:

-   **State Space**: This is the set of all possible configurations or
    situations in which the agent can be. Each state represents a
    distinct situation in the problem domain. For example, in
    route-finding, states are cities; in a puzzle, states are
    configurations of the puzzle pieces.

-   **Initial State**: The starting point of the problem. It is the
    state from which the agent begins its search for a solution. In a
    navigation problem, this could be the agent's current location.

-   **Actions**: These are the operations that the agent can perform in
    each state to transition to another state. Actions are
    context-dependent; the available actions vary from state to state.
    For instance, from a city, the actions might be to travel to
    adjacent cities.

-   **Result Function (Transition Model)**: This function defines the
    outcome of performing an action in a given state. It specifies the
    state that the agent will transition to after executing an action.
    In deterministic environments, the result is a single, predictable
    state.

-   **Goal Test**: A condition that determines whether a given state is
    a goal state. This test checks if the current state satisfies the
    problem's objective. There might be one or more goal states. For
    example, in route-finding, the goal is to be in the destination
    city.

-   **Cost Function (Path Cost)**: Assigns a numerical cost to each
    action. This cost can represent various factors, such as time,
    distance, resources, or penalties. The path cost is the sum of the
    costs of the actions in a path. In many problems, the goal is to
    find a path with the minimum total cost.

## Representing Search Problems: State Space Graph and Search Tree

To visualize and solve search problems, we use two key representations:

-   **State Space Graph**: This is a graphical representation of the
    problem's state space.

    -   **Nodes** in the graph represent *states*.

    -   **Edges** represent *transitions* between states, resulting from
        actions. Edges can be directed and may be labeled with the
        action and its associated cost.

    The state space graph provides a complete map of all possible states
    and transitions, but for complex problems, it can be very large or
    even infinite.

-   **Search Tree**: A *search tree* is constructed by exploring paths
    from the initial state. It is an explicit tree structure that is
    generated during the search process.

    -   The **root node** of the search tree corresponds to the *initial
        state*.

    -   Each **node** in the search tree represents a *path* from the
        initial state to the corresponding state in the state space
        graph. Thus, a state can appear multiple times in a search tree
        if it is reachable through different paths.

    -   **Branches** represent actions, leading to child nodes that
        represent the resulting states.

    The search tree is essentially an \"unfolding\" of the state space
    graph, focused on exploring paths from the initial state to find
    goal states.

## The Frontier: Managing Search Exploration

The concept of the **frontier** (also known as the *open set*) is
central to many search algorithms. The frontier is the collection of
states that the algorithm has reached but not yet explored. It marks the
boundary between the explored and unexplored parts of the state space.

Search algorithms operate by iteratively:

1.  **Selecting** a state from the frontier to expand. The selection
    strategy differentiates various search algorithms (e.g., BFS, DFS,
    UCS, A\*).

2.  **Expanding** the selected state, which means generating its
    successor states by considering all possible actions applicable in
    that state.

3.  **Adding** the newly generated successor states to the frontier, if
    they have not been explored yet and meet certain criteria.

By managing the frontier, search algorithms systematically explore the
state space, ensuring that they consider relevant paths and avoid
redundant exploration.

## Goals and Properties of Search Algorithms

The primary objectives when designing and evaluating search algorithms
are:

-   **Finding a Solution**: The fundamental goal is to locate a path
    from the initial state to a goal state. A solution is a sequence of
    actions that achieves the goal.

-   **Finding an Optimal Solution**: Often, we are not just interested
    in any solution, but in the *best* solution, typically defined as
    the one with the minimum path cost. Optimality is a crucial property
    for many applications.

-   **Efficiency**: Search algorithms should achieve these goals
    efficiently, using minimal computational resources, both in terms of
    time and memory. Efficiency is critical for solving complex problems
    within practical constraints.

To assess and compare search algorithms, we evaluate them based on the
following key properties:

-   **Completeness**: A search algorithm is *complete* if it guarantees
    finding a solution if one exists. Completeness is a desirable
    property, especially in critical applications where failing to find
    a solution can have significant consequences.

-   **Optimality**: An algorithm is *optimal* if it guarantees finding
    the least-cost solution among all possible solutions. Optimality is
    important when the quality of the solution is paramount.

-   **Time Complexity**: Measures how long the algorithm takes to find a
    solution, typically expressed in terms of the problem size. Time
    complexity is usually described using Big O notation, indicating how
    the runtime grows with the input size (e.g., branching factor, depth
    of solution).

-   **Space Complexity**: Measures the amount of memory the algorithm
    requires during its execution. Similar to time complexity, space
    complexity is also usually expressed using Big O notation,
    indicating how memory usage scales with the problem size.

## Classic Uninformed Search Algorithms

We have previously discussed three fundamental *uninformed* search
algorithms, also known as *blind* search algorithms. These algorithms do
not use any domain-specific knowledge beyond the problem definition.
They explore the search space based on a fixed strategy, without any
heuristic guidance.

### Breadth-First Search (BFS)

-   **Strategy**: BFS explores the search tree level by level. It
    expands all nodes at the current depth before proceeding to the next
    depth level. This is achieved by using a FIFO (First-In, First-Out)
    queue for the frontier.

-   **Completeness**: BFS is *complete*. If a solution exists at a
    finite depth, BFS is guaranteed to find it.

-   **Optimality**: BFS is *optimal* if all action costs are uniform
    (e.g., unit costs). In this case, it finds the shortest path in
    terms of the number of actions.

-   **Time Complexity**: $O(b^{d+1})$, where $b$ is the branching factor
    (maximum number of successors for any node) and $d$ is the depth of
    the shallowest goal node. In the worst case, it explores all nodes
    up to depth $d$.

-   **Space Complexity**: $O(b^{d+1})$. BFS needs to store all nodes at
    the current level in the frontier, which can be exponential in
    depth. This makes BFS space-inefficient for problems with large
    depths.

-   **Pros**: Completeness and optimality for unit costs.

-   **Cons**: High space complexity, can be impractical for large state
    spaces.

### Depth-First Search (DFS)

-   **Strategy**: DFS explores deeply along each branch of the search
    tree as far as possible before backtracking. It uses a LIFO
    (Last-In, First-Out) stack for the frontier.

-   **Completeness**: DFS is *not complete* in infinite state spaces or
    state spaces with cycles. It can get stuck in infinite loops if it
    explores along an infinitely long path that does not lead to a goal.
    In finite state spaces, it is complete if cycles are avoided.

-   **Optimality**: DFS is *not optimal*. It may find a solution in a
    deeper part of the search tree even if shallower, less costly
    solutions exist.

-   **Time Complexity**: $O(b^{m})$, where $m$ is the maximum depth of
    the search tree. In the worst case, DFS might explore the entire
    depth of the search space. For infinite depth spaces, $m$ can be
    infinity.

-   **Space Complexity**: $O(bm)$. DFS only needs to store the nodes
    along the current path from the root to the current node, plus
    siblings at each level for backtracking. This makes DFS much more
    space-efficient than BFS.

-   **Pros**: Low space complexity, can find solutions quickly if they
    exist in deep parts of the search space.

-   **Cons**: Incomplete in infinite spaces, not optimal, can explore
    very deep paths even if solutions are shallow.

### Uniform Cost Search (UCS) (Dijkstra's Algorithm)

-   **Strategy**: UCS expands nodes in order of increasing path cost
    $g(n)$. It uses a priority queue for the frontier, prioritizing
    nodes with the lowest $g(n)$ values. UCS is essentially Dijkstra's
    algorithm applied to state space search.

-   **Completeness**: UCS is *complete* if action costs are positive. It
    will find a solution if one exists and the costs are not negative,
    preventing infinite loops with zero or negative cost cycles (though
    negative costs are typically not well-defined in basic search
    problems).

-   **Optimality**: UCS is *optimal*. It always finds the least-cost
    solution because it explores paths in order of their cost. When it
    expands a goal node, it is guaranteed to have found the optimal path
    to that goal.

-   **Time Complexity**: $O(b^{C^*/\epsilon})$, where $C^*$ is the cost
    of the optimal solution and $\epsilon$ is the minimum action cost.
    In the worst case, it can explore all nodes with path cost less than
    or equal to $C^*$.

-   **Space Complexity**: $O(b^{C^*/\epsilon})$. Similar to BFS, UCS can
    store a large number of nodes in the frontier, especially if costs
    are uniform or nearly uniform, and the optimal path is long.

-   **Pros**: Completeness and optimality for general path costs.

-   **Cons**: Can be computationally expensive in terms of both time and
    space, especially if there are many paths with similar costs or if
    the optimal path cost is high.

Building upon the foundation of uninformed search methods, we now

## Informed Search: Guiding Search with Heuristics

*Informed search algorithms* leverage domain-specific knowledge to make
more intelligent choices during search. Unlike uninformed search, which
explores the search space blindly, informed search uses *heuristic
functions* to estimate the desirability of different states, guiding the
search towards promising paths and potentially finding solutions more
efficiently.

### Heuristic Functions - $h(n)$: Estimating the Path to the Goal

:::: definition
**Definition 1** (Heuristic Function).

::: tcolorbox
*A heuristic function $h(n)$ is a function that estimates the cost of
the cheapest path from a state $n$ to a goal state.*
:::
::::

The heuristic function, denoted as $h(n)$, is a crucial component of
informed search. It provides an *educated guess* or estimate of the
remaining cost to reach a goal from the current state $n$. A good
heuristic function should be computationally inexpensive to calculate
and provide a meaningful estimate that helps to differentiate between
more and less promising paths.

It is essential to distinguish the heuristic function $h(n)$ from the
path cost function $g(n)$.

-   **$g(n)$**: The path cost function, $g(n)$, calculates the actual
    cost incurred to reach the state $n$ from the initial state. It is a
    precise, backward-looking measure, representing the accumulated cost
    along the path traversed so far.

-   **$h(n)$**: The heuristic function, $h(n)$, estimates the cost to
    reach a goal state from the current state $n$. It is an estimated,
    forward-looking measure, guiding the search towards the goal.

The effectiveness of informed search algorithms heavily depends on the
design of a good heuristic function. Developing an effective heuristic
typically requires domain knowledge and a deep understanding of the
problem's characteristics. The heuristic function is not derived from
the problem definition itself but is brought in as additional
information to improve search efficiency.

### Greedy Best-First Search: Prioritizing the Most Promising Path

:::: algorithm
::: algorithmic
**Input:** Problem, heuristic function $h$ Initialize $\mathcal{F}$ with
the initial state **while** $\mathcal{F}$ is not empty **do** Select the
node $n$ from $\mathcal{F}$ with the lowest $h(n)$ **if** $n$ is a goal
state **then** **return** solution path to $n$ **end if** Expand $n$ and
add its successors to $\mathcal{F}$ **end while** **return** failure
:::

**Complexity Analysis:**

-   **Time Complexity**: $O(b^m)$ in the worst case, where $m$ is the
    maximum depth of the search space. However, with a good heuristic,
    it can perform much better in practice.

-   **Space Complexity**: $O(b^m)$ in the worst case, as it stores all
    nodes in the frontier.
::::

*Greedy Best-First Search* (GBFS), outlined in Algorithm
[\[alg:greedy_bfs\]](#alg:greedy_bfs){reference-type="ref"
reference="alg:greedy_bfs"}, is an informed search algorithm that
expands nodes based solely on the heuristic function $h(n)$. It operates
by prioritizing the nodes that are estimated to be closest to the goal,
in a greedy manner. At each step, GBFS selects the node from the
frontier that has the lowest $h(n)$ value, hoping that this will quickly
lead to a goal state.

While Greedy Best-First Search can be significantly faster than
uninformed search methods, especially when guided by a good heuristic,
it suffers from limitations:

-   **Not Optimal**: GBFS is not guaranteed to find the optimal
    solution. Because it only considers the heuristic cost $h(n)$ and
    ignores the path cost $g(n)$, it may take suboptimal paths that
    appear to be promising based on the heuristic but are actually more
    costly in the long run.

-   **Incomplete**: GBFS is not complete in general. It can get stuck in
    loops or infinite paths, even in finite state spaces, if it makes a
    series of locally optimal choices that do not lead to a goal.

:::: example
**Example 1** (Suboptimality of Greedy Best-First Search).

::: tcolorbox
*Consider a route-finding problem where we want to travel from city A to
city C. Suppose there are two paths:*

-   *Path 1: A $\rightarrow$ B $\rightarrow$ C, with actual costs
    $g(A,B) = 10$ and $g(B,C) = 10$, total cost = 20.*

-   *Path 2: A $\rightarrow$ D $\rightarrow$ C, with actual costs
    $g(A,D) = 20$ and $g(D,C) = 5$, total cost = 25.*

*Let's assume the heuristic estimates are: $h(B) = 5$, $h(D) = 1$,
$h(A) = 10$. Greedy Best-First Search would evaluate:*

-   *From A, consider moving to B with $h(B) = 5$ or D with $h(D) = 1$.*

-   *GBFS would choose to go to D first because $h(D) < h(B)$, as it
    greedily selects the node that appears closest to the goal based on
    $h(n)$.*

-   *However, the path through D (Path 2) is actually more costly (25)
    than the path through B (Path 1, cost 20).*

*This example illustrates how Greedy Best-First Search can be misled by
the heuristic and choose a suboptimal path.*
:::
::::

### A\* Search Algorithm: Combining Path Cost and Heuristic Estimate

:::: algorithm
::: algorithmic
**Input:** Problem, heuristic function $h$ Initialize $\mathcal{F}$ with
the initial state **while** $\mathcal{F}$ is not empty **do** Select the
node $n$ from $\mathcal{F}$ with the lowest $f(n) = g(n) + h(n)$ **if**
$n$ is a goal state **then** **return** solution path to $n$ **end if**
Expand $n$ and add its successors to $\mathcal{F}$ **end while**
**return** failure
:::

**Complexity Analysis:**

-   **Time Complexity**: In the worst case, A\* can have exponential
    time complexity, similar to UCS. However, with an admissible and
    consistent heuristic, the number of nodes expanded can be
    significantly reduced.

-   **Space Complexity**: Also similar to UCS, A\* can store a large
    number of nodes in the frontier, leading to exponential space
    complexity in the worst case.
::::

The *A\* Search algorithm*, detailed in Algorithm
[\[alg:astar\]](#alg:astar){reference-type="ref" reference="alg:astar"},
is a more sophisticated informed search algorithm that addresses the
limitations of Greedy Best-First Search by combining both the path cost
$g(n)$ and the heuristic estimate $h(n)$. A\* uses an *evaluation
function* $f(n)$ to prioritize nodes for expansion:
$$f(n) = g(n) + h(n)$$ where:

-   $g(n)$ is the cost of the path from the start node to node $n$.

-   $h(n)$ is the estimated cost of the cheapest path from node $n$ to a
    goal node.

-   $f(n)$ is the estimated total cost of the cheapest path from the
    start node through $n$ to a goal node.

A\* expands nodes with the lowest $f(n)$ value. By considering both the
cost already spent ($\\g(n)$) and the estimated cost to the goal
($h(n)$), A\* aims to find the optimal path efficiently. It balances
exploration (considering nodes with low $g(n)$) and exploitation
(favoring nodes with low $h(n)$).

:::: example
**Example 2** (A\* Search for Route Finding in Romania).

::: tcolorbox
*Let's illustrate the execution of A\* search using the example of
finding a path from Arad to Bucharest on a map of Romania. We will use
the straight-line distance to Bucharest as our heuristic function
$h(n)$.*

1.  ***Initialization**: Start by initializing the frontier with the
    initial state, Arad. Calculate the evaluation function
    $f(\text{Arad})$:

### Admissible Heuristics and the Optimality of A\*

To guarantee that A\* search finds the optimal solution, we need to
impose a condition on the heuristic function: *admissibility*.

:::: definition
**Definition 2** (Admissible Heuristic).

::: tcolorbox
*An admissible heuristic $h(n)$ is a heuristic function that never
overestimates the true cost to reach a goal state from state $n$.
Formally, for all states $n$, $h(n) \leq h^*(n)$, where $h^*(n)$ is the
true cost of the optimal path from $n$ to a goal state.*
:::
::::

In simpler terms, an admissible heuristic is *optimistic*; it
underestimates or at worst, accurately estimates the cost to the goal,
but never overestimates it. Straight-line distance, as used in the
Romanian map example, is an admissible heuristic for route-finding
problems on a map because the straight-line distance between two points
is always less than or equal to the actual path distance by road.

The admissibility of the heuristic is crucial for ensuring the
optimality of A\* search. This leads to a fundamental theorem:

:::: theorem
**Theorem 1** (Optimality of A\*).

::: tcolorbox
*If the heuristic function $h(n)$ is admissible, then A\* search is
optimal.*
:::
::::

::: proof
*Sketch of Proof.* Assume, for the sake of contradiction, that A\* finds
a suboptimal goal state $G_2$ with cost $f(G_2)$, but there exists an
optimal goal state $G_1$ with a lower cost $f(G_1) < f(G_2)$. Since A\*
selected $G_2$ for expansion before $G_1$, it implies that at some point
during the search, $G_2$ was chosen from the frontier while $G_1$ was
either not yet found or still in the frontier.

Consider a node $n$ that is on an optimal path to $G_1$ and is currently
in the frontier. Because $h$ is admissible, we know that
$h(n) \leq h^*(n)$, where $h^*(n)$ is the true optimal cost from $n$ to
$G_1$. Therefore, the f-cost of node $n$ is:
$$f(n) = g(n) + h(n) \leq g(n) + h^*(n) = \text{Cost of optimal path through } n \text{ to } G_1 = f(G_1)$$
Since $G_1$ is a goal state, $h^*(G_1) = 0$, and $f(G_1) = g(G_1)$,
which is the optimal path cost to $G_1$. Thus, we have
$f(n) \leq f(G_1)$.

By our initial assumption, $f(G_1) < f(G_2)$. Combining these
inequalities, we get $f(n) \leq f(G_1) < f(G_2)$. This shows that there
exists a node $n$ on the optimal path to $G_1$ in the frontier whose
f-cost $f(n)$ is less than the f-cost of the suboptimal goal $G_2$ that
A\* expanded.

According to the A\* algorithm, if there is a node $n$ in the frontier
with $f(n) < f(G_2)$, A\* should have expanded $n$ (or some other node
with an f-cost no greater than $f(n)$) before expanding $G_2$. This
contradicts our assumption that A\* expanded $G_2$ before finding the
optimal goal $G_1$.

Therefore, our initial assumption must be false, and A\* cannot find a
suboptimal goal before finding an optimal goal if the heuristic is
admissible. Hence, A\* search is optimal when using an admissible
heuristic. ◻
:::

The admissibility of the heuristic guarantees the optimality of A\*.
However, a purely admissible heuristic might not always lead to the most
efficient search. The challenge in using A\* effectively is to design
heuristics that are not only admissible but also *informative* enough to
significantly prune the search space and speed up the search process. An
ideal heuristic is both admissible and as close as possible to the true
remaining cost without overestimation.

### Illustrative Example: Heuristic Properties in Pac-Man

:::: example
**Example 3** (Heuristics for Pac-Man Pathfinding).

::: tcolorbox
*Consider the problem of Pac-Man navigating a grid to reach a food
pellet. Let's examine two common heuristic functions for this problem:*

-   ***Manhattan Distance**: The Manhattan distance between Pac-Man's
    current position $(x_1, y_1)$ and the pellet's position $(x_2, y_2)$
    is calculated as $|x_1 - x_2| + |y_1 - y_2|$. This represents the
    sum of horizontal and vertical steps needed to reach the pellet,
    assuming no obstacles.*

-   ***Euclidean Distance**: The Euclidean distance is the straight-line
    distance between the two points, calculated as
    $\sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2}$.*

*In a grid-based Pac-Man environment where Pac-Man can only move
horizontally and vertically and cannot pass through walls, both
Manhattan distance and Euclidean distance are admissible heuristics.*

-   ***Admissibility**: Both heuristics are admissible because they
    never overestimate the actual path length. The shortest path in the
    grid will always be greater than or equal to the straight-line
    distance (Euclidean) or the Manhattan distance (in a grid without
    diagonal moves).*

-   ***Informativeness**: Manhattan distance is generally considered a
    more informative heuristic in grid environments than Euclidean
    distance. This is because Pac-Man's movements are constrained to
    horizontal and vertical directions, which aligns more closely with
    the Manhattan distance calculation. Euclidean distance, while
    admissible, can sometimes be a less accurate estimate of the actual
    path cost in grid worlds, especially when movements are
    axis-aligned.*

*For instance, if the pellet is directly to the right of Pac-Man, the
Manhattan distance accurately reflects the number of steps needed, while
Euclidean distance might be a fractional value, still admissible but
less precise in this context.*

*While Manhattan distance is often a tighter and more relevant estimate
for grid-based movements, both heuristics are admissible and would
ensure the optimality of A\* search. The choice of heuristic can
significantly impact the efficiency of the search, even if both
guarantee optimality. In practice, a more informative admissible
heuristic (closer to $h^*(n)$) typically leads to faster search by
guiding A\* to explore fewer nodes.*

*It is crucial to remember that for A\* optimality, the primary
requirement is the admissibility of the heuristic, not necessarily its
\"tightness\" or closeness to the true cost, although a tighter
admissible heuristic generally improves performance.*

## Search in Non-Deterministic Environments: Handling Uncertainty

In our discussion so far, we have assumed *deterministic environments*,
where the outcome of an action is uniquely determined. However, many
real-world environments are *non-deterministic*, meaning that an action
taken in a state can lead to multiple possible outcomes. This
uncertainty necessitates different approaches to planning and search.

### Non-Deterministic Actions and Multiple Outcomes

In deterministic environments, the result function $\text{Result}(s, a)$
maps a state $s$ and an action $a$ to a single, predictable next state.
In *non-deterministic environments*, the result function
$\text{Result}(s, a)$ maps a state $s$ and an action $a$ to a *set* of
possible states $\{s'_1, s'_2, ..., s'_k\}$. This set represents all
potential states that could result from performing action $a$ in state
$s$.

:::: example
**Example 4** (Non-Deterministic Vacuum Cleaner Revisited).

::: tcolorbox
*Consider again the vacuum cleaner world with two locations, A and B.
Let's introduce non-determinism into the *Suck* action. In a
non-deterministic version, the action *Suck* in a location might have
the following outcomes:*

-   ***Success**: Clean the current location and possibly the adjacent
    location (as intended).*

-   ***Partial Failure**: Only clean the current location, leaving the
    adjacent location unchanged.*

-   ***Adverse Effect**: If the current location is already clean, the
    *Suck* action might accidentally deposit dirt in the current
    location due to a malfunction.*

*For instance, if the vacuum cleaner is in state 1 (location A dirty,
location B dirty, vacuum at A) and performs *Suck*, the possible
resulting states might be:*

-   *State 5: Location A clean, location B dirty, vacuum at A
    (successful cleaning of current location).*

-   *State 7: Location A clean, location B clean, vacuum at A
    (successful cleaning of both locations).*

-   *State 3: Location A dirty, location B dirty, vacuum at A (action
    fails to clean, or deposits more dirt).*

*This non-deterministic behavior means that a simple sequence of
actions, which would suffice in a deterministic environment, is no
longer adequate to guarantee reaching a goal state. The agent must plan
for contingencies and handle multiple possible outcomes.*
:::
::::

### Conditional Plans: Planning for Contingencies

In non-deterministic environments, a solution is typically not a fixed
sequence of actions but a *conditional plan* or a *contingency plan*. A
conditional plan specifies a course of action that depends on the
observed outcomes of actions. It is a more flexible and robust approach
to problem-solving under uncertainty.

:::: example
**Example 5** (Conditional Plan for Non-Deterministic Vacuum Cleaner).

::: tcolorbox
*For the non-deterministic vacuum cleaner, a conditional plan to achieve
the goal of having both locations A and B clean might look like this:*

    1. Action: Suck (in location A)
    2. Observe the outcome state after Suck.
    3. If the outcome is State 7 (both locations clean):
        Plan is complete, goal achieved.
    4. If the outcome is State 5 (location A clean, location B dirty):
        Action: Right (move to location B)
        Action: Suck (in location B)
        Observe the outcome state after Suck in location B.
        If location B is now clean, plan is complete.
        Else, replan or take further actions (e.g., Suck again in B).
    5. If the outcome is State 3 (location A remains dirty):
        Action: Suck again (in location A)
        Observe the outcome state.
        ... (continue planning based on outcomes)

*This conditional plan explicitly considers different possible outcomes
after each action and specifies subsequent actions based on these
outcomes. It is more complex than a simple sequence of actions but is
necessary to handle the uncertainty inherent in non-deterministic
environments.*
:::
::::

### AND-OR Trees: Representing Contingent Solutions

*AND-OR trees* provide a graphical representation for solutions in
non-deterministic environments. They extend the concept of search trees
to incorporate both choices made by the agent (OR nodes) and
contingencies arising from the environment's non-deterministic actions
(AND nodes).

In an AND-OR tree:

-   **OR Nodes**: Represent states where the agent needs to choose an
    action. From an OR node, the agent can select any one of the
    available actions, leading to different possible next states. OR
    nodes correspond to decision points for the agent, similar to nodes
    in standard search trees. In diagrams, OR nodes are typically
    represented as circles.

-   **AND Nodes**: Represent points where, after taking an action, the
    environment can produce multiple possible outcomes. For each
    possible outcome, there is a branch leading to a subsequent state.
    To achieve success from an AND node, the plan must work for *all*
    possible outcomes. AND nodes represent contingencies that the agent
    must handle. In diagrams, AND nodes are often represented as squares
    or circles with an arc connecting the branches. In the transcript
    example, they are represented as green circles.

### Solutions in AND-OR Trees

A solution in an AND-OR tree is not a single path, as in deterministic
search, but a *subtree* that satisfies certain conditions. A solution
subtree in an AND-OR tree is defined as follows:

-   It must include the **root node**, representing the initial state.

-   For each **OR node** in the subtree, it must include **exactly one**
    outgoing branch, corresponding to a chosen action. This represents
    the agent's choice of action in that state.

-   For each **AND node** in the subtree, it must include **all**
    outgoing branches, corresponding to all possible outcomes of an
    action. This ensures that the plan accounts for all contingencies.

-   All **leaf nodes** in the solution subtree must be **goal states**.
    This guarantees that every path in the conditional plan leads to a
    successful outcome, regardless of the environment's responses at AND
    nodes.

Finding a solution in an AND-OR tree means identifying a subtree that
meets these criteria, effectively representing a conditional plan that
is guaranteed to reach a goal state despite the non-deterministic nature
of the environment.

## Game Playing and Adversarial Search

Game playing introduces a fundamentally different type of search
problem: *adversarial search*. In game scenarios, we have multiple
agents (players) with conflicting goals, where each agent tries to
maximize their own outcome while simultaneously hindering others. This
competitive aspect requires search algorithms to consider not only the
possible actions and states but also the potential moves and
counter-moves of opponents.

### Games as a Challenge for Artificial Intelligence

Games have long been recognized as a compelling and challenging domain
for Artificial Intelligence research. They offer well-defined, yet often
highly complex, environments that require sophisticated AI techniques.
The challenges in game playing include:

-   **Strategic Thinking**: Games demand strategic decision-making,
    planning multiple steps ahead, and anticipating future consequences
    of actions.

-   **Adversarial Reasoning**: In competitive games, agents must reason
    about the intentions and potential moves of opponents, whose goals
    are in direct conflict. This requires modeling opponent behavior and
    developing counter-strategies.

-   **Complexity and Search Space**: Many games, like chess and Go, have
    enormous state spaces and branching factors, making exhaustive
    search computationally infeasible. Efficient search algorithms and
    heuristics are essential to manage this complexity.

-   **Imperfect Information and Uncertainty**: Some games involve
    imperfect information (e.g., poker, bridge), where players do not
    have complete knowledge of the game state (like opponent's cards).
    This introduces uncertainty and requires probabilistic reasoning and
    decision-making under incomplete information.

Despite these challenges, games provide a valuable testbed for AI
algorithms. The clear objectives, rules, and performance metrics in
games allow for rigorous evaluation and comparison of different AI
approaches. Success in game playing has often been seen as a milestone
in AI, demonstrating progress in areas like search, planning, and
strategic reasoning.

### A Brief History of Game AI

The pursuit of creating game-playing AI has been a significant thread in
the history of artificial intelligence, marked by notable milestones
across different games:

-   **Checkers (Dama)**: Checkers was one of the earliest games tackled
    by AI researchers. Arthur Samuel's checkers-playing program in the
    1950s was a landmark achievement, demonstrating machine learning and
    search techniques. In 1994, the Chinook program achieved a historic
    victory by defeating the human world champion, and in 2007, checkers
    was effectively \"solved\" by the development of a program that
    could provably play optimally.

-   **Chess (Scacchi)**: Chess has long been considered a grand
    challenge for AI. Early pioneers like Claude Shannon and Alan Turing
    explored chess programming in the early days of AI. Significant
    progress was made over decades, culminating in IBM's Deep Blue
    defeating world chess champion Garry Kasparov in 1997. This event
    was a watershed moment, demonstrating that AI could achieve
    superhuman performance in a complex strategic game. Modern chess
    engines now far surpass even the best human players, used
    extensively for analysis and training.

-   **Go (囲碁)**: Go, an ancient board game with vastly higher
    complexity than chess, posed an even greater challenge to AI. For a
    long time, Go resisted traditional AI approaches due to its enormous
    branching factor and the difficulty of evaluating board positions.
    However, a breakthrough came with the development of *Monte Carlo
    Tree Search* (MCTS) combined with deep learning. Google DeepMind's
    AlphaGo program achieved a historic feat in 2016 by defeating a
    world Go champion, and its successor AlphaGo Zero further advanced
    the field by learning to play Go from scratch without human data.

-   **Pac-Man**: While perhaps less strategically complex than chess or
    Go, Pac-Man and other arcade games have also been used as testbeds
    for AI research, particularly in areas like real-time
    decision-making, planning under uncertainty, and learning from game
    play. The lecturer's mention of Pac-Man may reflect research
    interests in applying search and AI techniques to such dynamic game
    environments.

These milestones in game AI highlight the continuous evolution of AI
techniques and their increasing capability to master games of
ever-increasing complexity. They also underscore the role of games as a
driving force and a benchmark for progress in artificial intelligence.

### Classifying Games: A Spectrum of Game Types

The world of games is incredibly diverse. Games can be classified along
several dimensions, each influencing the AI approaches needed to play
them effectively:

-   **Deterministic vs. Stochastic Games**:

    -   **Deterministic Games**: These games have no element of chance
        or randomness. The game state evolves predictably based on
        player actions. Examples include chess, checkers, Go, and
        tic-tac-toe.

    -   **Stochastic Games**: These games incorporate randomness,
        typically through dice rolls, card shuffling, or other chance
        events. Examples include backgammon, Monopoly, poker, and
        bridge. Stochastic games require AI agents to reason about
        probabilities and expected outcomes.

-   **Perfect vs. Imperfect Information Games**:

    -   **Perfect Information Games**: In these games, all players have
        complete knowledge of the current game state. There is no hidden
        information. Examples include chess, checkers, and Go.

    -   **Imperfect Information Games**: Players have incomplete
        information about the game state, often due to hidden elements
        like opponent's cards or concealed units. Examples include
        poker, bridge, and Starcraft (fog of war). Imperfect information
        games require dealing with uncertainty and bluffing/deception
        strategies.

-   **Number of Players**:

    -   **Two-Player Games**: Games with exactly two players, like
        chess, checkers, and Go.

    -   **Multi-Player Games**: Games with more than two players, such
        as poker, bridge, Monopoly, and many board games and video
        games. Multi-player games introduce complexities of coalitions,
        negotiation, and more intricate strategic interactions.

-   **Zero-Sum vs. Non-Zero-Sum Games**:

    -   **Zero-Sum Games**: In a zero-sum game, the total utility or
        payoff is constant. One player's gain is directly equivalent to
        another player's loss. Classic examples are chess and
        tic-tac-toe.

    -   **Non-Zero-Sum Games**: It is possible for multiple players to
        gain or lose simultaneously. Cooperation and mutual benefit are
        possible. Examples include many economic games, resource
        management games, and real-world scenarios where agents can
        collaborate or compete to varying degrees.

-   **Turn-Based vs. Real-Time Games**:

    -   **Turn-Based Games**: Players take turns making moves
        sequentially. Examples include chess, Go, and turn-based
        strategy games.

    -   **Real-Time Games**: Players act simultaneously and continuously
        in real-time. Examples include real-time strategy games like
        Starcraft, action games, and sports games. Real-time games often
        require fast reflexes, continuous planning, and handling time
        pressure.

### Focus on Deterministic, Turn-Based, Two-Player, Zero-Sum Games

For the purpose of introducing fundamental concepts in adversarial
search, we will initially focus on a simplified class of games:
**deterministic, turn-based, two-player, zero-sum games with perfect
information**. These games, while simpler than many real-world
scenarios, provide a clear framework for understanding core AI
game-playing techniques. Key characteristics of this class are:

-   **Deterministic**: No element of chance. Game outcomes are solely
    determined by player decisions.

-   **Turn-Based**: Players move in turns, providing a structured
    sequence of actions.

-   **Two-Player**: Exactly two players, often referred to as MAX and
    MIN, who have opposing goals.

-   **Zero-Sum**: The game is purely competitive; one player's gain is
    the other's loss. The total payoff is constant (often zero, hence
    \"zero-sum\").

-   **Perfect Information**: Both players have complete knowledge of the
    game state at all times.

Examples of games fitting this category include chess, checkers,
tic-tac-toe, and Go (in its deterministic, two-player form). These games
are adversarial because the players are opponents, and they are zero-sum
because a win for one player is a loss for the other.

### Game Formulation as a Search Problem: Game Trees

Similar to other problem-solving scenarios, games can be formally
defined as search problems. Specifically, deterministic, turn-based,
two-player, zero-sum games can be represented using *game trees*. A game
tree is a specialized type of search tree tailored for game playing. The
key components of game formulation are:

-   **Initial State**: The starting configuration of the game, e.g., the
    initial board setup in chess.

-   **Player Function**: Determines which player's turn it is to move in
    a given state. Typically alternates between players (MAX, MIN, MAX,
    MIN, \...).

-   **Actions (Moves)**: Defines the set of legal moves available to the
    current player in a given state. These are the actions that
    transition the game from one state to another.

-   **Result Function (Transition Model)**: Specifies the state that
    results from making a move in the current state. In deterministic
    games, this is a single, uniquely determined state.

-   **Terminal Test**: A condition that determines when the game ends.
    Terminal states are reached when the game concludes, such as
    checkmate in chess, reaching a certain score, or filling the board.

-   **Utility Function(Objective Function or Payoff Function)**: Assigns
    a numerical value to each terminal state. This value represents the
    outcome of the game from the perspective of one player
    (conventionally MAX). In zero-sum games, a positive utility for MAX
    implies a negative utility of equal magnitude for MIN, and vice
    versa. Common utility values are:

    -   +1: Win for MAX (and loss for MIN).

    -   -1: Loss for MAX (and win for MIN).

    -   0: Draw or tie.

The game tree starts at the initial state and branches out to represent
all possible sequences of moves by both players until terminal states
are reached. Each level of the tree typically represents a turn for one
of the players.

### Utility Values in Game States: Evaluating Game Outcomes

The *utility function* is crucial for evaluating the desirability of
game states, particularly terminal states. In terminal states, the
utility value is directly determined by the game rules (win, loss, or
draw). However, for non-terminal states, we need a way to estimate their
utility, reflecting how favorable they are for a player in leading to a
win.

In deterministic, turn-based, two-player, zero-sum games, the utility
values are often defined from the perspective of one player,
conventionally called **MAX**. MAX aims to maximize the utility value,
while the opponent, called **MIN**, aims to minimize it (which is
equivalent to maximizing their own utility in a zero-sum game).

### Introduction to the Minimax Algorithm: Optimal Play in Adversarial Games

::: algorithmic

Initialize $v = -\infty$ $v = \max(v, \Call{Minimax}{Result(state, a)})$

The *Minimax algorithm* is a foundational algorithm for decision-making
in deterministic, turn-based, two-player, zero-sum games with perfect
information. It provides a way to determine the optimal move for the MAX
player, assuming that the MIN player will also play optimally to
minimize MAX's utility. Minimax is based on the principle of perfect
rationality: both players are assumed to play perfectly to achieve their
conflicting goals.

The core idea of the Minimax algorithm, as shown in Algorithm
[\[alg:minimax\]](#alg:minimax){reference-type="ref"
reference="alg:minimax"}, is recursive and involves the following steps:

1.  **Game Tree Construction**: Build a game tree starting from the
    current game state, expanding all possible moves for both players to
    a certain depth or until terminal states are reached. The depth of
    the tree explored depends on computational resources and game
    complexity. For simple games like tic-tac-toe, the entire game tree
    can be explored. For complex games like chess or Go, a limited-depth
    tree is explored, combined with evaluation functions for
    non-terminal states (discussed in the next lecture).

2.  **Utility Evaluation of Terminal States**: Evaluate the utility of
    all terminal states in the game tree using the utility function
    defined for the game (e.g., +1 for MAX win, -1 for MIN win, 0 for
    draw). These utility values are the base case for the recursion.

3.  **Utility Propagation Upwards (Backpropagation)**: Propagate the
    utility values from the terminal states upwards through the game
    tree, level by level, using the Minimax principle:

    -   **MAX Nodes (Maximizing Player's Turn)**: At nodes where it is
        MAX's turn to move (MAX nodes), MAX will choose the move that
        leads to the state with the *maximum* utility value among its
        children. The utility value of a MAX node is the maximum of the
        utility values of its successors. This reflects MAX's goal to
        maximize their outcome.

    -   **MIN Nodes (Minimizing Player's Turn)**: At nodes where it is
        MIN's turn to move (MIN nodes), MIN will choose the move that
        leads to the state with the *minimum* utility value among its
        children. The utility value of a MIN node is the minimum of the
        utility values of its successors. This reflects MIN's goal to
        minimize MAX's outcome (and thus maximize their own in a
        zero-sum game).

4.  **Optimal Move Selection**: After propagating utility values up to
    the root node (representing the current game state), the root node's
    utility value represents the best achievable outcome for MAX,
    assuming optimal play by both sides. MAX should choose the move from
    the initial state that leads to the child node with this minimax
    value. This is the optimal move according to the Minimax algorithm.

By recursively applying the maximization and minimization steps at
alternating levels of the game tree, the Minimax algorithm effectively
simulates optimal adversarial play. It determines the best move for MAX
in the current state, considering all possible responses from MIN and
assuming MIN will also choose their best moves to counter MAX.

**Key Takeaways**:

-   **Heuristic Functions and A\* Search**: We learned that heuristic
    functions are indispensable for efficient informed search. A
    well-designed heuristic can dramatically reduce the search space by
    guiding the algorithm towards promising states. Crucially,
    *admissible heuristics*, which never overestimate the true cost to
    the goal, guarantee the optimality of the A\* search algorithm,
    making it a powerful tool for finding least-cost solutions in a wide
    range of problems. The art of designing effective heuristics lies in
    balancing admissibility with informativeness to achieve both
    optimality and efficiency.

-   **Conditional Plans and AND-OR Trees for Non-Deterministic
    Environments**: In environments where actions have uncertain
    outcomes, simple action sequences are insufficient. We discovered
    that *conditional plans* are necessary, allowing agents to adapt
    their actions based on the observed outcomes. *AND-OR trees* provide
    a structured framework for representing these conditional plans,
    distinguishing between agent choices (OR nodes) and environmental
    contingencies (AND nodes). This approach enables robust planning in
    the face of uncertainty, moving beyond the limitations of
    deterministic models.

-   **Adversarial Search in Game Playing**: Game playing introduces a
    new dimension to search---the presence of an adversary. In
    competitive games, AI agents must not only plan their own moves but
    also anticipate and counteract the moves of their opponents. This
    necessitates *adversarial search* techniques, where the goal is to
    maximize one's own utility while simultaneously minimizing the
    opponent's utility. Game theory and adversarial search are
    fundamental to developing AI capable of strategic decision-making in
    competitive scenarios.

-   **Minimax Algorithm as a Foundation for Game AI**: We introduced the
    *Minimax algorithm* as a cornerstone for decision-making in
    two-player, zero-sum games. Minimax provides a recursive approach to
    determine the optimal move by exploring the game tree, evaluating
    terminal states, and propagating utility values upwards. It embodies
    the principle of optimal play against an optimal opponent, forming
    the basis for more advanced game-playing algorithms and strategies
    in AI.
