Introduction

This lecture marks our return to the fundamental concepts of search within the realm of Artificial Intelligence. Search algorithms are at the heart of problem-solving in AI, enabling agents to navigate through complex environments and find solutions to intricate problems. We will begin by revisiting the definition of a search problem, ensuring a solid understanding of its essential components: the state space, actions, transition model, goal test, and cost function. We will reinforce how these components are modeled using state space graphs and search trees, which provide visual and conceptual frameworks for our exploration.

Our primary focus in this lecture is on uninformed search algorithms. These algorithms, also known as blind search methods, operate without any additional information about the problem beyond its formal definition. They explore the search space systematically but lack any heuristic guidance that might suggest promising directions towards the goal. Despite their lack of foresight, uninformed search methods are crucial for understanding the foundations of search and are applicable in scenarios where problem-specific heuristics are unavailable or too costly to compute.

We will delve into several key uninformed search algorithms, each employing a distinct strategy for exploring the search space:

  • Depth-First Search (DFS): Explores deeply into the search space, pursuing a single path until a dead end is reached, then backtracks.

  • Breadth-First Search (BFS): Explores broadly, examining all states at the current depth level before moving to the next level, ensuring shortest path discovery in terms of steps.

  • Uniform Cost Search (UCS): Extends BFS to handle varying action costs, always expanding the node with the lowest accumulated cost from the start, guaranteeing the least-cost path.

For each algorithm, we will rigorously analyze its underlying strategy, discuss practical implementation details, and evaluate its performance based on critical properties such as completeness (guaranteeing finding a solution if one exists), optimality (finding the best solution), and computational complexity in terms of time and space. We will also discuss the conditions under which each algorithm is most effective and appropriate.

Beyond these core algorithms, we will also touch upon techniques that enhance basic uninformed search, such as iterative deepening, which combines the space efficiency of DFS with the completeness and optimality of BFS for uniform costs, and bidirectional search, which aims to accelerate search by simultaneously exploring from the start and goal states.

Finally, this lecture will serve as a bridge to the realm of informed search. We will transition by introducing the concept of heuristics – estimates of the distance to the goal – and briefly preview the Greedy Best-First Search algorithm, which leverages heuristics to guide the search process. This sets the stage for our subsequent lectures, where we will explore more sophisticated informed search techniques that utilize problem-specific knowledge to achieve greater efficiency and effectiveness in solving complex AI problems.

Search Problems and State Spaces

Defining a Search Problem: The 6 Components

As discussed in the previous lecture, a search problem is formally defined by six key components. These components provide a structured way to represent and solve problems using search algorithms.

  1. Initial State (\(S\)): The starting point of the problem, representing the agent’s initial configuration. From this state, the search process begins its quest to find a solution. For example, in a route-finding problem, the initial state could be the starting city.

  2. Actions (\(\mathcal{A}(s)\)): A function that, for any given state \(s\), returns a set of possible actions that can be executed in that state. These actions define the transitions from one state to another. In the context of driving directions, actions might be ‘drive to Sibiu’, ‘drive to Timisoara’, etc., from the current city.

  3. Transition Model (Result(\(s, a\))): This function formally defines the outcome of taking action \(a\) in state \(s\). It specifies the state \(s'\) that the agent will transition to after performing action \(a\) in state \(s\). For instance, Result(Arad, drive to Sibiu) = Sibiu.

  4. State Space (\(\mathcal{S}\)): The entirety of states reachable from the initial state through any sequence of actions. It encompasses all possible configurations the agent can be in. The state space can be conceptualized as a graph, where each state is a node, and actions are directed edges connecting these states.

  5. Goal Test (\(\mathcal{G}(s)\)): A function that determines whether a given state \(s\) is a goal state. Goal states are the desired end configurations or solutions to the problem. In our route example, \(\mathcal{G}(s)\) would check if \(s\) is ‘Bucharest’.

  6. Cost Function (\(\mathcal{C}(s, a, s')\)): Assigns a numerical cost to the path resulting from action \(a\) taken in state \(s\) leading to state \(s'\). This cost reflects the ‘expense’ of the action, which could be distance, time, resources, or any other relevant metric. Often, the cost is simplified to be associated only with the action itself, \(\mathcal{C}(a)\). For example, the cost of ‘drive to Sibiu’ from Arad might be the kilometers traveled or the time taken.

Defining these six components with precision is paramount. It allows us to transform a real-world problem into a structured format that search algorithms can process to find solutions effectively.

State Space Graphs: Visualizing the Problem

The state space graph (\(\mathcal{G}_{SS}\)) is an essential abstraction for visualizing and understanding search problems. It provides a graphical depiction of the state space \(\mathcal{S}\) and the possible transitions between states.

  • Nodes Represent States: Each node in the state space graph corresponds to a unique state within the state space \(\mathcal{S}\). These states represent the different situations or configurations the agent can be in.

  • Edges Represent Actions: Directed edges in the graph symbolize actions. A directed edge from state \(s\) to state \(s'\) exists if and only if there is an action \(a \in \mathcal{A}(s)\) that, when executed in state \(s\), results in state \(s'\), i.e., Result(\(s, a\)) = \(s'\). These edges are often labeled with the action name and its associated cost, providing a clear representation of state transitions and their expenses.

The state space graph serves as a complete map of the problem’s environment, illustrating all reachable states and the permissible transitions. Solving a search problem within this framework then becomes equivalent to discovering a path within the state space graph, starting from the node representing the initial state and ending at a node representing a goal state. The state space graph is a static representation of the problem.

Search Trees: Exploring Paths to Solutions

While the state space graph provides the problem’s blueprint, the search tree (\(\mathcal{T}\)) is the dynamic structure constructed and utilized by search algorithms to explore potential solution paths. Unlike the state space graph, which is a static, bird’s-eye view of all possibilities, the search tree is built incrementally as the algorithm navigates through the state space in search of a goal.

  • Nodes Represent Paths, Not Just States: In a search tree, each node embodies a specific path from the initial state to a particular state in the state space. A crucial distinction from the state space graph is that a single state from the state space can appear multiple times as different nodes within the search tree. Each occurrence represents a unique path leading to that state.

  • Edges Represent Actions Along a Path: Edges in the search tree, like in the state space graph, represent actions. However, in the search tree, they specifically denote the action taken at each step along a particular path from the initial state.

  • Root is the Initial State: The search tree originates from a single root node, which invariably corresponds to the initial state of the problem. From this root, the tree branches out as the search algorithm explores different sequences of actions.

The search tree can be thought of as an overlay or superimposition on the state space graph. It is generated by ‘unfolding’ paths from the initial state within the state space graph. Search algorithms operate by systematically exploring this tree, aiming to identify a path from the root node to a node that represents a goal state. The search tree is a dynamic structure that reflects the algorithm’s exploration process.

Relationship Between State Space Graphs and Search Trees

To clarify the distinction, let’s summarize the relationship between state space graphs and search trees:

  • Foundation vs. Exploration Structure: The state space graph is the foundational, underlying structure that defines the problem, while the search tree is the structure algorithmically built to explore potential solutions. The search tree is constructed based on the state space graph.

  • Paths vs. States as Nodes: Nodes in the state space graph represent states. Nodes in the search tree represent paths to states.

  • State Duplication: A state appears at most once in the state space graph. A state can appear multiple times in a search tree, each instance representing a different path to reach that state. This is because the search tree explicitly tracks the sequence of actions taken to arrive at a state.

  • Visualization and Algorithm Operation: The search tree is invaluable for visualizing the step-by-step exploration carried out by a search algorithm. It makes the operational dynamics of algorithms more transparent, whereas the state space graph is more about the problem’s overall structure.

Consider the analogy of a maze. The state space graph is like a map of the maze, showing all rooms and connections. The search tree is like the path you trace with your finger as you explore different routes from the entrance, possibly revisiting rooms via different paths.

Dealing with Infinite Search Trees and Cycles

A significant challenge arises when the state space graph contains cycles or is, in essence, infinite. In such scenarios, the search tree derived from it can also become infinite. This poses a problem for search algorithms, as they might get trapped in endless loops or explore infinitely without ever finding a solution, even if one exists within a finite number of steps.

  • Cycles and Redundancy: If the state space graph contains cycles (e.g., state A can lead to state B, which can lead back to state A), a naive search algorithm might repeatedly traverse these cycles. This results in infinite paths in the search tree, exploring the same states over and over again through different paths, leading to inefficiency and potential non-termination.

  • Infinite State Spaces: Some problems inherently possess infinite state spaces. For example, consider a problem where states are defined by real numbers, or where there’s no inherent limit to the sequence of actions. In these cases, the search tree can grow indefinitely, and algorithms must be carefully designed to manage this potential infinity and avoid exploring infinitely long paths when a solution might be found through a shorter path or in another part of the search space.

To effectively handle infinite search trees and cycles, search algorithms must incorporate mechanisms to:

  • Detect and Avoid Cycles: Implement strategies to recognize when a state is revisited along a path or through a different path. This can be achieved by maintaining a set of visited states or paths.

  • Graph Search Techniques: Employ graph search methods, which explicitly keep track of already visited states in the state space graph. By remembering visited states, the algorithm can avoid re-exploring paths that lead to these states again, thus preventing infinite loops and redundant computations. When a search algorithm considers moving to a state, it first checks if that state has already been visited. If so, and if the current path to that state is not better than the previously found path, it can prune this path, preventing further exploration down a redundant route.

  • Depth Limits: For algorithms like Depth-First Search, imposing a depth limit can prevent infinite exploration along a single path in infinite trees. While this might sacrifice completeness (the guarantee of finding a solution if it exists), it ensures termination and can be effective in practice when solutions are expected within a certain depth.

By incorporating these techniques, search algorithms can be made more robust and efficient, capable of tackling problems with cycles and potentially infinite state spaces, increasing their applicability in complex AI scenarios.

Uninformed Search Algorithms

The Concept of the Frontier: The Edge of Exploration

The frontier (\(\mathcal{F}\)), also known as the open set, is a pivotal concept in systematic search algorithms. It is the collection of states that the algorithm has discovered but has not yet explored in detail. Think of the frontier as the boundary between what is known and what is yet to be investigated in the state space. These are the states poised for expansion, sitting at the "edge" of the explored region, waiting to be selected for further examination.

  • Boundary of Explored Space: The frontier dynamically separates the state space into two regions: the explored region (\(\mathcal{E}\)), which contains states that have already been expanded, and the unexplored region, which contains states not yet reached or considered. The frontier itself is the set of states that are reachable from the explored region in one step but have not yet been moved into the explored region.

  • Selection for Expansion: Search algorithms operate iteratively by selecting a state from the frontier. This selection is based on a specific strategy that differentiates one search algorithm from another (e.g., depth-first, breadth-first, uniform cost). The chosen state is then expanded, meaning its successor states are generated and added to the frontier (if they meet certain criteria, such as not being previously visited in graph search).

  • Initialization: At the outset of the search process, the frontier is initialized to contain only the initial state (\(S\)). This signifies the starting point of our exploration into the state space. As the algorithm progresses, the frontier evolves, growing and shrinking as new states are discovered and explored.

The strategic choice of which state to expand from the frontier at each step is what fundamentally defines the search strategy and distinguishes the various search algorithms from one another. A well-managed frontier is essential for efficient and systematic exploration of the state space.

Systematic Search and Exploration: Guaranteeing Solution Discovery

Systematic search is a paradigm of search algorithm design focused on exploring the state space in a structured, methodical, and exhaustive manner. The primary goal of systematic search is to guarantee finding a solution if one exists and if it meets predefined criteria, such as being the least-cost path or satisfying certain properties. This approach contrasts sharply with random or purely heuristic-driven exploration methods that may be less reliable in finding solutions or ensuring their quality.

  • Frontier Maintenance: Systematic search algorithms crucially rely on maintaining a frontier to meticulously track the paths that are yet to be explored. The frontier acts as a queue of pending explorations, ensuring that no promising avenue is overlooked.

  • Defined Expansion Strategy: These algorithms adhere to a specific, predetermined strategy for selecting which state to expand from the frontier. This strategy is not arbitrary; it is designed to ensure a methodical and comprehensive exploration of the state space. For example, Breadth-First Search uses a strategy of expanding nodes level by level, while Depth-First Search prioritizes deeper exploration.

  • Completeness as a Goal: A key objective of systematic search is to achieve completeness. Completeness means that if a solution exists within the state space, the algorithm is guaranteed to find it. This is a critical property for applications where it’s important to know whether a solution exists and to find it if it does. Systematic exploration ensures that the algorithm does not prematurely terminate or overlook parts of the search space where a solution might reside.

Systematic search algorithms are designed to be exhaustive within the bounds of the defined search space. They methodically explore all reachable states according to their strategy, ensuring that if a solution path is present, it will eventually be discovered. This rigor makes systematic search algorithms foundational in AI problem-solving, especially in scenarios where reliability and the guarantee of finding a solution are paramount.

General Uninformed Search Algorithm: A Blueprint for Blind Exploration

To formalize the process of uninformed search, we can define a general algorithm framework that encapsulates the common structure of these methods. This General-Search algorithm provides a blueprint that can be instantiated into specific uninformed search algorithms by defining a particular strategy for frontier node selection.

Description: This algorithm provides a general framework for uninformed search strategies. It initializes a search tree and a frontier with the initial state, then iteratively expands nodes from the frontier based on a given strategy until a goal state is found or the frontier is empty.

Initialize search tree with the initial state of the problem. Initialize frontier \(\mathcal{F}\) with the initial state. Initialize expanded states set \(\mathcal{E}\) to be empty. Choose a leaf node \(n\) from \(\mathcal{F}\) according to the given strategy. if \(n\) contains a goal state then Solution path from the initial state to the goal state in \(n\). end if Add node \(n\) to the set of expanded states \(\mathcal{E}\). Expand node \(n\), generating all its successor nodes. Add the generated successor nodes to \(\mathcal{F}\). Failure.

This General-Search algorithm outlines the fundamental steps shared by many uninformed search algorithms. The critical element that distinguishes algorithms like Depth-First Search (DFS), Breadth-First Search (BFS), and Uniform Cost Search (UCS) is the specific strategy employed in line 5 to choose which node to expand from the frontier. This strategy dictates the order in which the search space is explored and consequently determines the properties of the resulting search algorithm, such as completeness, optimality, and efficiency. By plugging in different strategies, we derive different search algorithms within this general framework.

Depth-First Search (DFS)

Strategy: Exploring Deepest Nodes First - The Depth-First Approach

Depth-First Search (DFS) is a quintessential uninformed search algorithm characterized by its strategy of prioritizing the exploration of the deepest nodes within the search tree. This "depth-first" approach dictates that the algorithm will relentlessly pursue a single path as far as possible into the search tree before considering alternative paths or siblings. Imagine navigating a maze by always choosing the first path at each junction and only backtracking when you hit a dead end; this is the essence of DFS.

  • Deep Exploration Preference: DFS is designed to plunge into the depths of the search space. Starting from the initial state, it selects a successor and moves to it, then selects a successor of that state, and continues this process down a path. Only when it reaches a state with no successors, or all successors have been visited, does it consider alternatives. This is in contrast to algorithms that explore broadly across the search space.

  • Backtracking Mechanism: The hallmark of DFS is its use of backtracking. When the algorithm encounters a dead end – a state that is not a goal and has no unvisited successors – it doesn’t stop. Instead, it intelligently backtracks. Backtracking involves retreating to the most recently visited state that still has unexplored alternatives. From this point, it resumes its depth-first exploration along a new path. This systematic backtracking ensures that all reachable parts of the search space are eventually explored, at least in principle.

DFS is particularly effective in scenarios where solutions are known to exist deep within the search tree, or when memory usage is a critical constraint due to its relatively low memory footprint compared to breadth-first approaches.

Implementation using a Stack (LIFO Queue): The Stack-Based Frontier

The depth-first strategy of DFS is naturally and efficiently implemented using a stack (Last-In, First-Out queue) to manage the frontier. The stack data structure perfectly embodies the LIFO principle, ensuring that the most recently added nodes (representing deeper paths) are explored first.

  • Push Operation (Adding to Frontier): When a node is expanded in DFS, and its successors are generated, these successor nodes are pushed onto the top of the stack. This action effectively adds them to the frontier, making them available for future exploration. Because it’s a stack, the last added successors will be the first to be considered next.

  • Pop Operation (Selecting for Expansion): The node to be expanded in the next iteration of DFS is obtained by performing a pop operation from the stack. Popping from the stack retrieves the node that was most recently pushed onto it. This mechanism ensures that DFS always explores the deepest nodes first, as these are the ones most recently added to the frontier.

The stack-based implementation is not just conceptually aligned with DFS’s strategy but also contributes to its efficiency, particularly in terms of space complexity. By only needing to maintain the current path and its siblings in the stack, DFS avoids storing all explored nodes at each level, as would be required in a breadth-first approach.

Illustrative Example of DFS Execution

Example 1 (Step-by-Step DFS Execution). To illustrate the execution of DFS, let’s consider a simplified state space graph. Starting from the initial node S, DFS exploration unfolds as follows. We will use a stack to represent the frontier and trace the algorithm’s progress.

  1. Initialization: Begin at the start state S. Initialize the frontier as a stack containing only S: Frontier Stack: [S].

  2. Expand S: Pop S from the stack. Frontier Stack: []. Expand S to generate successors: D, P, E. Push successors onto the stack (in reverse order of preference, assuming left-to-right exploration, so E is on top, then P, then D to explore D first). Frontier Stack: [E, P, D].

  3. Expand D: Pop D from the stack. Frontier Stack: [E, P]. Expand D to get successors: B, C, E. Push new successors onto the stack (avoiding already visited E if using graph search, or pushing again if tree search). Let’s assume we push B and C. Frontier Stack: [E, P, C, B].

  4. Expand B: Pop B. Frontier Stack: [E, P, C]. Expand B. Let’s say B has successor A. Push A. Frontier Stack: [E, P, C, A].

  5. Expand A: Pop A. Frontier Stack: [E, P, C]. Expand A. Assume A is a dead end (no successors). Nothing is added to the stack. Frontier Stack: [E, P, C].

  6. Expand C: Pop C. Frontier Stack: [E, P]. Expand C. Assume C has successor A (already visited, or a cycle). No new nodes added to frontier in this example to keep it simple. Frontier Stack: [E, P].

  7. Expand P: Pop P. Frontier Stack: [E]. Expand P to get successor Q. Push Q. Frontier Stack: [E, Q].

  8. Expand Q: Pop Q. Frontier Stack: [E]. Expand Q. Assume Q is a dead end. Frontier Stack: [E].

  9. Expand E: Pop E. Frontier Stack: []. Expand E to get successors H, P, Q. Push new successors (avoiding already visited P, Q or pushing again if tree search). Push H. Frontier Stack: [H].

  10. Expand H: Pop H. Frontier Stack: []. Expand H to get successors R, Q. Push R (avoiding Q if visited). Frontier Stack: [R].

  11. Expand R: Pop R. Frontier Stack: []. Expand R to get successor F. Push F. Frontier Stack: [F].

  12. Expand F: Pop F. Frontier Stack: []. Expand F to get successors C, G. Push G, C. Frontier Stack: [G, C].

  13. Expand G: Pop G. Frontier Stack: [C]. Check if G is a goal state. If G is a goal state, the search is successful. The solution path can be reconstructed by tracing back parent pointers from G to S (assuming parent pointers are maintained during search).

    If G is not a goal, or if we are looking for all solutions or continuing search, we would proceed to expand C next.

This step-by-step example demonstrates the core behavior of DFS: it aggressively explores down a path, and only when it reaches a point where it can no longer proceed deeper, it backtracks to explore alternative paths.

Properties of Depth-First Search: Strengths and Limitations

To fully understand the applicability and limitations of DFS, it’s crucial to analyze its key properties: completeness, optimality, time complexity, and space complexity.

Completeness: Finding a Solution When It Exists?

Completeness refers to whether an algorithm is guaranteed to find a solution if one exists. For Depth-First Search, the answer regarding completeness is nuanced and depends on the nature of the state space.

  • Incompleteness in Infinite or Cyclic State Spaces: DFS is fundamentally not complete in state spaces that are infinite or contain cycles, unless mechanisms for cycle detection and prevention are implemented. In such spaces, DFS can get lost down an infinitely deep path, endlessly exploring without ever returning to try other potentially fruitful paths. If the search tree has paths of infinite depth, DFS might traverse one of these infinite paths indefinitely, even if a goal state is reachable via a different path.

  • Completeness in Finite State Spaces (with Graph Search): In finite state spaces, DFS can be made complete if it is augmented with graph search techniques. Graph search involves keeping track of visited states to avoid re-exploration and cycles. By remembering states already visited, DFS can prevent redundant loops and ensure that it explores every reachable state within the finite space. In this scenario, DFS will eventually either find a goal state or exhaust the entire search space, thus guaranteeing completeness.

In essence, while the depth-first approach is efficient in exploring deep paths, its inherent nature can lead to getting lost in infinite branches. Completeness can be achieved in finite spaces by adding memory to track visited states, transforming it into a graph search algorithm.

Optimality: Finding the Best Solution?

Optimality is concerned with whether a search algorithm finds the least-cost solution path, especially when multiple solutions exist. Depth-First Search is, in general, not optimal.

  • No Guarantee of Least Cost: DFS is designed to find a solution quickly, not necessarily the best solution. Because it explores deeply, it may stumble upon a goal state that is located deep in the search tree and thus corresponds to a longer, more costly path from the initial state. Meanwhile, a goal state reachable via a shorter, less costly path might exist at a shallower depth but would be explored only later, if at all, after the deeper path is exhausted.

  • First Solution Found is Not Necessarily Optimal: DFS terminates as soon as it finds the first goal state, regardless of whether there might be other goal states reachable with lower path costs. It does not inherently compare path costs to find the minimum.

If finding the optimal solution (the one with the minimum path cost) is a requirement, DFS is generally not the algorithm of choice. Algorithms like Breadth-First Search (for uniform costs) or Uniform Cost Search (for varying costs) are better suited for optimality.

Time Complexity: How Long Does it Take?

Time complexity measures how the runtime of an algorithm scales with the input size, typically expressed using Big O notation. For DFS, the time complexity in the worst case is:

  • Worst-Case Exponential Time: The time complexity of DFS is \(O(b^m)\), where:

    • \(b\) is the branching factor, representing the maximum number of successors for any state in the state space.

    • \(m\) is the maximum depth of the search tree. In the worst case, DFS might explore a path of length \(m\) before backtracking, and in extremely unfavorable scenarios, it might explore nearly the entire depth-limited search tree.

  • Potential for Infinite Time (without cycle control): In state spaces with cycles or infinite paths, without proper graph search or depth limits, DFS can run indefinitely, leading to potentially infinite runtime. The \(O(b^m)\) complexity assumes a depth-limited search or a state spaceor a state space where cycles are managed.

The exponential time complexity highlights that DFS, in its basic form, may not be suitable for problems with very large search spaces or when a guaranteed runtime within polynomial bounds is needed.

Space Complexity: How Much Memory is Needed?

Space complexity refers to the amount of memory an algorithm requires to execute. DFS is relatively space-efficient compared to some other search algorithms, particularly Breadth-First Search. The space complexity of DFS is:

  • Linear Space Complexity: The space complexity of DFS is \(O(bm)\), where:

    • \(b\) is the branching factor.

    • \(m\) is the maximum depth of the search tree.

  • Memory for Current Path: DFS primarily needs to store the nodes along the current path from the root to the deepest node in the frontier. For each node on this path, it also needs to keep track of its unexplored siblings (successors). This storage requirement is linear with respect to the depth of the search tree and the branching factor.

  • Space Efficiency Compared to BFS: This linear space complexity is a significant advantage of DFS, especially when dealing with large search spaces where memory is a limiting factor. Breadth-First Search, in contrast, typically requires storing all nodes at the current level of the search, which can lead to exponential space complexity in the worst case.

The space efficiency of DFS makes it a valuable algorithm for problems where the search space is deep but solutions might be found within a reasonable depth, and memory conservation is paramount.

Depth-First Search Algorithm in Pseudocode

To summarize, here is the pseudocode for the Depth-First Search algorithm, incorporating graph search to handle visited states and prevent cycles:

Initialize frontier as a Stack with the initial state. Initialize explored set \(\mathcal{E}\) as an empty set. Pop a node \(n\) from the Frontier (Stack). if \(n\) is a goal state then Solution path from initial state to \(n\). end if Add \(n\) to the \(\mathcal{E}\). Generate successors of \(n\). if \(s\) is not in \(\mathcal{E}\) or Frontier then Push \(s\) onto the Frontier (Stack). end if Failure.

Complexity Analysis:

  • Time Complexity: \(O(b^m)\) in the worst case, where \(b\) is the branching factor and \(m\) is themaximum depth. Can be worse without cycle control.

  • Space Complexity: \(O(bm)\), linear space complexity, due to stack storage of the current path.

This pseudocode provides a clear, step-by-step procedure for implementing DFS with graph search, highlighting its stack-based frontier management and visited state tracking for completeness in finite state spaces.

Breadth-First Search (BFS)

Strategy: Exploring Shallowest Nodes First - The Breadth-First Approach

Breadth-First Search (BFS) is another fundamental uninformed search algorithm that adopts a contrasting strategy to DFS. BFS explores the search tree in a breadth-first manner, meaning it systematically examines all nodes at the current depth level before proceeding to nodes at the next depth level. This level-by-level exploration ensures that BFS discovers solutions that are closest to the initial state in terms of the number of steps or edges traversed. Imagine exploring a tree by examining all siblings before moving to their children; this is the essence of BFS.

  • Level-by-Level Exploration: BFS operates by exploring the search space in layers. Starting from the initial state (root node), it first visits all of its immediate neighbors (depth 1 nodes). Then, it visits all neighbors of those neighbors (depth 2 nodes), and so on. This process continues level by level until a goal state is found or the entire reachable state space has been explored. This methodical approach ensures no level is skipped and that shallower paths are always explored before deeper ones.

  • Guarantee of Shortest Path (in edges for uniform costs): A key characteristic of BFS is its ability to find the shortest path in terms of the number of edges or steps from the initial state to a goal state, provided that all step costs are uniform (i.e., each action has the same cost). This is because BFS explores paths in increasing order of their length. The first time BFS encounters a goal state, it is guaranteed to have reached it via the shortest possible path from the start in terms of the number of transitions. This property is highly desirable in scenarios where minimizing the number of steps is crucial, such as in pathfinding in unweighted graphs or problems where each step has an equal cost.

BFS is particularly well-suited for problems where solutions are expected to be at shallow depths in the search tree or when finding the shortest sequence of actions is a priority.

Comparison of BFS and DFS: Contrasting Exploration Strategies

Breadth-First Search (BFS) and Depth-First Search (DFS) offer fundamentally different approaches to exploring the search space, each with its own strengths and weaknesses. Understanding their comparative characteristics is crucial for selecting the appropriate algorithm for a given problem.

  • Exploration Order: Breadth vs. Depth:

    • BFS: Broad Exploration: BFS adopts a broad exploration strategy, expanding nodes level by level. It’s like casting a wide net, exploring all possibilities at the current depth before delving deeper. This ensures that it finds the shallowest solutions first.

    • DFS: Deep Exploration: DFS, conversely, employs a deep exploration strategy, pursuing a single path to its fullest extent before backtracking. It’s akin to diving deep into one area before checking others. This can lead to finding deep solutions quickly but risks missing shallower, potentially better, solutions initially.

  • Completeness: Guarantees of Finding a Solution:

    • BFS: Complete in Most Cases: BFS is complete in both finite and infinite state spaces, provided that a proper graph search implementation is used to avoid cycles and redundant paths. Because it explores level by level, if a solution exists at some finite depth, BFS is guaranteed to find it. Even in infinite state spaces, if there’s a solution at a finite depth, BFS will find it before exploring infinitely deep paths.

    • DFS: Complete Only in Finite Spaces (with graph search): DFS is complete only in finite state spaces when graph search is implemented. In infinite spaces or spaces with cycles without cycle detection, DFS is generally not complete as it can get lost down infinite paths.

  • Optimality: Finding the Best Solution:

    • BFS: Optimal for Uniform Costs: BFS is optimal if all step costs are uniform. The first solution BFS finds is guaranteed to be the shortest path in terms of the number of steps, which is also the least-cost path when all steps cost the same.

    • DFS: Not Optimal: DFS is not optimal. It finds a solution but makes no guarantees about its path cost. It may find a deep, costly solution while shallower, cheaper solutions exist but are explored later or not at all.

  • Space Complexity: Memory Requirements:

    • BFS: Higher Space Complexity: BFS generally has a higher space complexity than DFS. This is because BFS needs to store all nodes at the current frontier level in memory to explore them before moving to the next level. In the worst case, the number of nodes at each level can grow exponentially, leading to significant memory usage, potentially \(O(b^d)\), where \(d\) is the depth of the shallowest solution.

    • DFS: Lower Space Complexity: DFS is more space-efficient, with a space complexity of \(O(bm)\), where \(m\) is the maximum depth of the search tree. It only needs to store the current path and a limited number of sibling nodes, making it suitable for deep search spaces where memory is constrained.

  • Time Complexity: Runtime Performance:

    • BFS and DFS: Exponential Time in Worst Case: In the worst-case scenario, both BFS and DFS can exhibit exponential time complexity, typically \(O(b^d)\) for BFS (where \(d\) is the depth of the shallowest solution) and \(O(b^m)\) for DFS (where \(m\) is the maximum depth explored). However, the actual runtime performance in practice can vary significantly based on the structure of the search space and the location of goal states. For BFS, time complexity is often related to the depth of the shallowest goal, while for DFS, it can be influenced by the maximum depth of the search tree.

Guidance on When to Use BFS vs. DFS: Choosing the Right Tool

The choice between BFS and DFS depends critically on the problem characteristics and the priorities of the search task. Here’s a guide to help decide when to favor one over the other:

  • When to Favor Breadth-First Search (BFS):

    • Need for Shortest Path (in steps): If finding the shortest path in terms of the number of actions or transitions is essential, and action costs are uniform, BFS is the preferred choice due to its optimality in this regard.

    • Potentially Infinite State Space with Shallow Solution: When dealing with a state space that might be infinite, but there’s reason to believe that a solution exists at a relatively shallow depth, BFS is advantageous. Its level-by-level exploration is more likely to find such shallow solutions and avoid getting lost in infinitely deep branches.

    • Optimality is a Key Requirement (uniform costs): If it’s crucial to guarantee finding the best solution in terms of path length (for uniform costs), BFS’s optimality makes it the appropriate algorithm.

  • When to Favor Depth-First Search (DFS):

    • Memory Constraints are Strict: When memory is severely limited, and the search space is potentially deep, DFS’s lower space complexity becomes a significant advantage. It can explore deep state spaces with much less memory overhead than BFS.

    • Solutions Expected to be Deep in the Tree: If there’s domain knowledge suggesting that solutions are likely to be found deep within the search tree, DFS might be more efficient in reaching these solutions quickly, as it prioritizes depth exploration.

    • Completeness is Not Absolutely Necessary, or Finite/Acyclic Space: In scenarios where completeness is not strictly required, or when the search space is known to be finite and acyclic (or when graph search is implemented to handle cycles), DFS can be a viable option, especially if space efficiency or finding deep solutions is prioritized.

In summary, BFS is often chosen for its completeness and optimality (for uniform costs), especially when shortest paths are needed and memory is less of a concern. DFS is favored when memory is limited, and the search space is deep, even if it means sacrificing optimality and completeness in certain scenarios.

Iterative Deepening Depth-First Search (ID-DFS): Best of Both Worlds?

Iterative Deepening Depth-First Search (ID-DFS) is a clever search strategy designed to synthesize the desirable properties of both BFS and DFS. ID-DFS aims to achieve the completeness and optimality of BFS (for uniform costs) while maintaining the lower space complexity of DFS. It accomplishes this by iteratively performing depth-limited DFS searches with progressively increasing depth limits.

  • Repeated Depth-Limited DFS: ID-DFS works by conducting a series of Depth-First Search explorations. However, each DFS is performed with a preset depth limit. This limit restricts how deep the DFS can go along any path in the search tree during a single iteration.

  • Iterative Increase of Depth Limit: The core idea of ID-DFS is to start with a very shallow depth limit, typically 0 or 1, and perform a DFS within that depth. If no solution is found within this depth, the depth limit is incrementally increased (e.g., to 1, then 2, then 3, and so on), and a new DFS is initiated from the start state with the increased depth limit. This iterative process continues until a goal state is found.

  • Achieving Completeness and Optimality (uniform costs): Because ID-DFS systematically explores the search space level by level, albeit through repeated DFS runs, it inherits the completeness of BFS. If a solution exists at a finite depth, ID-DFS is guaranteed to find it. Furthermore, like BFS, ID-DFS is also optimal for uniform cost searches. It finds the shallowest goal state, which corresponds to the least number of steps, and thus the least cost when all step costs are the same.

  • Space Efficiency of DFS: Despite achieving BFS-like completeness and optimality, ID-DFS retains the space efficiency characteristic of DFS. In each iteration, it performs a depth-limited DFS, which has a linear space complexity. The space complexity of ID-DFS is approximately \(O(bd)\), where \(d\) is the depth of the shallowest goal state. This is significantly better than the space complexity of BFS, especially for problems where solutions are not extremely shallow.

While ID-DFS involves repeated searches, which might seem inefficient at first glance, the overhead is often surprisingly acceptable. This is because in typical search trees, the number of nodes at each depth level grows exponentially. Therefore, the nodes explored in shallower iterations are far fewer compared to those in deeper iterations, especially as the branching factor increases. The redundancy of re-exploring shallower levels is often outweighed by the space savings and the guarantee of finding optimal solutions (for uniform costs) with completeness. ID-DFS is particularly beneficial when the depth of the solution is not known in advance, and one desires the optimality of BFS but needs to operate under tighter memory constraints.

Uniform Cost Search (UCS)

Handling Non-Uniform Action Costs: Beyond Uniform Step Costs

Uniform Cost Search (UCS) represents a significant generalization of Breadth-First Search (BFS), designed to effectively handle scenarios where action costs are non-uniform. In many real-world problems, different actions have different costs associated with them – for example, driving one mile might take longer or cost more in fuel than driving another mile. While BFS is optimal when all step costs are uniform (effectively treating each step as costing ‘1’), it falters when costs vary. UCS addresses this limitation by finding the path with the least total cost, where the cost is the sum of the costs of actions along the path, regardless of the number of steps.

Cost Function \(g(n)\): Tracking Path Cost

At the heart of UCS lies the concept of path cost, quantified by the function \(g(n)\) or \(g(n)\). This function calculates and tracks the cumulative cost of the path from the initial state to the current node \(n\).

  • Cumulative Cost: \(g(n)\) is defined as the sum of the costs of all actions taken in the sequence leading from the initial state to node \(n\). It represents the total ‘expense’ incurred in reaching state \(n\) from the starting point.

  • Initial State Cost: For the initial state (\(S\)), the path cost is, by definition, zero: \(g(S) = 0\). This is because no actions have been taken yet to reach the starting state from itself.

  • Recursive Cost Calculation: For any state \(n'\) that is a successor of state \(n\), reached via an action \(a\), the path cost to \(n'\) is calculated recursively based on the path cost to \(n\) and the cost of the action \(a\): \(g(n') = g(n) + \mathcal{C}(a)\). This recursive definition ensures that as the search progresses, the algorithm accumulates the costs of actions taken along each path, accurately reflecting the total cost to reach each state.

The path cost function \(g(n)\) is crucial for UCS as it provides the basis for prioritizing exploration. UCS aims to minimize this path cost, ensuring that it finds the most economical path to the goal.

Strategy: Expanding Nodes with the Lowest Path Cost First

The core strategy of Uniform Cost Search is to always expand the node in the frontier that has the lowest path cost \(g(n)\). This strategy is fundamentally different from BFS (which expands nodes level by level) and DFS (which expands deepest nodes first). UCS’s priority is driven by cost, not depth or order of discovery.

  • Priority Queue for Frontier Management: To efficiently implement the strategy of expanding the lowest-cost node, UCS typically employs a priority queue to manage the frontier. A priority queue is a data structure that allows efficient retrieval of the element with the highest (or lowest) priority. In UCS, the priority of each node in the frontier is given by its path cost \(g(n)\). The priority queue automatically orders the nodes in the frontier based on these costs, ensuring that the node with the minimum \(g(n)\) is always at the front and readily accessible for expansion.

  • Selection and Expansion of Lowest Cost Node: In each iteration of the UCS algorithm, the node with the minimum \(g(n)\) is extracted (removed) from the priority queue. This node is then expanded: its successors are generated, their path costs are calculated, and these successors are added to the frontier (priority queue), again maintaining the priority queue’s order based on path costs. This process repeats until a goal state is extracted from the priority queue, at which point the algorithm has found the least-cost path to a goal.

By consistently choosing to expand the node with the lowest path cost, UCS systematically explores the search space in order of increasing path cost from the start state. This ensures that when a goal state is finally selected for expansion, the path taken to reach it is guaranteed to be the least costly among all possible paths.

Properties of Uniform Cost Search: Guarantees and Characteristics

To fully appreciate the capabilities and limitations of UCS, it’s essential to examine its key properties: completeness and optimality.

Completeness: Guaranteeing Solution Discovery with Costs

Completeness in the context of UCS refers to whether the algorithm is guaranteed to find a solution if one exists, especially considering the costs associated with actions. UCS exhibits a strong guarantee of completeness under specific conditions:

  • Completeness with Positive Action Costs: UCS is complete if all action costs are positive (\(\mathcal{C}(a) > 0\) for all actions \(a\)). This condition is crucial because positive action costs ensure that path costs, \(g(n)\), are monotonically increasing as the search progresses deeper into the state space. Monotonically increasing costs prevent the algorithm from getting trapped in infinite loops or cycles of zero or negative cost, which could lead to non-termination.

  • Monotonic Cost Increase and Exploration: With positive action costs, as UCS explores, the path costs of nodes in the frontier continuously increase. This ensures that UCS will eventually explore all reachable states whose path costs are less than the cost of the optimal solution. If a solution exists, and its path cost is finite, UCS will eventually reach and expand a goal state, thus guaranteeing finding a solution if one exists and is reachable with a finite cost.

The condition of positive action costs is generally reasonable in most problem domains. It ensures that UCS systematically explores the search space in a way that guarantees progress towards higher cost paths, eventually encompassing the least-cost solution if one is reachable.

Optimality: Guaranteeing the Least-Cost Solution

Definition 1 (Optimality of Uniform Cost Search). Description: Uniform Cost Search is optimal, meaning it is guaranteed to find the least-cost path to a goal state, provided that all action costs are positive.

Optimality is a hallmark of Uniform Cost Search. UCS is specifically designed to find not just any solution, but the least-cost path to a goal state. This is a powerful property, especially in applications where minimizing cost (be it time, resources, or distance) is paramount.

  • Guarantee of Least-Cost Path: UCS is provably optimal. It always finds the least-cost path to a goal state. This guarantee stems directly from its strategy of expanding nodes in order of increasing path cost.

  • First Goal Expanded is Optimal: Because UCS expands nodes in a sequence of non-decreasing path costs, the very first time UCS expands a node that is a goal state, it is guaranteed that the path it took to reach this goal state is the lowest cost path to any goal state. Any other path to a goal that might be found later would necessarily have an equal or higher cost.

  • Systematic Cost-Based Exploration: UCS’s systematic exploration based on path costs ensures that it never overlooks a lower-cost path in favor of a higher-cost one. By always prioritizing the expansion of the node with the minimum path cost, UCS effectively ‘contours’ the search space in layers of increasing cost, ensuring that the goal is reached via the most economical route.

The optimality of UCS makes it a preferred algorithm for problems where minimizing the total cost is the primary objective, such as in route planning with varying road tolls, task scheduling with different resource costs, or any scenario where actions have associated costs that need to be minimized to achieve the goal most efficiently.

Improving Uninformed Search

Best-First Search: A General Framework

Definition 2 (Best-First Search). Description: Best-First Search is a general search algorithm framework that uses an evaluation function to order nodes in the frontier. It expands nodes based on their desirability as estimated by this function.

Best-First Search is a general search algorithm framework that encompasses several specific search algorithms, including those discussed so far and those that will be discussed later (informed search). Best-First Search uses an evaluation function \(f(n)\) to determine the order in which nodes are expanded.

Using an Evaluation Function F(n)

The evaluation function \(f(n)\) estimates the "desirability" of expanding node \(n\). Different choices of \(f(n)\) lead to different search algorithms.

  • General Strategy: Expand the node from the frontier with the lowest \(f(n)\) value.

  • Priority Queue: Best-First Search is typically implemented using a priority queue, ordered by \(f(n)\).

For uninformed search algorithms, the evaluation function is based solely on path cost from the start node or depth in the search tree, without any heuristic guidance towards the goal.

  • BFS as Best-First Search: \(f(n) = \text{depth}(n)\). Minimizing depth leads to BFS.

  • DFS as Best-First Search: \(f(n) = -\text{depth}(n)\). Maximizing depth (minimizing negative depth) leads to DFS.

  • UCS as Best-First Search: \(f(n) = g(n)\). Minimizing path cost leads to UCS.

Bidirectional Search: Searching from Both Ends

Remark. Remark 1. Bidirectional Search: This strategy can improve search efficiency by simultaneously searching forward from the initial state and backward from the goal state, potentially meeting in the middle and reducing the search space.

Bidirectional Search is a search strategy that simultaneously searches forward from the initial state and backward from the goal state, hoping to meet in the middle. This can significantly reduce the search space and time complexity in some cases.

  • Forward Search: Starts from the initial state and explores forward, as in standard search algorithms.

  • Backward Search: Starts from the goal state and explores backward, reversing actions to move towards the initial state. This requires being able to determine predecessors of states.

  • Meeting Point: The search terminates when the frontiers of the forward and backward searches intersect, meaning a path has been found connecting the initial and goal states.

Bidirectional search is effective when both initial and goal states are well-defined, and predecessors are easily computable. It can reduce the search depth from approximately \(d\) to \(d/2\), leading to significant performance gains, especially in large search spaces.

Introduction to Informed Search

Using Heuristics to Guide Search: Moving Beyond Blind Exploration

Remark. Remark 2. Informed Search: Informed search algorithms use heuristic functions to estimate the cost to reach the goal, guiding the search more efficiently than uninformed search methods.

Informed search algorithms represent a significant advancement over uninformed search methods by incorporating heuristic functions to guide the search process. Unlike uninformed search, which explores the search space blindly, informed search leverages problem-specific knowledge to estimate the promise of different search paths. This guidance allows informed algorithms to be considerably more efficient, especially when navigating large and complex state spaces where uninformed methods become impractical. The fundamental advantage of informed search lies in its ability to prioritize exploration towards regions of the state space that are likely to contain goal states, thereby focusing computational resources more effectively.

Heuristic Functions \(h(n)\): Estimating the Path to the Goal

Definition 3 (Heuristic Function). Description: A heuristic function \(h(n)\) estimates the cost of the cheapest path from state \(n\) to a goal state. It is problem-specific and domain-dependent, providing informed guidance to search algorithms.

A heuristic function \(h(n)\) is a cornerstone of informed search. It is defined as a function that takes a state \(n\) as input and produces an estimate of the cost of the cheapest path from that state to a goal state. The heuristic function, often denoted as \(h(n)\), is essentially an educated guess or approximation of the remaining cost to reach the goal.

  • Problem-Specific and Domain-Dependent: The design of a heuristic function is inherently problem-specific. An effective heuristic leverages knowledge about the particular problem domain to provide meaningful guidance. There is no one-size-fits-all heuristic; rather, heuristics must be carefully crafted based on the characteristics of each problem.

  • Informativeness and Guidance: A valuable heuristic function is one that is informative, meaning it provides useful and reasonably accurate estimates that effectively differentiate between more and less promising paths. A well-informed heuristic helps the search algorithm make intelligent choices about which states to explore next, steering it towards the goal.

  • Computational Efficiency: While informativeness is crucial, a heuristic function must also be computationally efficient to calculate. The benefit of using a heuristic to reduce search effort can be negated if the computational cost of evaluating the heuristic itself is too high. Therefore, a balance must be struck between the accuracy and the computational cost of the heuristic.

  • Admissibility: Guaranteeing Optimality for A*: For certain algorithms like A* search, a desirable property of a heuristic function is admissibility. A heuristic \(h(n)\) is admissible if it never overestimates the actual cost to reach a goal state from state \(n\). In other words, for all states \(n\), \(h(n) \leq h^*(n)\), where \(h^*(n)\) is the true minimal cost from \(n\) to the nearest goal state. Admissibility is a key condition for A* to guarantee finding optimal solutions.

Examples of heuristic functions across different problem domains include:

  • Straight-Line Distance for Navigation Problems: In route-finding problems, such as finding a path between cities on a map, the straight-line distance (Euclidean distance) between the current city and the destination city is a commonly used heuristic. This heuristic is admissible because the straight line is always the shortest possible path, and any actual road path will be at least as long.

  • Manhattan Distance for Grid-Based Puzzles: In grid-based puzzles like the \(n \times n\) sliding tile puzzle or pathfinding in grid worlds with obstacles, the Manhattan distance is frequently employed. For a tile (or agent) at position \((x_1, y_1)\) and the target position \((x_2, y_2)\), the Manhattan distance is \(|x_1 - x_2| + |y_1 - y_2|\). This heuristic is admissible in grid worlds where movement is restricted to horizontal and vertical directions, as it represents the minimum number of moves required if diagonal movements are not allowed and there are no obstacles.

  • Number of Misplaced Tiles for \(n\)-Puzzle: For the \(n\)-puzzle, a simple yet effective heuristic is the number of misplaced tiles. This counts the number of tiles that are not in their goal positions. It is admissible because each misplaced tile will require at least one move to be placed correctly.

  • Pattern Databases for Complex Puzzles: For more complex puzzles, pattern databases can be used to create highly informative heuristics. A pattern database is a precomputed lookup table that stores the optimal solution costs for certain subproblems (patterns) of the original puzzle. For example, in a 15-puzzle, a pattern database might store the optimal number of moves required to solve configurations of a subset of tiles (e.g., tiles 1-8). Heuristics derived from pattern databases are typically admissible and can significantly prune the search space.

The Greedy Best-First Search Algorithm: Prioritizing Heuristic Estimates (Preview)

Description: Greedy Best-First Search expands nodes based solely on the heuristic estimate \(h(n)\), prioritizing nodes that appear closest to the goal. It is simple and can be efficient but is neither optimal nor complete in general.

Greedy Best-First Search is a quintessential example of an informed search algorithm that operates by exclusively using the heuristic function \(h(n)\) to guide its search. It embodies a "greedy" approach by always choosing to expand the node that is estimated to be closest to the goal, as per the heuristic function \(h(n)\).

  • Evaluation Function: Solely Heuristic-Driven: In Greedy Best-First Search, the evaluation function \(f(n)\) is defined as being equal to the heuristic function: \(f(n) = h(n)\). This means that the algorithm’s decision about which node to expand next is based entirely on the heuristic estimate of the remaining cost to the goal, disregarding the path cost \(g(n)\) incurred to reach the current state.

  • Strategy: Expand the Seemingly Closest Node: The core strategy of Greedy Best-First Search is to expand the node from the frontier that has the lowest \(h(n)\) value. In each step, it selects the node that the heuristic function estimates to be nearest to a goal state and explores its successors. This process is repeated, always prioritizing the node that appears to be "best" according to the heuristic at each step.

  • Greedy Nature and Limitations: The algorithm is termed "greedy" because it makes locally optimal choices at each step, based on the immediate heuristic evaluation, without considering the broader context of the search path or the accumulated cost from the start. While this greedy approach can often lead to solutions quickly, especially when the heuristic is well-informed, it comes with significant limitations:

    • Suboptimality: Greedy Best-First Search is generally not optimal. By focusing solely on the heuristic estimate and ignoring the path cost, it may find a goal state via a suboptimal path, even if a lower-cost path exists. The locally optimal choices do not guarantee a globally optimal solution.

    • Incompleteness: In certain state spaces, Greedy Best-First Search can also be incomplete. It can get stuck in local optima or follow paths that lead away from the goal, potentially failing to find a solution even if one exists. If the heuristic misleads the search into exploring an unbounded path, it might never backtrack to explore other promising regions of the state space.

Remark. Remark 3. Greedy Best-First Search Trade-offs: While fast and efficient in some cases, Greedy Best-First Search is neither optimal nor complete in general, due to its exclusive reliance on heuristics.

Despite its limitations in terms of optimality and completeness, Greedy Best-First Search is valuable for its simplicity and potential efficiency in quickly finding solutions, especially in scenarios where approximate solutions are acceptable, or as a component within more complex search strategies. It serves as an important stepping stone towards understanding more sophisticated informed search algorithms, such as A* search, which address the limitations of greedy search by combining heuristic estimates with path costs to achieve both efficiency and optimality. # Search Problems and State Spaces

## Defining a Search Problem: The 6 Components

As discussed in the previous lecture, a search problem is formally
defined by six key components. These components provide a structured way
to represent and solve problems using search algorithms.

1.  **Initial State** ($S$): The starting point of the problem,
    representing the agent's initial configuration. From this state, the
    search process begins its quest to find a solution. For example, in
    a route-finding problem, the initial state could be the starting
    city.

2.  **Actions** ($\mathcal{A}(s)$): A function that, for any given state
    $s$, returns a set of possible actions that can be executed in that
    state. These actions define the transitions from one state to
    another. In the context of driving directions, actions might be
    'drive to Sibiu', 'drive to Timisoara', etc., from the current city.

3.  **Transition Model** (Result($s, a$)): This function formally
    defines the outcome of taking action $a$ in state $s$. It specifies
    the state $s'$ that the agent will transition to after performing
    action $a$ in state $s$. For instance, Result(Arad, drive to Sibiu)
    = Sibiu.

4.  **State Space** ($\mathcal{S}$): The entirety of states reachable
    from the initial state through any sequence of actions. It
    encompasses all possible configurations the agent can be in. The
    state space can be conceptualized as a graph, where each state is a
    node, and actions are directed edges connecting these states.

5.  **Goal Test** ($\mathcal{G}(s)$): A function that determines whether
    a given state $s$ is a goal state. Goal states are the desired end
    configurations or solutions to the problem. In our route example,
    $\mathcal{G}(s)$ would check if $s$ is 'Bucharest'.

6.  **Cost Function** ($\mathcal{C}(s, a, s')$): Assigns a numerical
    cost to the path resulting from action $a$ taken in state $s$
    leading to state $s'$. This cost reflects the 'expense' of the
    action, which could be distance, time, resources, or any other
    relevant metric. Often, the cost is simplified to be associated only
    with the action itself, $\mathcal{C}(a)$. For example, the cost of
    'drive to Sibiu' from Arad might be the kilometers traveled or the
    time taken.

Defining these six components with precision is paramount. It allows us
to transform a real-world problem into a structured format that search
algorithms can process to find solutions effectively.

## State Space Graphs: Visualizing the Problem

The **state space graph** ($\mathcal{G}_{SS}$) is an essential
abstraction for visualizing and understanding search problems. It
provides a graphical depiction of the state space $\mathcal{S}$ and the
possible transitions between states.

-   **Nodes Represent States**: Each node in the state space graph
    corresponds to a unique state within the state space $\mathcal{S}$.
    These states represent the different situations or configurations
    the agent can be in.

-   **Edges Represent Actions**: Directed edges in the graph symbolize
    actions. A directed edge from state $s$ to state $s'$ exists if and
    only if there is an action $a \in \mathcal{A}(s)$ that, when
    executed in state $s$, results in state $s'$, i.e., Result($s, a$) =
    $s'$. These edges are often labeled with the action name and its
    associated cost, providing a clear representation of state
    transitions and their expenses.

The state space graph serves as a complete map of the problem's
environment, illustrating all reachable states and the permissible
transitions. Solving a search problem within this framework then becomes
equivalent to discovering a path within the state space graph, starting
from the node representing the initial state and ending at a node
representing a goal state. The state space graph is a static
representation of the problem.

## Search Trees: Exploring Paths to Solutions

While the state space graph provides the problem's blueprint, the
**search tree** ($\mathcal{T}$) is the dynamic structure constructed and
utilized by search algorithms to explore potential solution paths.
Unlike the state space graph, which is a static, bird's-eye view of all
possibilities, the search tree is built incrementally as the algorithm
navigates through the state space in search of a goal.

-   **Nodes Represent Paths, Not Just States**: In a search tree, each
    node embodies a specific *path* from the initial state to a
    particular state in the state space. A crucial distinction from the
    state space graph is that a single state from the state space can
    appear multiple times as different nodes within the search tree.
    Each occurrence represents a unique path leading to that state.

-   **Edges Represent Actions Along a Path**: Edges in the search tree,
    like in the state space graph, represent actions. However, in the
    search tree, they specifically denote the action taken at each step
    along a particular path from the initial state.

-   **Root is the Initial State**: The search tree originates from a
    single root node, which invariably corresponds to the initial state
    of the problem. From this root, the tree branches out as the search
    algorithm explores different sequences of actions.

The search tree can be thought of as an *overlay* or *superimposition*
on the state space graph. It is generated by 'unfolding' paths from the
initial state within the state space graph. Search algorithms operate by
systematically exploring this tree, aiming to identify a path from the
root node to a node that represents a goal state. The search tree is a
dynamic structure that reflects the algorithm's exploration process.

## Relationship Between State Space Graphs and Search Trees

To clarify the distinction, let's summarize the relationship between
state space graphs and search trees:

-   **Foundation vs. Exploration Structure**: The state space graph is
    the foundational, underlying structure that defines the problem,
    while the search tree is the structure algorithmically built to
    explore potential solutions. The search tree is constructed *based
    on* the state space graph.

-   **Paths vs. States as Nodes**: Nodes in the state space graph
    represent states. Nodes in the search tree represent *paths* to
    states.

-   **State Duplication**: A state appears at most once in the state
    space graph. A state can appear multiple times in a search tree,
    each instance representing a different path to reach that state.
    This is because the search tree explicitly tracks the sequence of
    actions taken to arrive at a state.

-   **Visualization and Algorithm Operation**: The search tree is
    invaluable for visualizing the step-by-step exploration carried out
    by a search algorithm. It makes the operational dynamics of
    algorithms more transparent, whereas the state space graph is more
    about the problem's overall structure.

Consider the analogy of a maze. The state space graph is like a map of
the maze, showing all rooms and connections. The search tree is like the
path you trace with your finger as you explore different routes from the
entrance, possibly revisiting rooms via different paths.

### Dealing with Infinite Search Trees and Cycles

A significant challenge arises when the state space graph contains
cycles or is, in essence, infinite. In such scenarios, the search tree
derived from it can also become infinite. This poses a problem for
search algorithms, as they might get trapped in endless loops or explore
infinitely without ever finding a solution, even if one exists within a
finite number of steps.

-   **Cycles and Redundancy**: If the state space graph contains cycles
    (e.g., state A can lead to state B, which can lead back to state A),
    a naive search algorithm might repeatedly traverse these cycles.
    This results in infinite paths in the search tree, exploring the
    same states over and over again through different paths, leading to
    inefficiency and potential non-termination.

-   **Infinite State Spaces**: Some problems inherently possess infinite
    state spaces. For example, consider a problem where states are
    defined by real numbers, or where there's no inherent limit to the
    sequence of actions. In these cases, the search tree can grow
    indefinitely, and algorithms must be carefully designed to manage
    this potential infinity and avoid exploring infinitely long paths
    when a solution might be found through a shorter path or in another
    part of the search space.

To effectively handle infinite search trees and cycles, search
algorithms must incorporate mechanisms to:

-   **Detect and Avoid Cycles**: Implement strategies to recognize when
    a state is revisited along a path or through a different path. This
    can be achieved by maintaining a set of visited states or paths.

-   **Graph Search Techniques**: Employ **graph search** methods, which
    explicitly keep track of already visited states in the state space
    graph. By remembering visited states, the algorithm can avoid
    re-exploring paths that lead to these states again, thus preventing
    infinite loops and redundant computations. When a search algorithm
    considers moving to a state, it first checks if that state has
    already been visited. If so, and if the current path to that state
    is not better than the previously found path, it can prune this
    path, preventing further exploration down a redundant route.

-   **Depth Limits**: For algorithms like Depth-First Search, imposing a
    depth limit can prevent infinite exploration along a single path in
    infinite trees. While this might sacrifice completeness (the
    guarantee of finding a solution if it exists), it ensures
    termination and can be effective in practice when solutions are
    expected within a certain depth.

By incorporating these techniques, search algorithms can be made more
robust and efficient, capable of tackling problems with cycles and
potentially infinite state spaces, increasing their applicability in
complex AI scenarios.

# Uninformed Search Algorithms

## The Concept of the Frontier: The Edge of Exploration

The **frontier** ($\mathcal{F}$), also known as the **open set**, is a
pivotal concept in systematic search algorithms. It is the collection of
states that the algorithm has discovered but has not yet explored in
detail. Think of the frontier as the boundary between what is known and
what is yet to be investigated in the state space. These are the states
poised for expansion, sitting at the \"edge\" of the explored region,
waiting to be selected for further examination.

-   **Boundary of Explored Space**: The frontier dynamically separates
    the state space into two regions: the **explored region**
    ($\mathcal{E}$), which contains states that have already been
    expanded, and the **unexplored region**, which contains states not
    yet reached or considered. The frontier itself is the set of states
    that are reachable from the explored region in one step but have not
    yet been moved into the explored region.

-   **Selection for Expansion**: Search algorithms operate iteratively
    by selecting a state from the frontier. This selection is based on a
    specific strategy that differentiates one search algorithm from
    another (e.g., depth-first, breadth-first, uniform cost). The chosen
    state is then expanded, meaning its successor states are generated
    and added to the frontier (if they meet certain criteria, such as
    not being previously visited in graph search).

-   **Initialization**: At the outset of the search process, the
    frontier is initialized to contain only the **initial state** ($S$).
    This signifies the starting point of our exploration into the state
    space. As the algorithm progresses, the frontier evolves, growing
    and shrinking as new states are discovered and explored.

The strategic choice of which state to expand from the frontier at each
step is what fundamentally defines the search strategy and distinguishes
the various search algorithms from one another. A well-managed frontier
is essential for efficient and systematic exploration of the state
space.

## Systematic Search and Exploration: Guaranteeing Solution Discovery

**Systematic search** is a paradigm of search algorithm design focused
on exploring the state space in a structured, methodical, and exhaustive
manner. The primary goal of systematic search is to **guarantee finding
a solution** if one exists and if it meets predefined criteria, such as
being the least-cost path or satisfying certain properties. This
approach contrasts sharply with random or purely heuristic-driven
exploration methods that may be less reliable in finding solutions or
ensuring their quality.

-   **Frontier Maintenance**: Systematic search algorithms crucially
    rely on maintaining a **frontier** to meticulously track the paths
    that are yet to be explored. The frontier acts as a queue of pending
    explorations, ensuring that no promising avenue is overlooked.

-   **Defined Expansion Strategy**: These algorithms adhere to a
    specific, predetermined **strategy** for selecting which state to
    expand from the frontier. This strategy is not arbitrary; it is
    designed to ensure a methodical and comprehensive exploration of the
    state space. For example, Breadth-First Search uses a strategy of
    expanding nodes level by level, while Depth-First Search prioritizes
    deeper exploration.

-   **Completeness as a Goal**: A key objective of systematic search is
    to achieve **completeness**. Completeness means that if a solution
    exists within the state space, the algorithm is guaranteed to find
    it. This is a critical property for applications where it's
    important to know whether a solution exists and to find it if it
    does. Systematic exploration ensures that the algorithm does not
    prematurely terminate or overlook parts of the search space where a
    solution might reside.

Systematic search algorithms are designed to be exhaustive within the
bounds of the defined search space. They methodically explore all
reachable states according to their strategy, ensuring that if a
solution path is present, it will eventually be discovered. This rigor
makes systematic search algorithms foundational in AI problem-solving,
especially in scenarios where reliability and the guarantee of finding a
solution are paramount.

## General Uninformed Search Algorithm: A Blueprint for Blind Exploration

To formalize the process of uninformed search, we can define a general
algorithm framework that encapsulates the common structure of these
methods. This `General-Search` algorithm provides a blueprint that can
be instantiated into specific uninformed search algorithms by defining a
particular *strategy* for frontier node selection.

:::: tcolorbox
**Description:** This algorithm provides a general framework for

frontier with the initial state, then iteratively expands nodes from the
frontier based on a given strategy until a goal state is found or the

This `General-Search` algorithm outlines the fundamental steps shared by

distinguishes algorithms like Depth-First Search (DFS), Breadth-First

***strategy*** employed in **line 5** to choose which node to expand
from the frontier. This strategy dictates the order in which the search
space is explored and consequently determines the properties of the
resulting search algorithm, such as completeness, optimality, and
efficiency. By plugging in different strategies, we derive different
search algorithms within this general framework.

# Depth-First Search (DFS)

## Strategy: Exploring Deepest Nodes First - The Depth-First Approach

**Depth-First Search (DFS)** is a quintessential uninformed search
algorithm characterized by its strategy of prioritizing the exploration
of the deepest nodes within the search tree. This \"depth-first\"
approach dictates that the algorithm will relentlessly pursue a single
path as far as possible into the search tree before considering
alternative paths or siblings. Imagine navigating a maze by always
choosing the first path at each junction and only backtracking when you
hit a dead end; this is the essence of DFS.

-   **Deep Exploration Preference**: DFS is designed to plunge into the
    depths of the search space. Starting from the initial state, it
    selects a successor and moves to it, then selects a successor of
    that state, and continues this process down a path. Only when it
    reaches a state with no successors, or all successors have been
    visited, does it consider alternatives. This is in contrast to
    algorithms that explore broadly across the search space.

-   **Backtracking Mechanism**: The hallmark of DFS is its use of
    **backtracking**. When the algorithm encounters a **dead end** -- a
    state that is not a goal and has no unvisited successors -- it
    doesn't stop. Instead, it intelligently backtracks. Backtracking
    involves retreating to the most recently visited state that still
    has unexplored alternatives. From this point, it resumes its
    depth-first exploration along a new path. This systematic
    backtracking ensures that all reachable parts of the search space
    are eventually explored, at least in principle.

DFS is particularly effective in scenarios where solutions are known to
exist deep within the search tree, or when memory usage is a critical
constraint due to its relatively low memory footprint compared to
breadth-first approaches.

## Implementation using a Stack (LIFO Queue): The Stack-Based Frontier

The depth-first strategy of DFS is naturally and efficiently implemented
using a **stack** (Last-In, First-Out queue) to manage the frontier. The
stack data structure perfectly embodies the LIFO principle, ensuring
that the most recently added nodes (representing deeper paths) are
explored first.

-   **Push Operation (Adding to Frontier)**: When a node is expanded in
    DFS, and its successors are generated, these successor nodes are
    **pushed** onto the top of the stack. This action effectively adds
    them to the frontier, making them available for future exploration.
    Because it's a stack, the last added successors will be the first to
    be considered next.

-   **Pop Operation (Selecting for Expansion)**: The node to be expanded
    in the next iteration of DFS is obtained by performing a **pop**
    operation from the stack. Popping from the stack retrieves the node
    that was most recently pushed onto it. This mechanism ensures that
    DFS always explores the deepest nodes first, as these are the ones
    most recently added to the frontier.

The stack-based implementation is not just conceptually aligned with
DFS's strategy but also contributes to its efficiency, particularly in
terms of space complexity. By only needing to maintain the current path
and its siblings in the stack, DFS avoids storing all explored nodes at
each level, as would be required in a breadth-first approach.

## Illustrative Example of DFS Execution

::: example
**Example 1** (Step-by-Step DFS Execution). To illustrate the execution
of DFS, let's consider a simplified state space graph. Starting from the
initial node S, DFS exploration unfolds as follows. We will use a stack
to represent the frontier and trace the algorithm's progress.

1.  **Initialization**: Begin at the start state S. Initialize the
    frontier as a stack containing only S: `Frontier Stack: [S]`.

2.  **Expand S**: Pop S from the stack. `Frontier Stack: []`. Expand S
    to generate successors: D, P, E. Push successors onto the stack (in
    reverse order of preference, assuming left-to-right exploration, so
    E is on top, then P, then D to explore D first).
    `Frontier Stack: [E, P, D]`.

3.  **Expand D**: Pop D from the stack. `Frontier Stack: [E, P]`. Expand
    D to get successors: B, C, E. Push new successors onto the stack
    (avoiding already visited E if using graph search, or pushing again
    if tree search). Let's assume we push B and C.
    `Frontier Stack: [E, P, C, B]`.

4.  **Expand B**: Pop B. `Frontier Stack: [E, P, C]`. Expand B. Let's
    say B has successor A. Push A. `Frontier Stack: [E, P, C, A]`.

5.  **Expand A**: Pop A. `Frontier Stack: [E, P, C]`. Expand A. Assume A
    is a dead end (no successors). Nothing is added to the stack.
    `Frontier Stack: [E, P, C]`.

6.  **Expand C**: Pop C. `Frontier Stack: [E, P]`. Expand C. Assume C
    has successor A (already visited, or a cycle). No new nodes added to
    frontier in this example to keep it simple.
    `Frontier Stack: [E, P]`.

7.  **Expand P**: Pop P. `Frontier Stack: [E]`. Expand P to get
    successor Q. Push Q. `Frontier Stack: [E, Q]`.

8.  **Expand Q**: Pop Q. `Frontier Stack: [E]`. Expand Q. Assume Q is a
    dead end. `Frontier Stack: [E]`.

9.  **Expand E**: Pop E. `Frontier Stack: []`. Expand E to get
    successors H, P, Q. Push new successors (avoiding already visited P,
    Q or pushing again if tree search). Push H. `Frontier Stack: [H]`.

10. **Expand H**: Pop H. `Frontier Stack: []`. Expand H to get
    successors R, Q. Push R (avoiding Q if visited).
    `Frontier Stack: [R]`.

11. **Expand R**: Pop R. `Frontier Stack: []`. Expand R to get
    successor F. Push F. `Frontier Stack: [F]`.

12. **Expand F**: Pop F. `Frontier Stack: []`. Expand F to get
    successors C, G. Push G, C. `Frontier Stack: [G, C]`.

13. **Expand G**: Pop G. `Frontier Stack: [C]`. Check if G is a goal
    state. **If G is a goal state**, the search is successful. The
    solution path can be reconstructed by tracing back parent pointers
    from G to S (assuming parent pointers are maintained during search).

    If G is not a goal, or if we are looking for all solutions or
    continuing search, we would proceed to expand C next.

This step-by-step example demonstrates the core behavior of DFS: it
aggressively explores down a path, and only when it reaches a point
where it can no longer proceed deeper, it backtracks to explore
alternative paths.
:::

## Properties of Depth-First Search: Strengths and Limitations

To fully understand the applicability and limitations of DFS, it's
crucial to analyze its key properties: completeness, optimality, time
complexity, and space complexity.

### Completeness: Finding a Solution When It Exists?

**Completeness** refers to whether an algorithm is guaranteed to find a
solution if one exists. For Depth-First Search, the answer regarding
completeness is nuanced and depends on the nature of the state space.

-   **Incompleteness in Infinite or Cyclic State Spaces**: DFS is
    fundamentally **not complete** in state spaces that are infinite or
    contain cycles, **unless** mechanisms for cycle detection and
    prevention are implemented. In such spaces, DFS can get lost down an
    infinitely deep path, endlessly exploring without ever returning to
    try other potentially fruitful paths. If the search tree has paths
    of infinite depth, DFS might traverse one of these infinite paths
    indefinitely, even if a goal state is reachable via a different
    path.

-   **Completeness in Finite State Spaces (with Graph Search)**: In
    **finite state spaces**, DFS can be made complete if it is augmented
    with **graph search** techniques. Graph search involves keeping
    track of visited states to avoid re-exploration and cycles. By
    remembering states already visited, DFS can prevent redundant loops
    and ensure that it explores every reachable state within the finite
    space. In this scenario, DFS will eventually either find a goal
    state or exhaust the entire search space, thus guaranteeing
    completeness.

In essence, while the depth-first approach is efficient in exploring
deep paths, its inherent nature can lead to getting lost in infinite
branches. Completeness can be achieved in finite spaces by adding memory
to track visited states, transforming it into a graph search algorithm.

### Optimality: Finding the Best Solution?

**Optimality** is concerned with whether a search algorithm finds the
least-cost solution path, especially when multiple solutions exist.
Depth-First Search is, in general, **not optimal**.

-   **No Guarantee of Least Cost**: DFS is designed to find *a* solution
    quickly, not necessarily the *best* solution. Because it explores
    deeply, it may stumble upon a goal state that is located deep in the
    search tree and thus corresponds to a longer, more costly path from
    the initial state. Meanwhile, a goal state reachable via a shorter,
    less costly path might exist at a shallower depth but would be
    explored only later, if at all, after the deeper path is exhausted.

-   **First Solution Found is Not Necessarily Optimal**: DFS terminates
    as soon as it finds the first goal state, regardless of whether
    there might be other goal states reachable with lower path costs. It
    does not inherently compare path costs to find the minimum.

If finding the optimal solution (the one with the minimum path cost) is
a requirement, DFS is generally not the algorithm of choice. Algorithms
like Breadth-First Search (for uniform costs) or Uniform Cost Search
(for varying costs) are better suited for optimality.

### Time Complexity: How Long Does it Take?

**Time complexity** measures how the runtime of an algorithm scales with
the input size, typically expressed using Big O notation. For DFS, the
time complexity in the worst case is:

-   **Worst-Case Exponential Time**: The time complexity of DFS is
    $O(b^m)$, where:

    -   $b$ is the **branching factor**, representing the maximum number
        of successors for any state in the state space.

    -   $m$ is the **maximum depth** of the search tree. In the worst
        case, DFS might explore a path of length $m$ before
        backtracking, and in extremely unfavorable scenarios, it might
        explore nearly the entire depth-limited search tree.

-   **Potential for Infinite Time (without cycle control)**: In state
    spaces with cycles or infinite paths, without proper graph search or
    depth limits, DFS can run indefinitely, leading to potentially
    infinite runtime. The $O(b^m)$ complexity assumes a depth-limited
    search or a state spaceor a state space where cycles are managed.

The exponential time complexity highlights that DFS, in its basic form,
may not be suitable for problems with very large search spaces or when a
guaranteed runtime within polynomial bounds is needed.

### Space Complexity: How Much Memory is Needed?

**Space complexity** refers to the amount of memory an algorithm
requires to execute. DFS is relatively space-efficient compared to some
other search algorithms, particularly Breadth-First Search. The space
complexity of DFS is:

-   **Linear Space Complexity**: The space complexity of DFS is $O(bm)$,
    where:

    -   $b$ is the branching factor.

    -   $m$ is the maximum depth of the search tree.

-   **Memory for Current Path**: DFS primarily needs to store the nodes
    along the current path from the root to the deepest node in the
    frontier. For each node on this path, it also needs to keep track of
    its unexplored siblings (successors). This storage requirement is
    linear with respect to the depth of the search tree and the
    branching factor.

-   **Space Efficiency Compared to BFS**: This linear space complexity
    is a significant advantage of DFS, especially when dealing with
    large search spaces where memory is a limiting factor. Breadth-First
    Search, in contrast, typically requires storing all nodes at the
    current level of the search, which can lead to exponential space
    complexity in the worst case.

The space efficiency of DFS makes it a valuable algorithm for problems
where the search space is deep but solutions might be found within a
reasonable depth, and memory conservation is paramount.

## Depth-First Search Algorithm in Pseudocode

To summarize, here is the pseudocode for the Depth-First Search
algorithm, incorporating graph search to handle visited states and
prevent cycles:

:::: tcolorbox
::: algorithmic
Initialize **frontier** as a Stack with the initial state. Initialize

# Breadth-First Search (BFS)

## Strategy: Exploring Shallowest Nodes First - The Breadth-First Approach

**Breadth-First Search (BFS)** is another fundamental uninformed search
algorithm that adopts a contrasting strategy to DFS. BFS explores the
search tree in a **breadth-first** manner, meaning it systematically
examines all nodes at the current depth level before proceeding to nodes
at the next depth level. This level-by-level exploration ensures that
BFS discovers solutions that are closest to the initial state in terms
of the number of steps or edges traversed. Imagine exploring a tree by
examining all siblings before moving to their children; this is the
essence of BFS.

-   **Level-by-Level Exploration**: BFS operates by exploring the search
    space in layers. Starting from the initial state (root node), it
    first visits all of its immediate neighbors (depth 1 nodes). Then,
    it visits all neighbors of those neighbors (depth 2 nodes), and so
    on. This process continues level by level until a goal state is
    found or the entire reachable state space has been explored. This
    methodical approach ensures no level is skipped and that shallower
    paths are always explored before deeper ones.

-   **Guarantee of Shortest Path (in edges for uniform costs)**: A key
    characteristic of BFS is its ability to find the **shortest path**
    in terms of the number of edges or steps from the initial state to a
    goal state, **provided that all step costs are uniform** (i.e., each
    action has the same cost). This is because BFS explores paths in
    increasing order of their length. The first time BFS encounters a
    goal state, it is guaranteed to have reached it via the shortest
    possible path from the start in terms of the number of transitions.
    This property is highly desirable in scenarios where minimizing the
    number of steps is crucial, such as in pathfinding in unweighted
    graphs or problems where each step has an equal cost.

BFS is particularly well-suited for problems where solutions are
expected to be at shallow depths in the search tree or when finding the
shortest sequence of actions is a priority.

## Comparison of BFS and DFS: Contrasting Exploration Strategies

Breadth-First Search (BFS) and Depth-First Search (DFS) offer
fundamentally different approaches to exploring the search space, each
with its own strengths and weaknesses. Understanding their comparative
characteristics is crucial for selecting the appropriate algorithm for a
given problem.

-   **Exploration Order: Breadth vs. Depth**:

    -   **BFS: Broad Exploration**: BFS adopts a **broad** exploration
        strategy, expanding nodes level by level. It's like casting a
        wide net, exploring all possibilities at the current depth
        before delving deeper. This ensures that it finds the shallowest
        solutions first.

    -   **DFS: Deep Exploration**: DFS, conversely, employs a **deep**
        exploration strategy, pursuing a single path to its fullest
        extent before backtracking. It's akin to diving deep into one
        area before checking others. This can lead to finding deep
        solutions quickly but risks missing shallower, potentially
        better, solutions initially.

-   **Completeness: Guarantees of Finding a Solution**:

    -   **BFS: Complete in Most Cases**: BFS is **complete** in both
        finite and **infinite state spaces**, provided that a proper
        graph search implementation is used to avoid cycles and
        redundant paths. Because it explores level by level, if a
        solution exists at some finite depth, BFS is guaranteed to find
        it. Even in infinite state spaces, if there's a solution at a
        finite depth, BFS will find it before exploring infinitely deep
        paths.

    -   **DFS: Complete Only in Finite Spaces (with graph search)**: DFS
        is complete only in **finite state spaces** when graph search is
        implemented. In infinite spaces or spaces with cycles without
        cycle detection, DFS is generally **not complete** as it can get
        lost down infinite paths.

-   **Optimality: Finding the Best Solution**:

    -   **BFS: Optimal for Uniform Costs**: BFS is **optimal** if all
        step costs are **uniform**. The first solution BFS finds is
        guaranteed to be the shortest path in terms of the number of
        steps, which is also the least-cost path when all steps cost the
        same.

    -   **DFS: Not Optimal**: DFS is **not optimal**. It finds a
        solution but makes no guarantees about its path cost. It may
        find a deep, costly solution while shallower, cheaper solutions
        exist but are explored later or not at all.

-   **Space Complexity: Memory Requirements**:

    -   **BFS: Higher Space Complexity**: BFS generally has a **higher
        space complexity** than DFS. This is because BFS needs to store
        all nodes at the current frontier level in memory to explore
        them before moving to the next level. In the worst case, the
        number of nodes at each level can grow exponentially, leading to
        significant memory usage, potentially $O(b^d)$, where $d$ is the
        depth of the shallowest solution.

    -   **DFS: Lower Space Complexity**: DFS is more
        **space-efficient**, with a space complexity of $O(bm)$, where
        $m$ is the maximum depth of the search tree. It only needs to
        store the current path and a limited number of sibling nodes,
        making it suitable for deep search spaces where memory is
        constrained.

-   **Time Complexity: Runtime Performance**:

    -   **BFS and DFS: Exponential Time in Worst Case**: In the
        worst-case scenario, both BFS and DFS can exhibit **exponential
        time complexity**, typically $O(b^d)$ for BFS (where $d$ is the
        depth of the shallowest solution) and $O(b^m)$ for DFS (where
        $m$ is the maximum depth explored). However, the actual runtime
        performance in practice can vary significantly based on the
        structure of the search space and the location of goal states.
        For BFS, time complexity is often related to the depth of the
        shallowest goal, while for DFS, it can be influenced by the
        maximum depth of the search tree.

### Guidance on When to Use BFS vs. DFS: Choosing the Right Tool

The choice between BFS and DFS depends critically on the problem
characteristics and the priorities of the search task. Here's a guide to
help decide when to favor one over the other:

-   **When to Favor Breadth-First Search (BFS)**:

    -   **Need for Shortest Path (in steps)**: If finding the shortest
        path in terms of the number of actions or transitions is
        essential, and action costs are uniform, BFS is the preferred
        choice due to its optimality in this regard.

    -   **Potentially Infinite State Space with Shallow Solution**: When
        dealing with a state space that might be infinite, but there's
        reason to believe that a solution exists at a relatively shallow
        depth, BFS is advantageous. Its level-by-level exploration is
        more likely to find such shallow solutions and avoid getting
        lost in infinitely deep branches.

    -   **Optimality is a Key Requirement (uniform costs)**: If it's
        crucial to guarantee finding the best solution in terms of path
        length (for uniform costs), BFS's optimality makes it the
        appropriate algorithm.

-   **When to Favor Depth-First Search (DFS)**:

    -   **Memory Constraints are Strict**: When memory is severely
        limited, and the search space is potentially deep, DFS's lower
        space complexity becomes a significant advantage. It can explore
        deep state spaces with much less memory overhead than BFS.

    -   **Solutions Expected to be Deep in the Tree**: If there's domain
        knowledge suggesting that solutions are likely to be found deep
        within the search tree, DFS might be more efficient in reaching
        these solutions quickly, as it prioritizes depth exploration.

    -   **Completeness is Not Absolutely Necessary, or Finite/Acyclic
        Space**: In scenarios where completeness is not strictly
        required, or when the search space is known to be finite and
        acyclic (or when graph search is implemented to handle cycles),
        DFS can be a viable option, especially if space efficiency or
        finding deep solutions is prioritized.

In summary, BFS is often chosen for its completeness and optimality (for
uniform costs), especially when shortest paths are needed and memory is
less of a concern. DFS is favored when memory is limited, and the search
space is deep, even if it means sacrificing optimality and completeness
in certain scenarios.

## Iterative Deepening Depth-First Search (ID-DFS): Best of Both Worlds?

**Iterative Deepening Depth-First Search (ID-DFS)** is a clever search
strategy designed to synthesize the desirable properties of both BFS and
DFS. ID-DFS aims to achieve the **completeness and optimality of BFS
(for uniform costs)** while maintaining the **lower space complexity of
DFS**. It accomplishes this by iteratively performing depth-limited DFS
searches with progressively increasing depth limits.

-   **Repeated Depth-Limited DFS**: ID-DFS works by conducting a series
    of Depth-First Search explorations. However, each DFS is performed
    with a preset **depth limit**. This limit restricts how deep the DFS
    can go along any path in the search tree during a single iteration.

-   **Iterative Increase of Depth Limit**: The core idea of ID-DFS is to
    start with a very shallow depth limit, typically 0 or 1, and perform
    a DFS within that depth. If no solution is found within this depth,
    the depth limit is incrementally increased (e.g., to 1, then 2, then
    3, and so on), and a new DFS is initiated from the start state with
    the increased depth limit. This iterative process continues until a
    goal state is found.

-   **Achieving Completeness and Optimality (uniform costs)**: Because
    ID-DFS systematically explores the search space level by level,
    albeit through repeated DFS runs, it inherits the **completeness**
    of BFS. If a solution exists at a finite depth, ID-DFS is guaranteed
    to find it. Furthermore, like BFS, ID-DFS is also **optimal for
    uniform cost searches**. It finds the shallowest goal state, which
    corresponds to the least number of steps, and thus the least cost
    when all step costs are the same.

-   **Space Efficiency of DFS**: Despite achieving BFS-like completeness
    and optimality, ID-DFS retains the **space efficiency**
    characteristic of DFS. In each iteration, it performs a
    depth-limited DFS, which has a linear space complexity. The space
    complexity of ID-DFS is approximately $O(bd)$, where $d$ is the
    depth of the shallowest goal state. This is significantly better
    than the space complexity of BFS, especially for problems where
    solutions are not extremely shallow.

While ID-DFS involves repeated searches, which might seem inefficient at
first glance, the overhead is often surprisingly acceptable. This is
because in typical search trees, the number of nodes at each depth level
grows exponentially. Therefore, the nodes explored in shallower
iterations are far fewer compared to those in deeper iterations,
especially as the branching factor increases. The redundancy of
re-exploring shallower levels is often outweighed by the space savings
and the guarantee of finding optimal solutions (for uniform costs) with
completeness. ID-DFS is particularly beneficial when the depth of the
solution is not known in advance, and one desires the optimality of BFS
but needs to operate under tighter memory constraints.

## Breadth-First Search Algorithm in Pseudocode

To formalize the BFS strategy, here is the pseudocode for the
Breadth-First Search algorithm, incorporating graph search to manage
visited states and prevent cycles:

:::: tcolorbox
::: algorithmic

**explored set** $\mathcal{E}$ as an empty set. Dequeue a node $n$ from

-   **Space Complexity:** $O(b^d)$, exponential space complexity, due to
    queue storage of nodes at each level.

This pseudocode clearly illustrates the step-by-step process of BFS with
graph search, emphasizing its queue-based frontier management and the
use of a visited set to ensure completeness and efficiency by avoiding
redundant explorations.

# Uniform Cost Search (UCS)

## Handling Non-Uniform Action Costs: Beyond Uniform Step Costs

**Uniform Cost Search (UCS)** represents a significant generalization of
Breadth-First Search (BFS), designed to effectively handle scenarios
where **action costs are non-uniform**. In many real-world problems,
different actions have different costs associated with them -- for
example, driving one mile might take longer or cost more in fuel than
driving another mile. While BFS is optimal when all step costs are
uniform (effectively treating each step as costing '1'), it falters when
costs vary. UCS addresses this limitation by finding the path with the
**least total cost**, where the cost is the sum of the costs of actions
along the path, regardless of the number of steps.

## Cost Function $g(n)$: Tracking Path Cost

At the heart of UCS lies the concept of **path cost**, quantified by the
function $g(n)$ or $g(n)$. This function calculates and tracks the
cumulative cost of the path from the initial state to the current node
$n$.

-   **Cumulative Cost**: $g(n)$ is defined as the sum of the costs of
    all actions taken in the sequence leading from the initial state to
    node $n$. It represents the total 'expense' incurred in reaching
    state $n$ from the starting point.

-   **Initial State Cost**: For the **initial state** ($S$), the path
    cost is, by definition, zero: $g(S) = 0$. This is because no actions
    have been taken yet to reach the starting state from itself.

-   **Recursive Cost Calculation**: For any state $n'$ that is a
    successor of state $n$, reached via an action $a$, the path cost to
    $n'$ is calculated recursively based on the path cost to $n$ and the
    cost of the action $a$: $g(n') = g(n) + \mathcal{C}(a)$. This
    recursive definition ensures that as the search progresses, the
    algorithm accumulates the costs of actions taken along each path,
    accurately reflecting the total cost to reach each state.

The path cost function $g(n)$ is crucial for UCS as it provides the
basis for prioritizing exploration. UCS aims to minimize this path cost,
ensuring that it finds the most economical path to the goal.

## Strategy: Expanding Nodes with the Lowest Path Cost First

The core strategy of Uniform Cost Search is to always **expand the node
in the frontier that has the lowest path cost** $g(n)$. This strategy is
fundamentally different from BFS (which expands nodes level by level)
and DFS (which expands deepest nodes first). UCS's priority is driven by
cost, not depth or order of discovery.

-   **Priority Queue for Frontier Management**: To efficiently implement
    the strategy of expanding the lowest-cost node, UCS typically
    employs a **priority queue** to manage the frontier. A priority
    queue is a data structure that allows efficient retrieval of the
    element with the highest (or lowest) priority. In UCS, the priority
    of each node in the frontier is given by its path cost $g(n)$. The
    priority queue automatically orders the nodes in the frontier based
    on these costs, ensuring that the node with the minimum $g(n)$ is
    always at the front and readily accessible for expansion.

-   **Selection and Expansion of Lowest Cost Node**: In each iteration
    of the UCS algorithm, the node with the **minimum $g(n)$** is
    extracted (removed) from the priority queue. This node is then
    expanded: its successors are generated, their path costs are
    calculated, and these successors are added to the frontier (priority
    queue), again maintaining the priority queue's order based on path
    costs. This process repeats until a goal state is extracted from the
    priority queue, at which point the algorithm has found the
    least-cost path to a goal.

By consistently choosing to expand the node with the lowest path cost,
UCS systematically explores the search space in order of increasing path
cost from the start state. This ensures that when a goal state is
finally selected for expansion, the path taken to reach it is guaranteed
to be the least costly among all possible paths.

## Properties of Uniform Cost Search: Guarantees and Characteristics

To fully appreciate the capabilities and limitations of UCS, it's
essential to examine its key properties: completeness and optimality.

### Completeness: Guaranteeing Solution Discovery with Costs

**Completeness** in the context of UCS refers to whether the algorithm
is guaranteed to find a solution if one exists, especially considering
the costs associated with actions. UCS exhibits a strong guarantee of
completeness under specific conditions:

-   **Completeness with Positive Action Costs**: UCS is **complete** if
    all action costs are **positive** ($\mathcal{C}(a) > 0$ for all
    actions $a$). This condition is crucial because positive action
    costs ensure that path costs, $g(n)$, are monotonically increasing
    as the search progresses deeper into the state space. Monotonically
    increasing costs prevent the algorithm from getting trapped in
    infinite loops or cycles of zero or negative cost, which could lead
    to non-termination.

-   **Monotonic Cost Increase and Exploration**: With positive action
    costs, as UCS explores, the path costs of nodes in the frontier
    continuously increase. This ensures that UCS will eventually explore
    all reachable states whose path costs are less than the cost of the
    optimal solution. If a solution exists, and its path cost is finite,
    UCS will eventually reach and expand a goal state, thus guaranteeing
    finding a solution if one exists and is reachable with a finite
    cost.

The condition of positive action costs is generally reasonable in most
problem domains. It ensures that UCS systematically explores the search
space in a way that guarantees progress towards higher cost paths,
eventually encompassing the least-cost solution if one is reachable.

### Optimality: Guaranteeing the Least-Cost Solution

::: definition
**Definition 1** (Optimality of Uniform Cost Search). **Description:**
Uniform Cost Search is optimal, meaning it is guaranteed to find the
least-cost path to a goal state, provided that all action costs are
positive.
:::

**Optimality** is a hallmark of Uniform Cost Search. UCS is specifically
designed to find not just any solution, but the **least-cost path** to a
goal state. This is a powerful property, especially in applications
where minimizing cost (be it time, resources, or distance) is paramount.

-   **Guarantee of Least-Cost Path**: UCS is provably **optimal**. It
    always finds the least-cost path to a goal state. This guarantee
    stems directly from its strategy of expanding nodes in order of
    **increasing path cost**.

-   **First Goal Expanded is Optimal**: Because UCS expands nodes in a
    sequence of non-decreasing path costs, the very **first time UCS
    expands a node that is a goal state**, it is guaranteed that the
    path it took to reach this goal state is the **lowest cost path** to
    any goal state. Any other path to a goal that might be found later
    would necessarily have an equal or higher cost.

-   **Systematic Cost-Based Exploration**: UCS's systematic exploration
    based on path costs ensures that it never overlooks a lower-cost
    path in favor of a higher-cost one. By always prioritizing the
    expansion of the node with the minimum path cost, UCS effectively
    'contours' the search space in layers of increasing cost, ensuring
    that the goal is reached via the most economical route.

The optimality of UCS makes it a preferred algorithm for problems where
minimizing the total cost is the primary objective, such as in route
planning with varying road tolls, task scheduling with different
resource costs, or any scenario where actions have associated costs that
need to be minimized to achieve the goal most efficiently.

# Improving Uninformed Search

## Best-First Search: A General Framework

::: definition
**Definition 2** (Best-First Search). **Description:** Best-First Search
is a general search algorithm framework that uses an evaluation function
to order nodes in the frontier. It expands nodes based on their
desirability as estimated by this function.
:::

**Best-First Search** is a general search algorithm framework that
encompasses several specific search algorithms, including those
discussed so far and those that will be discussed later (informed
search). Best-First Search uses an **evaluation function** $f(n)$ to
determine the order in which nodes are expanded.

### Using an Evaluation Function F(n)

The evaluation function $f(n)$ estimates the \"desirability\" of
expanding node $n$. Different choices of $f(n)$ lead to different search
algorithms.

-   **General Strategy**: Expand the node from the frontier with the
    lowest $f(n)$ value.

-   **Priority Queue**: Best-First Search is typically implemented using
    a priority queue, ordered by $f(n)$.

For uninformed search algorithms, the evaluation function is based
solely on path cost from the start node or depth in the search tree,
without any heuristic guidance towards the goal.

-   **BFS as Best-First Search**: $f(n) = \text{depth}(n)$. Minimizing
    depth leads to BFS.

-   **DFS as Best-First Search**: $f(n) = -\text{depth}(n)$. Maximizing
    depth (minimizing negative depth) leads to DFS.

-   **UCS as Best-First Search**: $f(n) = g(n)$. Minimizing path cost
    leads to UCS.

## Bidirectional Search: Searching from Both Ends

::: remark
**Remark 1**. **Bidirectional Search:** This strategy can improve search
efficiency by simultaneously searching forward from the initial state
and backward from the goal state, potentially meeting in the middle and
reducing the search space.
:::

**Bidirectional Search** is a search strategy that simultaneously
searches forward from the initial state and backward from the goal
state, hoping to meet in the middle. This can significantly reduce the
search space and time complexity in some cases.

-   **Forward Search**: Starts from the initial state and explores
    forward, as in standard search algorithms.

-   **Backward Search**: Starts from the goal state and explores
    backward, reversing actions to move towards the initial state. This
    requires being able to determine predecessors of states.

-   **Meeting Point**: The search terminates when the frontiers of the
    forward and backward searches intersect, meaning a path has been
    found connecting the initial and goal states.

Bidirectional search is effective when both initial and goal states are
well-defined, and predecessors are easily computable. It can reduce the
search depth from approximately $d$ to $d/2$, leading to significant
performance gains, especially in large search spaces.

# Introduction to Informed Search

## Using Heuristics to Guide Search: Moving Beyond Blind Exploration

::: remark
**Remark 2**. **Informed Search:** Informed search algorithms use
heuristic functions to estimate the cost to reach the goal, guiding the
search more efficiently than uninformed search methods.
:::

**Informed search algorithms** represent a significant advancement over
uninformed search methods by incorporating **heuristic functions** to
guide the search process. Unlike uninformed search, which explores the
search space blindly, informed search leverages problem-specific
knowledge to estimate the promise of different search paths. This
guidance allows informed algorithms to be considerably more efficient,
especially when navigating large and complex state spaces where
uninformed methods become impractical. The fundamental advantage of
informed search lies in its ability to **prioritize exploration**
towards regions of the state space that are likely to contain goal
states, thereby focusing computational resources more effectively.

## Heuristic Functions $h(n)$: Estimating the Path to the Goal

::: definition
**Definition 3** (Heuristic Function). **Description:** A heuristic
function $h(n)$ estimates the cost of the cheapest path from state $n$
to a goal state. It is problem-specific and domain-dependent, providing
informed guidance to search algorithms.
:::

A **heuristic function** $h(n)$ is a cornerstone of informed search. It
is defined as a function that takes a state $n$ as input and produces an
**estimate** of the cost of the cheapest path from that state to a goal
state. The heuristic function, often denoted as $h(n)$, is essentially
an educated guess or approximation of the remaining cost to reach the
goal.

-   **Problem-Specific and Domain-Dependent**: The design of a heuristic
    function is inherently **problem-specific**. An effective heuristic
    leverages knowledge about the particular problem domain to provide
    meaningful guidance. There is no one-size-fits-all heuristic;
    rather, heuristics must be carefully crafted based on the
    characteristics of each problem.

-   **Informativeness and Guidance**: A valuable heuristic function is
    one that is **informative**, meaning it provides useful and
    reasonably accurate estimates that effectively differentiate between
    more and less promising paths. A well-informed heuristic helps the
    search algorithm make intelligent choices about which states to
    explore next, steering it towards the goal.

-   **Computational Efficiency**: While informativeness is crucial, a
    heuristic function must also be **computationally efficient** to
    calculate. The benefit of using a heuristic to reduce search effort
    can be negated if the computational cost of evaluating the heuristic
    itself is too high. Therefore, a balance must be struck between the
    accuracy and the computational cost of the heuristic.

-   **Admissibility: Guaranteeing Optimality for A\***: For certain
    algorithms like **A\* search**, a desirable property of a heuristic
    function is **admissibility**. A heuristic $h(n)$ is admissible if
    it **never overestimates** the actual cost to reach a goal state
    from state $n$. In other words, for all states $n$,
    $h(n) \leq h^*(n)$, where $h^*(n)$ is the true minimal cost from $n$
    to the nearest goal state. Admissibility is a key condition for A\*
    to guarantee finding optimal solutions.

Examples of heuristic functions across different problem domains
include:

-   **Straight-Line Distance for Navigation Problems**: In route-finding
    problems, such as finding a path between cities on a map, the
    **straight-line distance** (Euclidean distance) between the current
    city and the destination city is a commonly used heuristic. This
    heuristic is admissible because the straight line is always the
    shortest possible path, and any actual road path will be at least as
    long.

-   **Manhattan Distance for Grid-Based Puzzles**: In grid-based puzzles
    like the $n \times n$ sliding tile puzzle or pathfinding in grid
    worlds with obstacles, the **Manhattan distance** is frequently
    employed. For a tile (or agent) at position $(x_1, y_1)$ and the
    target position $(x_2, y_2)$, the Manhattan distance is
    $|x_1 - x_2| + |y_1 - y_2|$. This heuristic is admissible in grid
    worlds where movement is restricted to horizontal and vertical
    directions, as it represents the minimum number of moves required if
    diagonal movements are not allowed and there are no obstacles.

-   **Number of Misplaced Tiles for $n$-Puzzle**: For the $n$-puzzle, a
    simple yet effective heuristic is the **number of misplaced tiles**.
    This counts the number of tiles that are not in their goal
    positions. It is admissible because each misplaced tile will require
    at least one move to be placed correctly.

-   **Pattern Databases for Complex Puzzles**: For more complex puzzles,
    **pattern databases** can be used to create highly informative
    heuristics. A pattern database is a precomputed lookup table that
    stores the optimal solution costs for certain subproblems (patterns)
    of the original puzzle. For example, in a 15-puzzle, a pattern
    database might store the optimal number of moves required to solve
    configurations of a subset of tiles (e.g., tiles 1-8). Heuristics
    derived from pattern databases are typically admissible and can
    significantly prune the search space.

## The Greedy Best-First Search Algorithm: Prioritizing Heuristic Estimates (Preview)

::: algorithm
**Description:** Greedy Best-First Search expands nodes based solely on
the heuristic estimate $h(n)$, prioritizing nodes that appear closest to
the goal. It is simple and can be efficient but is neither optimal nor
complete in general.
:::

**Greedy Best-First Search** is a quintessential example of an informed
search algorithm that operates by exclusively using the heuristic
function $h(n)$ to guide its search. It embodies a \"greedy\" approach
by always choosing to expand the node that is estimated to be **closest
to the goal**, as per the heuristic function $h(n)$.

-   **Evaluation Function: Solely Heuristic-Driven**: In Greedy
    Best-First Search, the evaluation function $f(n)$ is defined as
    being equal to the heuristic function: $f(n) = h(n)$. This means
    that the algorithm's decision about which node to expand next is
    based entirely on the heuristic estimate of the remaining cost to
    the goal, disregarding the path cost $g(n)$ incurred to reach the
    current state.

-   **Strategy: Expand the Seemingly Closest Node**: The core strategy
    of Greedy Best-First Search is to **expand the node from the
    frontier that has the lowest $h(n)$ value**. In each step, it
    selects the node that the heuristic function estimates to be nearest
    to a goal state and explores its successors. This process is
    repeated, always prioritizing the node that appears to be \"best\"
    according to the heuristic at each step.

-   **Greedy Nature and Limitations**: The algorithm is termed
    \"greedy\" because it makes locally optimal choices at each step,
    based on the immediate heuristic evaluation, without considering the
    broader context of the search path or the accumulated cost from the
    start. While this greedy approach can often lead to solutions
    quickly, especially when the heuristic is well-informed, it comes
    with significant limitations:

    -   **Suboptimality**: Greedy Best-First Search is generally **not
        optimal**. By focusing solely on the heuristic estimate and
        ignoring the path cost, it may find a goal state via a
        suboptimal path, even if a lower-cost path exists. The locally
        optimal choices do not guarantee a globally optimal solution.

    -   **Incompleteness**: In certain state spaces, Greedy Best-First
        Search can also be **incomplete**. It can get stuck in **local
        optima** or follow paths that lead away from the goal,
        potentially failing to find a solution even if one exists. If
        the heuristic misleads the search into exploring an unbounded
        path, it might never backtrack to explore other promising
        regions of the state space.

::: remark
**Remark 3**. **Greedy Best-First Search Trade-offs:** While fast and
efficient in some cases, Greedy Best-First Search is neither optimal nor
complete in general, due to its exclusive reliance on heuristics.
:::

Despite its limitations in terms of optimality and completeness, Greedy
Best-First Search is valuable for its simplicity and potential
efficiency in quickly finding solutions, especially in scenarios where
approximate solutions are acceptable, or as a component within more
complex search strategies. It serves as an important stepping stone
towards understanding more sophisticated informed search algorithms,
such as A\* search, which address the limitations of greedy search by
combining heuristic estimates with path costs to achieve both efficiency
and optimality. In the subsequent lectures, we will delve deeper into
these advanced informed search techniques.
